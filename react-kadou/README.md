# react-kadou

要員の**週別プロジェクト稼働（割当）管理**を行うための画面 UI プロジェクトです。
構成・技術スタックは既存の `react-ud` を参照しています。

## 技術スタック

- React 18 + TypeScript (Create React App / react-scripts 5)
- UI: Ant Design (antd 5) + @ant-design/icons
- 日付: dayjs
- ログイン: FastAPI のログイン API に接続
- 要員情報: FastAPI の年度別 API に接続
- その他の業務データ: フロント内のモックデータ（業務データ API は未接続）

## セットアップ & 起動

```bash
npm install     # 依存パッケージのインストール
npm start       # 開発サーバー起動 (http://localhost:3000)
npm run build   # 本番ビルド（検証用。build/ に出力）
```

ビルド成果物を確認する場合は、依存なしの簡易静的サーバーを使います。

```bash
npm run build
node scripts/serve-build.cjs   # http://localhost:3001
```

型チェック / Lint:

```bash
npx tsc --noEmit -p tsconfig.json
npx eslint "src/**/*.{ts,tsx}"
```

## ログイン（FastAPI）

ログイン時に `POST /api/login/login` へ `{ "userId": "...", "password": "..." }` を送信します。
FastAPI は `JN_USER_TABLE` で照合するため、先に `api_kadou` を起動して DB 接続を設定してください。

フロントの API 接続先は既定で `http://127.0.0.1:8000` です。変更する場合はプロジェクトルートに `.env.local` を作成します。

```text
REACT_APP_API_BASE_URL=http://127.0.0.1:8000
```

`yakushokuKubun` と画面ロールの対応コードが未定義のため、ログインユーザーは最低の画面ロール（部長相当）で画面に入り、職級欄には API の値を表示します。管理者権限の割り当ては未接続です。これは画面表示上の扱いで、バックエンドの認可機能はまだありません。

- セッションはメモリのみ（リロードで再ログイン）です。

### 起動

1. `api_kadou` の README に従って DB 設定と FastAPI を起動します（`http://127.0.0.1:8000`）。
2. `react-kadou` で `npm start` を実行します（`http://localhost:3000`）。

## 画面

`App.tsx` が全画面を常時マウントし、メニュー選択で表示/非表示を切り替えます（画面内の入力・絞り込み状態は保持されます）。

### 年度選択 `src/YearSelect/YearSelectScreen.tsx`

- すべてのデータ（部門・要員・項目・休日・済南統計・稼動グリッド）は**年度に紐づきます**。ここで年度を切り替えると全画面がその年度のデータに切り替わります。
- 年度ごとに 部門 / 要員 / 項目 / 休日 / 週数 の件数を表示（編集中の内容も反映）。
- データ未準備の年度は選択できますが、中身は空（空白）で表示されます。

### 要員稼動管理 `src/WorkStatus/WorkStatus.tsx`

- **要員 × 週 のグリッド**：行 = 要員、列 = 1週間（月曜〜日曜）。表示範囲は**当年 1/1 を含む週 〜 12/31 を含む週（53 週）**。
- ヘッダーは「月」→「週（開始日〜終了日）」の2段構成。左固定列 = 番号 / 備考 / 役割 / 社員番号 / 名前 / 所属、右固定 = 操作（異動 / 削除）。
- **年途中の部門異動**：行の右端「異動」から「新しい所属」と「適用開始週」を指定すると、旧所属の行と新所属の行の2行に分割されます（旧行は異動週の前週まで、新行は異動週から）。期間外の週セルは空欄・編集不可です。異動先の行を削除すると元の1行に戻ります。
- **セルはプロジェクト（略称）の選択**。未割当は「－」、契約外・非計費は **BUFFER**。「内・退職」を選ぶとその週以降が一括設定されます。
- セルの右クリックメニュー（BUFFER にする/解除・コピー・未割当に）、`複数選択` ON での範囲一括入力。
- **列ヘッダーのフィルタ（漏斗）**：所属列と各週列。Excel のオートフィルタと同じく列内 OR / 列間 AND で絞り込み、候補は他列の条件に連動して絞られます（自分の列の条件は除外）。
- **表示期間 From/To** で週の範囲を絞り込み。`全表示` で期間＋すべての列フィルタを解除できます。
- ツールバー右 = 行追加 / 複数選択 / 保存（モック）。未保存のまま年度切替・ログアウトをすると確認ダイアログが出ます。
- モック初期データ：開始済みの週（月曜 <= 今日）に要員ごとの主担当プロジェクトを自動セット（未来週は空欄 = 計画入力）。

### 要員情報 `src/Personnel/PersonnelInfoScreen.tsx`

- 年度別の要員一覧取得・追加／更新・削除・一括読み込みは FastAPI の `/api/personnel` API を使用します。
- 社員番号を入力すると 役割・名前・所属 を表示し、全項目を編集できます。未登録の社員番号は確認のうえで新規追加。
- 「一括読み込む」で **Excel(.xlsx/.xlsm) / CSV / TSV** を取り込みます（`src/Personnel/personnelImport.ts`・外部ライブラリなし）。社員番号で突合し、既存は上書き・新規は追加。
- 検証用フィクスチャは `node scripts/gen-test-fixtures.cjs` で生成できます（OS の一時フォルダに出力）。

### 部門管理 `src/Department/DepartmentManagementScreen.tsx`

- **部門／協力会社**を登録・修正・削除します（部門ID は内部キーのため画面には表示しません）。種別は一覧のタグで判別できます。
- **協力会社は部門と平級の単位**です。要員の「所属」やプロジェクトの「所属部門」としては選択できますが、**済南稼働率統計（稼働率）の集計対象には含めません**。

### プロジェクト管理 `src/Project/ProjectManagementScreen.tsx`

- 一覧（15件/ページ）＋ 新規 / 修正 / 削除。必須は 顧客 / 案件 / 所属部門です。
- 略称は「顧客1文字目・案件・チーム・Subチーム」から自動生成（空要素は連結しない／`src/Project/projectAbbr.ts`）。
- 項目ID は任意・空欄可（重複可）。主キーはシステム項目IDです。

### 済南稼働率統計 `src/Statistics/JinanWorkRateScreen.tsx`

- 週単位・部門別（第一開発部 / 第二開発部 / 第三開発部 / 済南全社）の 9 指標：総人数 / 離職人数 / 総稼動人数 / 総稼動率 / 非契約稼動人数 / 教育実施人数 / 現地稼動人数（日本出張含）/ 現地稼動率 / 契約稼動率。
- 数値は**保存済みの要員稼動管理（稼働表）から算出**します（行の所属・有効期間・割当・BUFFER）。年途中の部門異動は 2 行に分かれるため、その週に有効な行だけを数えます。
- 上部カード = **今週の集計**（当週＝今日を含む週の実績値。テーブルの今週ハイライト列と一致）。目標稼働率は `JINAN_TARGET_RATE = 50`。
- テーブルは要員稼動管理と同じ横向き（行 = 9 指標 × 4 部門、列 = 月グループ＋週の2段ヘッダー、今週の列をハイライト）。
- 教育実施人数は判定材料が無いため暫定でモック値を使用（保留中の指標）。

### 休日設置 `src/Holiday/HolidaySettingsScreen.tsx`

- 休日の 追加 / 編集 / 削除 と **CSV 出力**（BOM 付き UTF-8 / CRLF）。
- 区分 = 祝日 / 会社休日 / 振替休日。休日は年度ごとのデータです。

### ユーザー管理 `src/User/UserManagementScreen.tsx`

- 管理者のみ。ログインユーザーの 追加 / 変更 / 削除、職級（部長 / 事業部長 / 管理者）と所属部門の設定。
- ログイン中の自分自身の削除、および管理者が 1 名だけの状態での降格・削除はできません。
- この画面の内容は年度に依存しません。

## データの持ち方

- `src/data/kadouRepository.ts` … 保存層。`KadouRepository` interface と**メモリ実装**（`MemoryKadouRepository`）を持ち、バックエンドができたら HTTP 実装に差し替える想定です。
- `src/data/yearStore.ts` … 年度ごとのストア（`YearStore` = 部門 / 要員 / 項目 / 休日 / 済南統計 / 稼動グリッド）。静的モック（`YEAR_DATA`）から初期値を作ります。
- 保存は年度単位の全量更新です（要員稼動管理 = 要員＋割当＋BUFFER、マスタ = 各配列）。

## 現在の制限（モック段階）

- データはすべてブラウザのメモリ上のみで、**リロードすると初期状態に戻ります**。永続化（localStorage / API）は未実装です。
- 認証・権限はフロント内の簡易実装です（パスワードも平文でバンドルに含まれます）。セッションはメモリのみ。
- 同時編集・排他制御はありません。複数のブラウザ／タブで同じユーザーが操作した場合、それぞれが独立したデータを保持します。バックエンド接続時は、全量上書きによる後勝ちで変更が消えないよう、楽観ロック（バージョン / 更新日時）や項目単位の更新が必要です。

## 今後の拡張イメージ

- バックエンド（api-ud 相当）との API 接続（`/api/kadou/**`）と認証 API への置き換え
- 1週間に複数プロジェクトを割当可能にする（タグ入力）
- 月間・四半期の集計、PDF / Excel 出力

```
│  ├─ serve-build.cjs        # ビルド成果物の簡易静的サーバー（port 3001）

   ├─ App.tsx / App.css       # 全画面のマウント・年度／ユーザー状態・保存処理
   ├─ index.tsx / index.css
   ├─ components/             # UnsavedChangesModal（未保存確認）
   ├─ data/                   # モックデータ・保存層

   │  ├─ kadouRepository.ts   # 保存層 interface + メモリ実装
   │  ├─ mockData.ts / mockJinanStats.ts / mockUsers.ts / yearWeeks.ts
   ├─ Login/                  # ログイン画面
   ├─ Menu/                   # 共通メニュー（ヘッダー）
   ├─ YearSelect/             # 年度選択 画面
   ├─ WorkStatus/             # 要員稼動管理 画面（types.ts = 共通型）
   ├─ Personnel/              # 要員情報 画面 + 取込パーサ
   ├─ Department/             # 部門管理 画面
   ├─ Project/                # プロジェクト管理 画面 + 略称生成
   ├─ Statistics/             # 済南稼働率統計 画面
   ├─ Holiday/                # 休日設置 画面
   └─ User/                   # ユーザー管理 画面
```
