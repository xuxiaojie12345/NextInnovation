4. 处理流程
   【AuthenticationApi】
   # Login画面
    4.1 客户端通过POST请求访问接口 /api/ud01/AuthenticationApi，将用户名、密码等请求参数，以JSON格式发送至后端服务。

    4.2 后端【Ud01Controller】接收前端请求，通过【Ud01Request】实体对象封装并校验请求参数，完成请求入口层的参数接收与初步格式验证。

    4.3 控制器层调用【Ud01Service】接口中的 login() 方法，将校验后的请求对象传递至业务逻辑层处理。

    4.4 【Ud01ServiceImpl】业务实现层执行核心登录逻辑：
        • 对请求参数进行非空、长度、格式等合法性校验
        • 对密码格式、账号状态进行前置校验
        • 校验不通过则直接返回参数异常响应

    4.5 业务层通过【UserMapper】数据访问层，根据用户名查询数据库中的用户信息，获取用户实体对象。

    4.6 登录核心验证逻辑：
        • 判断用户或者密码是否存在，若有任何一个不存在则返回“We didn't recognize the username or password you entered. Please try again.”

    4.7 验证全部通过后：
        • 可记录登录日志（登录时间、IP、设备信息）
        • 构建登录成功响应体，包含用户基础信息

    4.8 封装【LoginResponse】响应对象，统一返回标准格式：
       Response Success (200)
       {
        "code": 200,
        "message": null,
        "data": {
         "userId":"AD001"
        }
       }
