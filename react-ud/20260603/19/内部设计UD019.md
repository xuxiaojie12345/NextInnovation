## 1. 背景 (Background)

本模块用于查询用户信息及其市场权限，支持多种查询方式（Userid、用户名、未配置、规则、模板），提供用户市场权限的全面检索功能。

- **核心功能和目标**：
  - 查询用户信息及其市场权限。
  - 支持多种查询方式（Userid、用户名、未配置、规则、模板）。
  - 提供用户市场权限的全面检索功能。
- **面向的用户群体**：系统管理员、权限管理人员、用户信息查询人员。
- **用户体验方面的考虑**：
  - 提供灵活的查询条件。
  - 支持多种筛选方式。
  - 显示完整的用户市场权限信息。
- **安全性或特殊要求**：
  - 确保用户信息查询的安全性。
  - 防止未授权的用户信息访问。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有用户查询逻辑均在用户点击 Search 按钮时执行。

### 3.1 处理流程

#### 3.1.1 Userid 查询功能

- **功能说明**：输入 Userid 后点击【Search】，从 Saviynt 获取用户名，再从用户市场权限表带出用户绑定的市场信息。
- **开始**：点击 Search 按钮。
- **前置处理**：获取用户输入的查询条件。
- **操作步骤**：
  1. 输入 Userid。
  2. 点击 Search 按钮。
  3. 系统从 Saviynt 获取用户名。
  4. 从用户市场权限表获取用户绑定的市场信息。
  5. 显示查询结果。
- **API调用 (Backend Check)**：
  - 调用 `UD19SearchResultListApi`。
- **结果处理**：
  - 成功：显示查询结果。
  - 失败：显示错误消息。

#### 3.1.2 用户名查询功能

- **功能说明**：输入用户名后点击【Search】，先从 Saviynt 反查用户ID，再依据用户ID从用户市场权限表获取所属市场。
- **开始**：点击 Search 按钮。
- **前置处理**：获取用户输入的查询条件。
- **操作步骤**：
  1. 输入用户名。
  2. 点击 Search 按钮。
  3. 系统从 Saviynt 反查用户ID。
  4. 依据用户ID从用户市场权限表获取所属市场。
  5. 显示查询结果。
- **API调用 (Backend Check)**：
  - 调用 `UD19SearchResultListApi`。
- **结果处理**：
  - 成功：显示查询结果。
  - 失败：显示错误消息。

#### 3.1.3 未配置筛选功能

## 4. 接口定义 (API Specification)

### 4.1 UD19SelectMarketMaster

- **功能**：根据传入的参数 Userid 或者 User 名称，获取用户名称或反查用户ID，再获取用户 market 权限。
- **Method**: `GET`
- **Endpoint**: `/api/ud19searchresultlistapi/ud19selectmarketmaster`

#### Request

```json
{
  "userid": "string",
  "user": "string"
}
```

#### Response Success (200)

```json
{
  "code": 200,
  "msg": "查询成功",
  "data": {
    "users": [
      {
        "userid": "string",
        "username": "string",
        "markets": ["string"]
      }
    ],
    "count": 0
  }
}
```

#### Response Error (400)

```json
{
  "code": 400,
  "msg": "查询失败",
  "data": null
}
```

### 4.2 UD19SearchHdoc

- **功能**：根据传入的参数 Userid 或者 User 名称，获取用户名称或反查用户ID，再获取用户 market 权限。
- **Method**: `GET`
- **Endpoint**: `/api/ud19searchresultlistapi/ud19searchhdoc`

#### Request

```json
{
  "userid": "string",
  "user": "string",
  "searchType": "NOT_SET"
}
```

#### Response Success (200)

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "count": 2,
    "users": [
      {
        "userid": "SWE",
        "user": "Kurt Bjork",
        "market": "-EU,1AD,1CZ"
      },
      {
        "userid": "e2090ru",
        "user": "Ivanova Anna",
        "market": "-EU,1RU"
      }
    ]
  }
}
```

#### Response Error (400)

```json
{
  "code": 400,
  "msg": "查询失败",
  "data": null
}
```

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理 `userid`, `user`, `market`, `notSet`, `rule`, `template`, `searchResults`, `count`, `isLoading`。
   - 实现查询条件互斥逻辑，确保只能选择一种查询方式。
   - 管理查询结果数据表格的显示状态。
   - 实现表单验证状态管理，确保 userid 长度不超过10位，user 长度不超过32位。
   - 在 Search 操作后更新查询结果和计数显示。
2. **安全性**：
   - 对输入字段进行适当的格式验证，userid 和 user 只允许半角英数字。
   - 所有 API 请求必须通过 HTTPS 发送。
   - 不在前端日志中打印敏感数据。
   - 实现用户信息访问的安全验证机制，确保只有授权用户才能执行查询操作。
3. **UI 细节**：
   - Search 按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
   - userid 和 user 输入框应限制最大长度并验证格式。
   - Radiobox 选项应正确实现互斥选择逻辑。
   - DataTable 应正确显示查询结果，包括 userid、user、market 等信息。
   - COUNT 字段应正确显示检索结果的记录数。
   - 当多个查询条件同时选择时，应显示错误消息"请只选择一种查询方式"。
   - 错误消息（Message）Label 仅在出错时显示，建议使用红色文字。
