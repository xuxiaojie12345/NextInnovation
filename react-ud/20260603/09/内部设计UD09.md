## 1. 背景 (Background)

本模块的核心功能是展示基于上一页查询条件所获取的“Homologation Variables”数据列表。该页面作为认证参数管理流程中的中间环节，支持用户对检索结果进行选择、打印、批量删除等操作，并提供跳转至用户详情页的功能，辅助用户完成数据确认与后续处理。

- **目标**：清晰展示检索结果，提供高效的批量操作能力（选择、删除），并确保操作的安全性（权限控制、二次确认）。
- **安全性**：
  - 删除操作需经过前端二次确认及后端权限校验。
  - “Created by user” 链接跳转需验证当前用户登录状态。
  - 打印功能不包含敏感系统内部ID。
- **用户体验**：
  - 支持多行勾选，提升批量操作效率。
  - 表格字段清晰，支持排序（Product Class, Market, Number）。
  - 底部显示记录总数，操作按钮语义明确。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有操作逻辑均在用户点击相应按钮时执行。

### 3.1 处理流程

#### 3.1.1 初期表示

1.  **开始**：画面初期表示。
2.  **前置处理**：
    - 页面加载时，从 URL 或 State 获取查询条件，调用 API 获取数据列表。
    - 操作前，验证当前会话有效性。

#### 3.1.2 Select按钮点击处理

1.  **开始**：点击 **Select**。
2.  **空值/状态校验 (Frontend Check)**：
    - 若点击 **Select**：
      - 检查是否有至少一行被勾选。
      - 若无选中项，设置 `ErrorMessage` = `请至少选择一条记录`，**终止**流程。
3.  **结果处理**：
    - **Select**: 将选中数据通过 State 或 Callback 回传至父页面/上一级页面，并执行返回操作。
    - **Back**: 直接执行路由返回，不保存当前页状态。
    - **Print**: 调用浏览器 `window.print()`，并通过 CSS `@media print` 隐藏按钮和非必要元素

#### 3.1.3 Delete selected按钮点击处理

1.  **开始**：点击 **Delete selected**。
2.  **空值/状态校验 (Frontend Check)**：
    - 若点击**Delete selected**：
      - 检查是否有至少一行被勾选。
      - 若无选中项，设置 `ErrorMessage` = `请至少选择一条记录`，**终止**流程。
3.  **结果处理**：
    - **Delete**:
      - 弹出确认框：“确定要删除选中的 X 条记录吗？”
      - 用户确认后，发送请求。
      - 成功：刷新列表，提示“删除成功，共删除 X 条记录”。
      - 失败：提示错误消息。

#### 3.1.4 Back按钮点击处理

1.  **开始**：点击 **Back**。

2.  **结果处理**：
    - **Back**: 直接执行路由返回，不保存当前页状态。

#### 3.1.5 Print按钮点击处理

1.  **开始**：点击 **Print**。

2.  **结果处理**：
    - **Print**: 调用浏览器 `window.print()`，并通过 CSS `@media print` 隐藏按钮和非必要元素

## 4. 接口定义 (API Specification)

### 4.1 获取检索结果列表

- **功能**：根据条件查询认证参数列表。
- **Method**: `POST`
- **Endpoint**: `/api/ud08homologationvariablesapi/ud08searchlist`

#### Request Parameters (Query or Body)

```json
{
  "productClass": "E2",
  "number": 1,
  "market": "-EU",
  "variable": "ENG_TORQUE"
}
```

#### Response Success (200 OK)

```json
{
  "data": [
    {
      "productClass": "E2",
      "number": 1,
      "market": "-EU",
      "variable": "ENG_TORQUE",
      "value": "1000",
      "variantString": "E2-OMEGA",
      "comments": "Engine Torque",
      "addDate": "202504",
      "deleteDate": null,
      "createdByUser": "a304598",
      "date": "2025-04-05"
    }
  ],
  "totalCount": 98
}
```

### 4.2 UD08Delete

- **功能**：删除指定的多条记录。
- **Method**: `DELETE`
- **Endpoint**: `/api/ud08homologationvariablesapi/ud08delete`

#### Request Body

```json
[
  {
    "productClass": "E2",
    "number": 1,
    "market": "-EU"
  },
  {
    "productClass": "E2",
    "number": 2,
    "market": "-EU"
  }
]
```

_(注：使用组合主键进行删除)_

#### Response Success (200 OK)

```json
{
  "success": true,
  "message": "删除成功",
  "deletedCount": 2
}
```

#### Response Error (404 Not Found)

```json
{
  "error": "Not Found",
  "message": "Data does not exist, Please enter the correct content"
}
```

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `dataSource` (列表数据), `selectedRowKeys` (选中项的主键集合), `loading`, `errorMessage`。
    - 使用 `useLocation` 或 `useSearchParams` 获取上一页传来的查询条件。
2.  **UI 细节**：
    - **表格选择**：使用 Ant Design Table 的 `rowSelection` 属性实现多选。
    - **打印样式**：编写专门的 CSS `@media print` 规则，隐藏 `.no-print` 类（包含按钮、导航栏等），确保打印输出整洁。
    - **用户链接**：`Created by user` 列渲染为 `<Link to={`/user/detail/${record.createdByUser}`}>{record.createdByUser}</Link>`。
    - **计数显示**：`Count` Label 动态更新为 `Number of lines found: ${dataSource.length}`。
3.  **交互反馈**：
    - 删除操作必须使用 `Modal.confirm` 或类似组件进行二次确认。
    - 操作成功后，使用 `message.success` 提示用户，并重新加载列表数据。
4.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 删除接口的 Payload 应在后端再次校验当前用户是否有权限删除这些特定记录。
