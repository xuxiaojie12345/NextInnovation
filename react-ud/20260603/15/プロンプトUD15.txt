2. 背景 (Background)
  本模块的核心功能是提供对车辆铭牌（VIN Plate）数据的查询与状态管理。用户可通过输入底盘编号（Chassis number）来查看对应车辆的铭牌详情，并执行重新生成、确认完成、切换版本等操作，支持生产流程中的状态控制。

  面向的用户群体：
  - 生产工程师
  - 质量控制人员
  - 认证管理人员

  用户体验方面的考虑：
  - 界面简洁，突出核心操作按钮
  - 支持快速输入与状态变更
  - 所有操作均有明确反馈提示
  - 操作逻辑清晰，避免误操作

  安全性或特殊要求：
  - 所有状态变更需确认
  - 数据更新由后端统一控制，防止并发冲突
  - 所有通信使用 HTTPS 加密

4. 功能描述 (Functional Description)

    4.1 查看信息功能
    功能说明：输入底盘编号并点击“View Info”按钮，展示该底盘的车辆铭牌详情。
    操作步骤：
      1. 用户在“Chassis number”字段中输入底盘编号（如 JPCT 013945）
      2. 点击“View Info”按钮
      3. 系统校验输入合法性
      4. 若通过，则调用接口查询 HDOC_SEND_DATA_VIN_PLATE 表（UD15SelecthdocsenddatavinplateApi/UD15ViewInfo）
      5. 成功后转移 VIN　Plate詳細画面
      6. 若未找到记录，则显示错误消息：“Chassis number XXX not found.”

    4.2 重新生成功能
    功能说明：将指定底盘的状态更新为0（新增），触发重新生成流程。
    操作步骤：
            1. 用户输入底盘编号
      2. 点击“Set Regenerate”按钮
      3. 系统调用接口更新数据库(UD15SelecthdocsenddatavinplateApi/UD15SetRegenerate)
      4. 将 STATUS 字段设为 0
      5. 成功后提示：“状态已更新为新增”

    4.3 确认完成功能
    功能说明：将指定底盘的状态更新为1（XML文档已生成），表示已完成处理。
    操作步骤：
      1. 用户输入底盘编号
      2. 点击“Set OK”按钮
      3. 系统调用接口更新数据库(UD15SelecthdocsenddatavinplateApi/UD15SetOK)
      4. 将 STATUS 字段设为 1
      5. 成功后提示：“状态已更新为XML已生成”

    4.4 切换为基础信息功能
    功能说明：将指定底盘的状态更新为0（新增），类型更新为1（基础版）。
    操作步骤：
      1. 用户输入底盘编号
      2. 点击“Change to Basic Info”按钮
      3. 系统调用接口更新数据库(UD15SelecthdocsenddatavinplateApi/UD15ChangetoBasicInfo)
      4. 将 STATUS 设为 0，TYPE 设为 1
      5. 成功后提示：“已切换为基础信息模式”

    4.5 切换为高级信息功能
    功能说明：将指定底盘的状态更新为0（新增），类型更新为2（高级版，含重量数据）。
    操作步骤：
      1. 用户输入底盘编号
      2. 点击“Change to Advanced Info”按钮
      3. 系统调用接口更新数据库(UD15SelecthdocsenddatavinplateApi/UD15ChangetoAdvancedInfo)
      4. 将 STATUS 设为 0，TYPE 设为 2
      5. 成功后提示：“已切换为高级信息模式”

5. 业务逻辑与校验规则 (Business Logic & Checks)

   5.1 处理流程

      开始：用户点击 View Info / Set Regenerate / Set OK / Change to Basic Info / Change to Advanced Info 按钮
      前置处理：获取 chassisNumber 参数

      5.1.1 空值校验等 (Frontend Check)：
       若 chassisNumber 为空且点击任何按钮：
        设置Message = “Please enter a chassis number.”
        终止流程

   5.2 结果处理：
       成功：显示提示消息“操作成功”
       失败：显示错误消息“操作失败，请稍后重试”

   5.3 校验详细规格表

   | No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 (Message Content) | 动作 |
   |-----|---------|---------|---------|--------------------------|------|
   | 1   | 点击任意按钮 | Chassis number | 为空 | “Please enter a chassis number.” | 阻止提交 |
   | 2   | 查询时 | Chassis number | 不存在 | “Chassis number XXX not found.” | 显示警告 |
   | 3   | 更新时 | 用户权限 | 不足 | “您没有权限执行此操作” | 禁用按钮 |

6. 接口定义 (API Specification)

   UD15SelecthdocsenddatavinplateApi
     功能：获取指定底盘的车辆铭牌信息
     Method：GET
     Endpoint：/api/UD15SelecthdocsenddatavinplateApi/UD15ViewInfo

     Request [json]
     {
        "chassisNumber": "JPCT 013945"
           }

     Response Success (200)
     {
       "chassisNumber": "JPCT 013945",
       "plateType": 1,
       "status": 0,
       "registerDateTime": "2022-01-10 18:29",
       "docReady": true,
       "sentToCABFactory": false,
       "printItems": ["AXLE_CONF", "WB_MM"],
       "vpData": {
         "variantName": "E2-OMEGA",
         "value": "1234"
       }
     }

     Response Error (404)
     {
       "error": "Not Found",
       "message": "Chassis number XXX not found."
     }

7. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message显示内容 |
|---------|---------|----------------|
| 网络超时 | 重试一次，若仍失败则提示 | “网络连接失败，请检查网络设置” |
| 底盘编号不存在 | 返回错误响应 | “Chassis number XXX not found.” |
| 数据库异常 | 回滚事务，记录日志 | “系统繁忙，请稍后再试” |
