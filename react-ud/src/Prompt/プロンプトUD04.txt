2. 背景 (Background)
 请描述：
  本模块的核心功能和目标：本模块用于展示特定底盘号（Chassis No）对应的 VIN Plate 文档生成结果。它在页面加载时触发后台批处理程序生成 .trf 文件，并展示相关的车辆信息、S-Note 警告、轮胎主数据以及文档下载链接。
  面向的用户群体：内部业务操作人员、技术支持人员。
  用户体验方面的考虑：
    清晰展示关键车辆标识信息（Chassis, Order No, Build Week等）。
    通过颜色（红色）和明确的消息提示用户注意需要修改文档的情况（AD-Change激活）。
    提供直接下载生成文件和跳转至调试/修改页面的快捷入口。

4. 业务逻辑与校验规则 (Business Logic & Checks)
请提供：
   4.1 处理流程
    按步骤描述每个主要功能的处理流程，格式如下：

      4.1.1 页面初始化与数据加载 (Initial Load)
       开始：页面加载（OnLoad），接收到 Chassis series和Chassis No。
       操作步骤：
         1. 接收前画面传入的 Chassis series 和 Chassis no。
         2. 调用 API UD04SelectGeneratedocumentApi 获取详细数据。
         3. 页面渲染各项 Label 和 Link。
       结果处理：
         成功：页面完整显示所有车辆信息、S-Note、轮胎数据、模板信息及下载链接。
         失败：在 Error message area 显示具体的英文错误消息

      4.1.2 跳转至修改文档页面 (Navigate to Modify Document)
       功能说明：用户点击 Modify Doc Link 链接，跳转至修改文档页面。
       操作步骤：
         1. 系统检查 HDOC_ADCA_CHANGE 表中 ACT 字段是否为'Y'。
         2. 若是，Modify Doc Link 显示为红色文字："After def change detected. Document need to be modified."。
         3. 用户点击该链接。
       结果处理：
         成功：携带参数 Chassis no、 Market，迁移到 "Modify Document"（修改文档）画面。
         失败：在 Error message area 显示具体的英文错误消息

      4.1.3 跳转至Chassis详细情报页面 (Navigate to MVDA - Vehicle Specification)
       功能说明：用户点击 Chassis no 链接，跳转至Chassis详细情报页面。
       操作步骤：
         1. 用户点击Chassis no 链接。
       结果处理：
         成功：：携带参数 Chassis no，迁移到 "MVDA - Vehicle Specification"（Chassis详细情报）画面。
         失败：在 Error message area 显示具体的英文错误消息
