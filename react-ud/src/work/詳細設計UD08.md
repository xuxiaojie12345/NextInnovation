## 1. 背景 (Background)

本模块管理车辆认证相关的用户定义参数规则。用户可以通过此画面查询、添加、更新、删除 RULES 情报。

- **面向的用户群体**：系统管理员、数据维护人员。
- **用户体验方面的考虑**：
  1. 提供直观的增删改查（CRUD）操作界面。
  2. 清晰的按钮布局，区分搜索、清空、新增、更新、删除等操作。
  3. 对关键操作（新增、更新、删除）提供即时的错误反馈，确保数据准确性。
  4. 在新增时对 Variable 字段进行特殊处理（去除前缀并校验）。
- **安全性或特殊要求**：对输入数据进行严格校验，防止注入等安全风险。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

#### 3.1.0 画面初始化 (Initial Load)

- **功能说明**：页面加载时，获取并填充下拉框选项。
- **操作步骤**：
  1. **从 Menu 画面迁移的场合**：用户从 Menu 画面点击 "Update user defined variables (rules)" 链接，跳转到本画面。
  2. **从查询结果页返回的场合**：用户从认证参数查询结果页点击【back】按钮，返回到本画面。此时，系统需保存查询结果页返回的 "Product class", "Number", "Market" 的值，并将其他返回值回填到对应字段。
  3. 系统调用 `UD08SelectProductclassmaster` API，获取 `PRODUCT_CLASS_MASTER` 表中所有 PC 值，填充到 "Product class" 下拉框。
  4. 系统调用 `UD08SelectMarketmaster` API，获取 `MARKET_MASTER` 表中所有 MARKET 值，填充到 "Market" 下拉框。
  5. 下拉框加载完成，其他输入框和按钮处于待命状态。若为从结果页返回，则查询条件字段已预填充。
- **结果处理**：
  - 成功：页面正确显示下拉框选项，等待用户操作。
  - 失败：在页面显眼位置显示错误消息。

#### 3.1.1 新增操作 (Add Operation)

- **功能说明**：向数据库中添加一条新的用户定义规则记录。
- **开始**：用户点击 "Add" 按钮。
- **前置处理**：获取画面所有字段的当前值。
- **空值校验 (Frontend Check)**：
  - 若 "Product class", "Number", "Market" 任一为空：
    - 设置 Message = `"Product class, Number, and Market are required for Add operation."`
    - **终止**流程。
- **存在性检查 (Backend Check)**：
  - 调用 `UD08SelectUserDefinedRules` API，传入 "Product class", "Number", "Market"。
  - 若 API 返回记录存在：
    - 设置 Message = `"Primary key conflict, Please enter the correct content"`
    - **终止**流程。
- **格式校验 (Frontend Check)**：
  - 若 "Variable" 字段以 "TEMPLATE-" 开头，则去除前缀。
- **API调用 (Backend Check)**：
  - 调用 `UD08SelectUserDefinedRules` API，传入 "Product class", "Number", "Market"，检查记录是否存在。
  - 调用 `UD08SelectHdocvariables` API，传入处理后的 "Variable" 值，校验其在 `HDOC_VARIABLES` 表中是否存在。
  - 调用 `UD08Add` API，传入所有字段值，执行新增。
- **结果处理**：
  - 成功：显示 "新增成功" 提示，刷新列表。
  - 失败：显示对应错误消息（"Primary key conflict..." 或 "Variant does not exist..."）。

#### 3.1.2 更新操作 (Update Operation)

- **功能说明**：更新数据库中已有的用户定义规则记录。
- **开始**：用户点击 "Update" 按钮。
- **前置处理**：获取画面所有字段的当前值。
- **空值校验 (Frontend Check)**：
  - 若 "Product class", "Number", "Market" 任一为空：
    - 设置 Message = `"Product class, Number, and Market are required for Update operation."`
    - **终止**流程。
- **存在性检查 (Backend Check)**：
  - 从查询结果页返回的场合：
    - 若 "Product class", "Number", "Market" 的值和本地存储的值不一致：
      - 设置 Message = `"Primary key conflict, Please enter the correct content"`
      - **终止**流程。
    - 否则：
      - 调用 `UD08SelectUserDefinedRules` API，传入 "Product class", "Number", "Market"。
      - 若 API 返回记录不存在：
        - 设置 Message = `"Data does not exist, Please enter the correct content"`
        - **终止**流程。
- **格式校验 (Frontend Check)**：
  - 若 "Variable" 字段以 "TEMPLATE-" 开头，则去除前缀。
- **API调用 (Backend Check)**：
  - 调用 `UD08SelectUserDefinedRules` API，传入 "Product class", "Number", "Market"，检查记录是否存在。
  - 调用 `UD08SelectHdocvariables` API，传入处理后的 "Variable" 值，校验其在 `HDOC_VARIABLES` 表中是否存在。
  - 调用 `UD08Update` API，传入所有字段值，执行更新。
- **结果处理**：
  - 成功：显示 "更新成功" 提示。
  - 失败：显示对应错误消息（"Data does not exist..." 或 "Primary key conflict..." 或 "Variant does not exist..."）。

#### 3.1.3 删除操作 (Delete Operation)

- **功能说明**：从数据库中删除一条用户定义规则记录。
- **开始**：用户点击 "Delete" 按钮。
- **前置处理**：获取 "Product class", "Number", "Market" 字段的当前值。
- **空值校验 (Frontend Check)**：
  - 若 "Product class", "Number", "Market" 任一为空：
    - 设置 Message = `"Product class, Number, and Market are required for Delete operation."`
    - **终止**流程。
- **存在性检查 (Backend Check)**：
  - 调用 `UD08SelectUserDefinedRules` API，传入 "Product class", "Number", "Market"。
  - 若 API 返回记录不存在：
    - 设置 Message = `"Data does not exist, Please enter the correct content"`
    - **终止**流程。
- **API调用 (Backend Check)**：
  - 调用 `UD08SelectUserDefinedRules` API，传入 "Product class", "Number", "Market"，检查记录是否存在。
  - 调用 `UD08Delete` API，传入 "Product class", "Number", "Market" 值，执行删除。
- **结果处理**：
  - 成功：显示 "删除成功" 提示。
  - 失败：显示对应错误消息（"Data does not exist..."）。

#### 3.1.4 查询操作 (Search Operation)

- **功能说明**：根据输入的查询条件执行数据检索，并跳转至查询结果页面。
- **操作步骤**：
  1. 用户在画面任意字段输入查询条件。
  2. 用户点击 "Search" 按钮。
  3. 系统将输入的查询条件作为参数，携带至认证参数查询结果页。
  4. 系统执行业务逻辑校验（检查主键重复，校验 Variable 是否存在）。
  5. 页面跳转至认证参数查询结果页，并显示符合查询条件的数据。
- **结果处理**：
  - 成功：跳转到查询结果页并显示数据。
  - 失败：在画面显眼位置显示错误消息。

#### 3.1.5 清空操作 (Clear Operation)

- **功能说明**：清空所有输入字段的内容。
- **操作步骤**：
  1. 用户点击 "Clear" 按钮。
  2. 系统将所有输入字段（TextField, Pull-downList）的值清空。
  3. 所有输入字段变为空。
- **结果处理**：
  - 成功：画面所有字段清空。
  - 失败：无（纯前端操作，不涉及 API 调用）。

### 4.1 UD08SelectProductclassmaster

- **功能**：获取产品类别主数据列表。
- **Method**: `GET`
- **Endpoint**: `/api/ud08/select-productclassmaster`

#### Request

无参数

#### Response Success (200)

```json
{
  "code": 200,
  "message": "Success",
  "data": [{ "pc": "PC01" }, { "pc": "PC02" }]
}
```

#### Response Error (400/500)

```json
{
  "code": 500,
  "message": "System Error",
  "data": null
}
```

#### Request

```json
{
  "pc": "string",
  "number": "string",
  "market": "string"
}
```

#### Response Success (200)

```json
{
  "code": 200,
  "message": "Deleted successfully"
}
```

#### Response Error (400/500)

```json
{
  "code": 400,
  "message": "Data does not exist, Please enter the correct content",
  "data": null
}
```

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理所有表单字段的状态，包括 pc, number, market, variable, val, vs, vs2, comments, addDate, deleteDate, updateUser, updateDatetime 等。
   - 管理下拉框选项状态，分别存储 Product class 和 Market 的选项数据。
   - 在组件挂载时调用 `UD08SelectProductclassmaster` 和 `UD08SelectMarketmaster` API 获取下拉框数据。
   - 实现本地存储（如 sessionStorage）逻辑，用于在从查询结果页返回时保存和恢复主键值（Product class, Number, Market）。
   - 从查询结果页返回时，需将返回的 "Product class", "Number", "Market" 值与本地存储的值进行一致性校验后进行 Update 操作。
2. **安全性**：
   - 对所有输入字段进行严格的正则校验，确保只接受允许的字符类型。
   - Variable 字段的 TEMPLATE- 前缀处理逻辑需要在提交前执行。
   - 所有 API 请求必须通过 HTTPS 发送。
   - 不在前端日志中打印敏感数据。
3. **UI 细节**：
   - Clear 按钮点击后应清空所有输入字段（包括下拉框和文本框）。
   - Add、Update、Delete 按钮在提交过程中应设为 disabled 状态，防止重复提交。
   - 错误消息应以醒目方式显示，建议使用红色文字。
   - 成功消息应以适当方式提示用户操作结果。
   - 确保页面布局合理，按钮位置清晰易于操作。
