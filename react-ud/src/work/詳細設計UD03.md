## 1. 背景 (Background)

本模块是生成认证文件的入口画面。用户在此输入底盘系列号（Chassis series）、底盘号（Chassis no）并选择文档类型（Document type），系统会根据输入的底盘信息自动加载可用的文档类型列表，并在提交后跳转至文档生成画面。

- **目标**：为需要生成车辆认证文件（Homologation Documents）的工程人员或管理人员提供入口，实现文档生成的初始化。
- **面向用户**：需要生成车辆认证文件（Homologation Documents）的工程人员或管理人员。
- **用户体验**：
  - 自动回填：页面加载时自动显示上次使用的检索条件，减少重复输入。
  - 动态加载：点击或加载时根据底盘信息动态获取文档类型，确保选项的有效性。
  - 清晰反馈：若底盘号不存在或数据异常，立即在错误区域提示。
- **安全性**：输入字段需严格限制字符类型（半角英文、半角数字），防止注入或格式错误。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

#### 3.1.1 页面初始化与数据获取 (Initialization & Data Fetching)

**功能说明**：页面加载时，恢复上次的检索条件，并调用 API 获取文档类型列表。

1.  **开始**：页面加载完成 (OnLoad)。
2.  **前置处理**：
    - 从本地存储（Local Storage/Session）读取上次的 Chassis series, Chassis no, Document type 并填充到对应控件。
    - 立即调用 API `UD03SelectHdocdocumentlistApi`（无参数）。
3.  **API调用 (Backend Check)**：
    - 请求：GET `/api/UD03/select-hdoc-document-list`
4.  **结果反馈**：
    - **成功且数据非空**：解析 API 返回的文档类型列表，更新 Document type 下拉框选项。若上次选择的值在列表中，则保持选中；否则清空或选中第一项。清空 error message area。
    - **成功但数据为空 (0件)**：在 error message area 显示错误消息 `"Chassis no is not exists"`。下拉框置空或禁用。
    - **失败 (Network/Error)**：在 error message area 显示系统错误消息。

#### 3.1.2 提交校验与跳转 (Submit Validation & Navigation)

**功能说明**：校验用户输入，并将参数传递至下一画面。

1.  **开始**：用户点击 Submit 按钮。
2.  **前置处理**：获取所有表单字段的当前值。
3.  **空值校验 (Frontend Check)**：
    - 若 `Chassis series` 为空：设置Message = `"Chassis series is required."`，终止流程。
    - 若 `Chassis no` 为空：设置Message = `"Chassis no is required."`，终止流程。
    - 若 `Document type` 未选择（值为空）：设置Message = `"Document type is required."`，终止流程。
4.  **结果处理**：
    - **校验通过**：保存当前输入到本地存储（作为下次"上次设定值"）。携带参数 `{ chassisSeries, chassisNo, documentType }` 跳转到「Generate document」画面。
    - **校验失败**：画面不跳转，在 `error message area` 显示错误消息。

#### 3.1.3 重置 (Reset)

**功能说明**：清空当前表单内容及错误提示，恢复到未输入的初始状态，清除本地存储的历史记录。

1.  **开始**：用户点击 [Reset] 按钮。
2.  **处理过程**：
    - 清空 Chassis series, Chassis no, Document type。
    - 清除 error message area。
    - 清除本地存储的上次检索条件。

#### 3.1.4 帮助 (Help)

**功能说明**：跳转到帮助页面。

1.  **开始**：用户点击 [Help] 按钮。
2.  **处理过程**：系统迁移到 Help 画面。

## 4. 接口定义 (API Specification)

### 4.1 UD03SelectHdocdocumentlistApi

- **功能**：获取可用的文档类型列表。
- **Method**: `GET`
- **Endpoint**: `/api/UD03/selecthdocdocumentlist`

#### Request

Params: **None**

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "Success",
  "data": [
    {
      "doctype": "CERTIFICATE"
    },
    {
      "doctype": "VIN_PLATE"
    }
  ]
}
```

#### Response Error (400/500)

```json
{
  "code": 500,
  "message": "System Error",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景                         | 处理方式                         | Message 显示内容                             |
| :------------------------------- | :------------------------------- | :------------------------------------------- |
| **网络超时/连接失败 (初始化时)** | 捕获异常，显示通用网络错误       | `Network error. Please try again.`           |
| **服务器内部错误 (500)**         | 捕获异常，记录日志，显示友好提示 | `System error. Please contact support.`      |
| **API 返回数据为空**             | 业务逻辑判断                     | `Chassis no is not exists`                   |
| **输入格式错误 (前端拦截)**      | 正则校验失败                     | `Invalid format. Only alphanumeric allowed.` |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `chassisSeries`, `chassisNo`, `documentType`, `message`, `isLoading`。
    - `error message area` Label 默认隐藏（内容为空时不占位或高度为0）。
    - 本地存储管理上次检索条件，使用 localStorage 或 sessionStorage 存储和恢复表单数据。
2.  **安全性**：
    - 对输入字段进行严格的正则校验，确保只接受允许的字符类型。
    - API 请求必须通过 HTTPS 发送。
3.  **UI 细节**：
    - Submit 按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
    - `error message area` 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
    - Document type 下拉框在无数据时应显示禁用状态或提示信息。
    - Reset 按钮点击后应清空所有表单内容和本地存储的记录。
