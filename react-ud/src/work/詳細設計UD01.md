## 1. 背景 (Background)

本模块是系统的入口，负责验证用户身份。用户通过输入 UserID 和 Password，经由前端校验后调用后端 `AuthenticationApi` 进行认证。

- **目标**：提供用户身份验证入口，点击登录按钮进行用户认证。
- **安全性**：密码输入需掩码显示，传输需加密，敏感信息不落地。
- **用户体验**：采用 Label 形式在页面内显示错误信息，避免频繁弹窗打断操作流。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

1.  **开始**：用户点击 [Login] 按钮。
2.  **前置处理**：获取 UserID 和 Password 输入值，Trim 处理。
3.  **空值校验等 (Frontend Check)**：
    - 若 UserID 为空 OR Password 为空：
      - 设置 Message = `Username and password are required.`
    - 若 UserID OR Password 不正确：
      - 设置 Message = `We didn't recognize the username or password you entered. Please try again.`
      - **终止**流程。
4.  **API 调用 (Backend Check)**：
    - 若校验通过，调用 `AuthenticationApi(userID, password)`。
5.  **结果处理**：
    - **认证成功**：清空 Message，保存用户信息到 sessionStorage，迁移到 Menu 一览画面。
    - **认证失败**：设置 Message = `We didn't recognize the username or password you entered. Please try again.`

### 3.2 校验详细规格表

| No. |   检查时机   |  检查对象   |                检查条件                |                          错误消息 (Message Content)                           |                 动作                 |
| :-: | :----------: | :---------: | :------------------------------------: | :---------------------------------------------------------------------------: | :----------------------------------: |
|  1  | Click Login  |   UserID    | `Value == null` OR `Trim(Value) == ""` |                     `Username and password are required.`                     | 显示 Message，焦点停留在第一个空字段 |
|  2  | Click Login  |  Password   | `Value == null` OR `Trim(Value) == ""` |                     `Username and password are required.`                     | 显示 Message，焦点停留在第一个空字段 |
|  3  | API Response | Auth Result |  `Status != Success` OR `Code == 401`  | `We didn't recognize the username or password you entered. Please try again.` | 显示 Message，建议清空 Password 字段 |

## 4. 接口定义 (API Specification)

### 4.1 AuthenticationApi

- **功能**：用户情报认证。
- **Method**: `GET`
- **Endpoint**: `/api/authentication/login`

#### Request [application/json]

```json
{
  "userID": "string",
  "password": "string"
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "Success",
  "data": {
    "token": "eyJhbGci...",
    "userId": 1,
    "username": "xxx"
  }
}
```

#### Response Error (401 Unauthorized)

```json
{
  "code": 401,
  "data": null,
  "message": "Invalid credentials"
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景                 | 处理方式               | Message 显示内容                               |
| :----------------------- | :--------------------- | :--------------------------------------------- |
| **网络超时/连接失败**    | 捕获异常，重置按钮状态 | `Network error. Please check your connection.` |
| **服务器内部错误 (500)** | 捕获异常，记录日志     | `System error. Please try again later.`        |
| **输入包含非法字符**     | 前端拦截或后端返回     | `Invalid character format.`                    |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `userID`, `password`, `message`, `isLoading`。
    - `Message` Label 默认隐藏（内容为空时不占位或高度为0）。
2.  **安全性**：
    - 严禁在前端日志中打印明文密码。
    - API 请求必须通过 HTTPS 发送。
3.  **UI 细节**：
    - [Login]按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
    - `Message` 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
