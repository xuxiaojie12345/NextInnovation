## 1. 背景 (Background)

本模块用于展示特定底盘号（Chassis No）对应的 VIN Plate 文档生成结果。它在页面加载时触发后台批处理程序生成 .trf 文件，并展示相关的车辆信息、S-Note 警告、轮胎主数据以及文档下载链接。

- **面向的用户群体**：内部业务操作人员、技术支持人员。
- **用户体验方面的考虑**：
  - 清晰展示关键车辆标识信息（Chassis, Order No, Build Week等）。
  - 通过颜色（红色）和明确的消息提示用户注意需要修改文档的情况（AD-Change激活）。
  - 提供直接下载生成文件和跳转至调试/修改页面的快捷入口。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

#### 3.1.1 页面初始化与数据加载 (Initial Load)

- **开始**：页面加载（OnLoad），接收到 Chassis series和Chassis No。
- **操作步骤**：
  1. 接收前画面传入的 Chassis series 和 Chassis no。
  2. 调用 API UD04SelectGeneratedocumentApi 获取详细数据。
  3. 页面渲染各项 Label 和 Link。
- **结果处理**：
  - 成功：页面完整显示所有车辆信息、S-Note、轮胎数据、模板信息及下载链接。
  - 失败：在 Error message area 显示具体的英文错误消息

#### 3.1.2 跳转至修改文档页面 (Navigate to Modify Document)

- **功能说明**：用户点击 Modify Doc Link 链接，跳转至修改文档页面。
- **操作步骤**：
  1. 系统检查 HDOC_ADCA_CHANGE 表中 ACT 字段是否为'Y'。
  2. 若是，Modify Doc Link 显示为红色文字："After def change detected. Document need to be modified."。
  3. 用户点击该链接。
- **结果处理**：
  - 成功：携带参数 Chassis no、 Market，迁移到 "Modify Document"（修改文档）画面。
  - 失败：在 Error message area 显示具体的英文错误消息

#### 3.1.3 跳转至Chassis详细情报页面 (Navigate to MVDA - Vehicle Specification)

- **功能说明**：用户点击 Chassis no 链接，跳转至Chassis详细情报页面。
- **操作步骤**：
  1. 用户点击Chassis no 链接。
- **结果处理**：
  - 成功：：携带参数 Chassis no，迁移到 "MVDA - Vehicle Specification"（Chassis详细情报）画面。
  - 失败：在 Error message area 显示具体的英文错误消息

## 4. 接口定义 (API Specification)

### 4.1 UD04SelectGeneratedocumentApi

- **功能**：获取生成文档所需的所有展示数据，包括订单信息、VDA信息、轮胎信息、AD-Change状态及修改参数。
- **Method**：GET
- **Endpoint**：/api/ud04/generatedocument

#### Request [json]

```json
{
  "chassisSeries": "String",
  "chassisNo": "String"
}
```

#### Response Success (200)

```json
{
  "code": 200,
  "message": "Success",
  "data": {
    "orderNumber": "String",
    "buildWeek": "String",
    "specWeek": "String",
    "market": "String",
    "sNoteNo": "String",
    "loadIndex": "String",
    "adChangeActive": boolean,
    "replacementParams": [
      {
        "variable": "String",
        "newVal": "String"
      }
    ],
    "Date": "String"
  }
}
```

#### Response Error (500/400)

```json
{
  "code": 500,
  "message": "Batch processing failed: Failed to make the Inplate",
  "errorReason": "XXX"
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景       | 处理方式                       | Message显示内容                                    |
| -------------- | ------------------------------ | -------------------------------------------------- |
| API执行异常    | 捕获异常，记录日志，返回错误码 | API call failed: [Exception Message]               |
| 数据库连接失败 | 连接池异常捕获                 | Database connection error, please try again later. |
| 查询结果为空   | 数据查询结果验证               | No data found for chassis: [chassis number]        |
| 网络/API超时   | 前端超时处理                   | System timeout, please try again later.            |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `documentData`, `errorMessage`, `isLoading`。
    - `Error message area` Label 默认隐藏（内容为空时不占位或高度为0）。
    - `isLoading` 期间显示 "Loading document data..." 消息。
2.  **UI 细节**：
    - **标题样式**：18px 粗体深蓝色 (#000080)，左对齐。
    - **信息行布局**：flex 横向布局，标签最小宽度 140px，行间距 6px。
    - **S-Note NO**：独立一行显示，不在 label/value 结构中。
    - **警告信息**：S-Note Message 和 AD-Change 警告使用红色 (#ff0000)。
    - **缩进显示**：Replacing parameters 需缩进 140px (margin-left: 140px)。
    - **底部信息**：Date/Version 区域上边距 40px (margin-top: 40px)。
    - **Chassis no**：以 "ChassisSeries - ChassisNo" 格式显示，该链接可点击跳转至 MVDA - Vehicle Specification 画面。
    - **Modify Doc Link**：在 AD-Change 状态激活时应显示为红色文字以起到警示作用，点击后携带 Chassis no、Market 参数跳转至 "Modify Document" 画面。
    - **可点击元素**：添加 `role="button"` 和 `tabIndex={0}`，支持键盘事件（Enter 和 Space 键）。
3.  **安全性**：
    - 必须对用户输入内容做校验，防范 XSS 攻击。
    - API 请求必须通过 HTTPS 发送。
    - 错误消息中不泄露底层技术细节。
