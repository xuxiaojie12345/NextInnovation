## 1. 背景 (Background)

本模块提供HDoc模板文件的上传和删除功能，支持用户选择市场并上传或删除相应的模板文件，并提供模板检查功能。

- **面向的用户群体**：系统管理员、开发人员、运维人员等需要管理HDoc模板文件的用户。
- **用户体验方面的考虑**：
  1. 提供直观的界面布局，区分上传和删除功能区域。
  2. 支持模板文件的选择和上传操作。
  3. 提供删除确认机制，防止误删除。
  4. 提供模板检查功能，便于用户验证模板质量。
- **安全性或特殊要求**：
  - 确保文件上传的安全性，防止恶意文件上传。
  - 实现删除前的确认机制。
  - 确保模板文件存储位置的安全性。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

#### 3.1.1 市场列表加载处理流程 (Market List Load)

- **功能说明**：页面初始化时，加载市场下拉列表。
- **开始**：页面初始化完成。
- **前置处理**：准备获取市场列表。
- **API调用 (Backend Check)**：
  - 调用 `UD08HomologationVariablesApi` 的 `UD08SelectMarketmaster` 方法。
- **结果处理**：
  - 成功：将市场列表填充到 Market 下拉列表。
  - 失败：显示具体错误消息。

#### 3.1.2 上传操作处理流程 (Upload)

- **功能说明**：选择模板文件后点击[Upload]按钮，文件将上传至指定文件夹。
- **开始**：点击[Upload file]按钮。
- **前置处理**：获取用户选择的模板文件和市场信息。
- **空值校验 (Frontend Check)**：
  - 若 [Template File 为空]：
    - 设置 Message = `"NO FILE UPLOADED"`
    - **终止**流程。
  - 若 [Market 未选择]：
    - 设置 Message = `"请选择目标市场"`
    - **终止**流程。
- **操作步骤**：
  1. 用户在[Market]下拉列表中选择目标市场。
  2. 用户在[Template File]中选择要上传的文件。
  3. 点击[Upload file]按钮。
  4. 系统验证文件并上传到相应市场文件夹。
- **API调用 (Backend Check)**：
  - 调用 `UD12UploadDeletetemplatApi` 的 `UD12UploadFlie` 方法。
- **结果处理**：
  - 成功：显示 `"TEMPLATE [文件名] WAS SUCCESSFULLY UPLOADED TO MARKET [市场代码]"` 消息。
  - 失败：显示具体错误消息。

#### 3.1.3 删除操作处理流程 (Delete)

- **功能说明**：选择市场与模板后点击[Delete]按钮，即可从指定文件夹中移除该模板文件。
- **开始**：点击[Delete]按钮。
- **前置处理**：获取用户选择的市场和模板文件信息。
- **操作步骤**：
  1. 用户在[Market]下拉列表中选择目标市场。
  2. 系统根据选择的市场加载可用模板文件列表。
  3. 用户在[Templates]下拉列表中选择要删除的模板。
  4. 点击[Delete]按钮。
  5. 系统显示删除确认警告。
  6. 用户确认后，系统删除选定的模板文件。
- **API调用 (Backend Check)**：
  - 调用 `UD12UploadDeletetemplatApi` 的 `UD12DeleteFlie` 方法。
- **结果处理**：
  - 成功：显示 `"TEMPLATE [文件名] WAS SUCCESSFULLY DELETED FROM MARKET [市场代码]"` 消息。
  - 失败：显示具体错误消息。

#### 3.1.4 模板检查操作处理流程 (Check Template)

- **功能说明**：点击链接[Check Template] (Only for rtf files)，跳转至「HDoc Template Check」画面。
- **开始**：点击[Check Template]链接。
- **操作步骤**：
  1. 用户点击[Check Template]链接。
  2. 系统验证当前是否有 RTF 文件选中。
  3. 跳转至 HDoc Template Check 画面。
  4. 在新画面中进行模板检查。
- **结果处理**：
  - 成功：跳转至 HDoc Template Check 画面。
  - 失败：显示错误消息。

## 4. 接口定义 (API Specification)

### 4.1 UD08SelectMarketmaster

- **功能**：获取市场主数据信息。
- **Method**: `POST`
- **Endpoint**: `/api/UD12UploadDeletetemplatApi/selectmarketmaster`

#### Request

无参数

#### Response Success (200)

```json
{
  "code": 200,
  "msg": "查询成功",
  "data": {
    "markets": [{ "market": "JPN" }, { "market": "USA" }]
  }
}
```

#### Response Error (400)

```json
{
  "code": 400,
  "msg": "获取市场列表失败",
  "data": null
}
```

### 4.2 UD12UploadFlie

- **功能**：将文件上传到服务器。
- **Method**: `POST`
- **Endpoint**: `/api/ud12uploaddeletetemplat/uploadfile`

#### Request [multipart/form-data]

| 参数   | 类型        | 说明     |
| :----- | :---------- | :------- |
| file   | file object | 模板文件 |
| market | string      | 目标市场 |

#### Response Success (200)

```json
{
  "code": 200,
  "msg": "TEMPLATE [文件名] WAS SUCCESSFULLY UPLOADED TO MARKET [市场代码]",
  "data": null
}
```

#### Response Error (400)

```json
{
  "code": 400,
  "msg": "上传失败：[具体错误信息]",
  "data": null
}
```

### 4.3 UD12DeleteFlie

- **功能**：将文件从服务器中删除。
- **Method**: `POST`
- **Endpoint**: `/api/ud12uploaddeletetemplat/deletefile`

#### Request

```json
{
  "market": "string",
  "template": "string"
}
```

#### Response Success (200)

```json
{
  "code": 200,
  "msg": "TEMPLATE [文件名] WAS SUCCESSFULLY DELETED FROM MARKET [市场代码]",
  "data": null
}
```

#### Response Error (400)

```json
{
  "code": 400,
  "msg": "删除失败：[具体错误信息]",
  "data": null
}
```

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理上传区域的 Template File 和 Market 状态。
   - 使用 React State 管理删除区域的 Market 和 Templates 下拉框状态。
   - 页面初始化时调用 `UD08SelectMarketmaster` API 获取市场列表，填充到两个区域的 Market 下拉框。
   - 删除区域选择 Market 后，动态加载该市场文件夹下的模板文件列表，填充到 Templates 下拉框。
2. **安全性**：
   - 文件上传前需验证文件类型和大小，防止恶意文件上传。
   - 文件路径需进行安全检查，防止路径遍历攻击。
   - 所有 API 请求必须通过 HTTPS 发送。
   - 不在前端日志中打印敏感数据。
3. **UI 细节**：
   - 上传区域和删除区域应清晰区分，避免用户混淆。
   - Upload 按钮点击前需校验文件和市场是否已选择。
   - Delete 按钮点击前应弹出确认对话框，提示 "Do you really want to delete template?"。
   - 上传/删除操作完成后应显示明确的成功或失败消息。
   - Check Template 链接仅对 RTF 文件有效，非 RTF 文件应禁用或提示。
   - 文件上传过程中应将按钮设为 disabled 状态，防止重复提交。

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 file、market、templates 等表单字段状态。
    - 管理 Market 下拉框选项，从 MARKET_MASTER 表获取数据。
    - 管理 Templates 下拉框选项，根据选择的市场动态加载模板文件列表。
    - 实现文件上传进度和状态管理。
    - 在组件挂载时调用 UD08SelectMarketmaster API 获取市场列表。
2.  **安全性**：
    - 对上传的文件类型进行严格验证，只允许特定类型的模板文件。
    - 对上传的文件大小进行限制，防止过大的文件上传。
    - 在删除操作前显示确认对话框，防止误删除。
    - 所有 API 请求必须通过 HTTPS 发送。
    - 不在前端日志中打印敏感数据。
3.  **UI 细节**：
    - Upload file 和 Delete 按钮在提交过程中应设为 disabled 状态，防止重复提交。
    - 文件上传时应显示进度指示器。
    - Templates 下拉框应根据选择的 Market 动态更新选项。
    - Check Template 链接应只对 RTF 文件有效。
    - 错误消息应以醒目方式显示，建议使用红色文字。
    - 确保页面布局合理，上传和删除区域清晰分离。
