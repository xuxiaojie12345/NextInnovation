## 1. 背景 (Background)

本模块显示车辆规格信息修改后的具体内容摘要，供用户确认。

- **面向的用户群体**：内部业务操作人员、质量管理人员。
- **用户体验方面的考虑**
  1. 清晰展示修改前后的关键信息（Chassis, Doctype, Version, Storing 等）。
  2. 提供明确的关闭操作，方便用户返回或结束流程。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

#### 3.1.1 画面初始化与数据显示

- **开始**：画面加载时，接收前画面传入的 Chassis No。
- **操作步骤**：
  1. 用户进入 VDA - Vehicle Specification 画面。
  2. 系统接收前画面传入的 Chassis 信息（用于拆分 Serie 和 Number）。
  3. 系统调用 UD06SaveModificationsApi 中的 UD06SelectHdocAdcaModification 方法，获取 Modify 情报。
  4. 界面渲染各项 Label：
     4.1 Chassis serie：显示 Chassis 号中 '-' 之前的部分。
     4.2 Chassis number：显示 Chassis 号中 '-' 之后的部分。
     4.3 Doctype, Version, Storing, FOUND UNRELEASED VERSION：显示 API 返回的对应字段值。
     4.4 Message：若版本已发布，显示 'VERSION IS RELEASED'。
  5. 显示 "Close" 按钮。
- **结果处理**：
  - 成功：正确显示所有标签信息。
  - 失败：若 API 调用失败，显示通用错误消息。

#### 3.1.2 关闭画面

- **功能说明**：用户点击关闭按钮，退出当前确认页面。
- **操作步骤**：
  1. 用户点击 "Close" 按钮。
  2. 系统执行关闭当前窗口或返回上一页面的操作。
- **结果处理**：
  - 成功：画面关闭。

## 4. 接口定义 (API Specification)

### 4.1 UD06SelectHdocAdcaModification

- **功能**：获取 HDOC_ADCA_MODIFICATION 表中的修改情报，用于在确认画面展示。
- **Method**：GET
- **Endpoint**：/api/ud06/selectmodificationdetails

#### Request [json]

```json
{
  "chassisNo": "string"
}
```

#### Response Success (200)

```json
{
  "code": 200,
  "message": "Success",
  "data": {
    "doctype": "string",
    "version": "string",
    "storingInfo": "string",
    "foundUnreleasedVersion": "string"
  }
}
```

#### Response Error (400/500)

```json
{
  "code": 500,
  "message": "Internal Server Error",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景         | 处理方式                     | Message显示内容                                                    |
| ---------------- | ---------------------------- | ------------------------------------------------------------------ |
| 网络请求失败     | 前端捕获网络错误             | System error: Unable to connect to server. Please try again later. |
| 数据加载失败     | 显示后端返回的错误或默认错误 | Failed to load modification details.                               |
| Chassis 格式异常 | 前端解析 '-' 失败时          | Invalid Chassis Number format.                                     |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 chassisSerie, chassisNumber, doctype, version, storingInfo, foundUnreleasedVersion, message, isLoading 等状态。
    - 在组件挂载时调用 UD06SelectHdocAdcaModification API 获取显示数据。
    - 实现 chassisNo 的解析逻辑，将其拆分为 serie 和 number 部分。
2.  **安全性**：
    - 所有 API 请求必须通过 HTTPS 发送。
    - 不在前端日志中打印敏感数据。
    - 对从后端获取的数据进行适当的安全处理，防止 XSS 攻击。
3.  **UI 细节**：
    - Close 按钮点击后应正确关闭当前窗口或返回上一页面。
    - 所有 Label 应正确显示从 API 获取的数据。
    - 错误消息应以醒目方式显示，建议使用红色文字。
    - 确保页面布局合理，信息展示清晰易读。
