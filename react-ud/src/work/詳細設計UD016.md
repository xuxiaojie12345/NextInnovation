## 1. 背景 (Background)

本模块对车型 - 底盘编号（Serie-Chnr）执行新增、删除、校验操作，管理AD Change相关的车型底盘信息。

- **核心功能和目标**：对车型 - 底盘编号（Serie-Chnr）执行新增、删除、校验操作，管理AD Change相关的车型底盘信息。
- **面向的用户群体**：生产线操作员、质量控制人员、系统管理员。
- **用户体验方面的考虑**：
  1. 提供直观的操作界面。
  2. 实时反馈操作结果。
  3. 清晰的错误提示信息。
- **安全性或特殊要求**：
  - 确保数据操作的安全性和一致性。
  - 防止重复添加相同数据。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有操作逻辑均在用户点击相应按钮时执行。

### 3.1 处理流程

#### 3.1.1 新增操作处理流程 (Add)

- **功能说明**：对车型-底盘编号执行新增操作。
- **开始**：点击 Add 按钮。
- **前置处理**：获取用户输入的 Serie-Chnr 和 Desc 信息。
- **空值校验 (Frontend Check)**：
  - 若 `Serie-Chnr` 为空：
    - 设置 `Message` = `"AFTER DEF CHANGE IS NOT ACTIVATED"`
    - **终止**流程。
- **操作步骤**：
  1. 输入 Serie-Chnr 和 Desc 信息。
  2. 点击 ADD 按钮。
  3. 系统调用 `UD16SelectHdocAdcaChange` 方法检查数据是否存在。
  4. 若数据不存在，调用 `UD16InsertHdocAdcaChange` 方法插入数据；若存在，显示错误信息 `"AFTER DEF CHANGE IS NOT ACTIVATED"`。
- **API调用 (Backend Check)**：
  - 调用 `UD16ADChangeApi`。
- **结果处理**：
  - 成功：显示 "新增成功" 消息。
  - 失败：显示错误消息，如 `"AFTER DEF CHANGE IS NOT ACTIVATED"`。

#### 3.1.2 删除操作处理流程 (Delete)

- **功能说明**：对车型-底盘编号执行删除操作。
- **开始**：点击 DELETE 按钮。
- **前置处理**：获取用户输入的 Serie-Chnr 信息。
- **空值校验 (Frontend Check)**：
  - 若 `Serie-Chnr` 为空：
    - 设置 `Message` = `"请输入车型-底盘编号"`
    - **终止**流程。
- **操作步骤**：
  1. 输入 Serie-Chnr 信息。
  2. 点击 DELETE 按钮。
  3. 系统调用 `UD16UpdateHdocAdcaChange` 方法删除数据。
  4. 显示操作结果。
- **API调用 (Backend Check)**：
  - 调用 `UD16ADChangeApi`。
- **结果处理**：
  - 成功：显示 "删除成功" 消息。
  - 失败：显示错误消息。

#### 3.1.3 校验操作处理流程 (Check)

- **功能说明**：对车型-底盘编号执行校验操作，检查数据是否存在。
- **开始**：点击 CHECK 按钮。
- **操作步骤**：
  1. 点击 CHECK 按钮。
  2. 系统调用 `UD16SelectHdocAdcaChange` 方法检查数据是否存在。
- **API调用 (Backend Check)**：
  - 调用 `UD16ADChangeApi`。
- **结果处理**：
  - 成功：显示 "数据已存在/不存在" 消息。
  - 失败：显示错误信息。

### 3.2 校验详细规格表

| No. | 检查时机      | 检查对象     | 检查条件   | 错误消息 (Message Content)          | 动作                         |

## 4. 接口定义 (API Specification)

### 4.1 UD16InsertHdocAdcaChange

- **功能**：点击ADD按钮后，存在check通过的场合，将数据登录进数据库中。
- **Method**: `POST`
- **Endpoint**: `/api/ad-change/insert`

#### Request

```json
{
  "serie": "string",
  "chnr": "string",
  "desc": "string"
}
```

#### Response Success (200)

```json
{
  "code": 200,
  "msg": "新增成功",
  "data": null
}
```

#### Response Error (400)

```json
{
  "code": 400,
  "msg": "AFTER DEF CHANGE IS NOT ACTIVATED",
  "data": null
}
```

### 4.2 UD16UpdateHdocAdcaChange

- **功能**：点击DELETE按钮后，利用参数Serie-Chnr删除数据。
- **Method**: `POST`
- **Endpoint**: `/api/ad-change/delete`

#### Request

```json
{
  "serie": "string",
  "chnr": "string"
}
```

#### Response Success (200)

```json
{
  "code": 200,
  "msg": "删除成功",
  "data": null
}
```

#### Response Error (404)

```json
{
  "code": 404,
  "msg": "删除失败",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景           | 处理方式         | Message 显示内容                    |
| :----------------- | :--------------- | :---------------------------------- |
| **数据已存在**     | 显示错误消息     | `AFTER DEF CHANGE IS NOT ACTIVATED` |
| **数据库连接失败** | 显示系统错误消息 | 系统暂时不可用，请稍后再试          |
| **网络请求超时**   | 显示超时提示     | 请求超时，请检查网络连接            |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理 `serieChnr`、`desc`、`message`、`isLoading` 等表单字段状态。
   - 实现表单验证状态管理，确保 Serie-Chnr 长度不超过15位，Desc 长度不超过4000位。
   - 管理按钮提交状态，防止重复提交。
   - 在 ADD 操作前先检查数据是否存在，避免重复添加。
2. **安全性**：
   - 对输入字段进行适当的长度验证，Serie-Chnr 最大15位，Desc 最大4000位。
   - 所有 API 请求必须通过 HTTPS 发送。
   - 不在前端日志中打印敏感数据。
   - 对于已存在的数据，提供明确的错误提示。
3. **UI 细节**：
   - ADD、DELETE、CHECK 按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
   - Serie-Chnr 和 Desc 输入框应限制最大长度。
   - 错误消息（Message）Label 仅在出错时显示，建议使用红色文字。
   - 操作按钮应有明确的视觉反馈，区分不同的功能。
