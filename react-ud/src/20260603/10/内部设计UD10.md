## 1. 背景 (Background)

本模块的核心功能是提供对 `HDOC_VARIABLES` 表中认证参数（Homologation Variables）的查询、新增、更新、删除及导出操作。用户可通过输入条件进行筛选，并执行 CRUD 操作，支持数据批量管理。

- **目标**：提供便捷的变量维护入口，确保数据完整性（Variable 必填、唯一性校验），并提供 CSV 导出功能以满足报表需求。
- **安全性**：
  - 删除操作需经过前端二次确认及后端权限校验。
  - “Variable” 字段在增改时为必填项。
  - 导出文件不包含敏感信息（如内部 ID）。
  - 权限控制由后端统一管理（如仅允许特定角色执行删除）。
- **用户体验**：
  - 查询条件字段清晰布局，便于快速定位。
  - 支持“Add/Update/Delete”按钮联动控制必填项提示。
  - 所有操作均有明确反馈提示（成功/失败消息）。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 **[Add]**, **[Update]**, **[Delete]**, **[Search]** 或 **[Excel]** 按钮时执行。

### 3.1 处理流程

1.  **开始**：用户点击操作按钮。
2.  **前置处理**：获取表单数据或选中行数据。
3.  **空值/状态校验 (Frontend Check)**：
    - 若点击 **Add** 或 **Update**：
      - 检查 `Variable` 是否为空。
      - 若为空，设置 `ErrorMessage` = `Variable 是必填项`，**终止**流程。
    - 若点击 **Delete**：
      - 检查是否已选中记录（通常通过 Variable 或 ID 判断）。
      - 若未选中，设置 `ErrorMessage` = `请选择要删除的记录`，**终止**流程。
4.  **API 调用 (Backend Check)**：
    - **Search**: 携带查询条件跳转至结果页（或通过 API 获取列表并在当前页展示，依具体路由设计而定，UD10 描述为“跳转至现有文档参数查询结果页”）。
    - **Add**: 调用 `POST /api/HDOC_VARIABLES/add`。
    - **Update**: 调用 `PUT /api/HDOC_VARIABLES/update`。
    - **Delete**: 调用 `DELETE /api/HDOC_VARIABLES/delete`。
    - **Excel**: 调用 `GET /api/HDOC_VARIABLES/export`。
5.  **结果处理**：
    - **成功**：提示“操作成功”，刷新列表或清空表单。
    - **失败**：显示后端返回的错误消息（如主键冲突、记录不存在等）。

## 4. 接口定义 (API Specification)

### 4.1 UD10Add (新增)

- **功能**：新增一条认证参数记录。
- **Method**: `POST`
- **Endpoint**: `/api/HDOC_VARIABLES/add`

#### Request Body

```json
{
  "variable": "ENG_TORQUE",
  "type": "VDA",
  "description": "Engine Torque"
}
```

_(注：Created_by_user 和 Date 由后端自动填充)_

#### Response Success (201 Created)

```json
{
  "success": true,
  "id": "12345",
  "message": "添加成功"
}
```

#### Response Error (409 Conflict)

```json
{
  "error": "Conflict",
  "message": "Variant already exists. Please enter the correct content"
}
```

### 4.2 UD10Update (更新)

- **功能**：更新现有记录。
- **Method**: `PUT`
- **Endpoint**: `/api/HDOC_VARIABLES/update`

#### Request Body

```json
{
  "id": "12345",
  "variable": "ENG_TORQUE",
  "type": "User Defined",
  "description": "Updated Engine Torque"
}
```

#### Response Success (200 OK)

```json
{
  "success": true,
  "message": "更新成功"
}
```

#### Response Error (404 Not Found)

```json
{
  "error": "Not Found",
  "message": "Variant does not exist. Please enter the correct content"
}
```

### 4.3 UD10Delete (删除)

- **功能**：删除指定记录。
- **Method**: `DELETE`
- **Endpoint**: `/api/HDOC_VARIABLES/delete`

#### Request Params / Body

```json
{
  "id": "12345"
}
```

_(或使用 variable 作为主键)_

#### Response Success (200 OK)

```json
{
  "success": true,
  "message": "删除成功"
}
```

#### Response Error (404 Not Found)

```json
{
  "error": "Not Found",
  "message": "Variant does not exist. Please enter the correct content"
}
```

### 4.4 UD10Export (导出)

- **功能**：导出当前查询结果为 CSV 文件。
- **Method**: `GET`
- **Endpoint**: `/api/HDOC_VARIABLES/export`

#### Request Parameters (Query)

```text
?variable=ENG&type=VDA
```

#### Response Success (200 OK)

- Content-Type: `text/csv`
- Content-Disposition: `attachment; filename="HDoc_Variables_YYYYMMDD.csv"`
- Body: [CSV File Stream]

#### Response Error (400 Bad Request)

```json
{
  "error": "Invalid export request",
  "message": "无法生成导出文件"
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景          | 处理方式           | Message 显示内容                                           |
| :---------------- | :----------------- | :--------------------------------------------------------- |
| **网络断开/超时** | 捕获 Network Error | `网络连接失败，请检查网络设置`                             |

| **变量已存在**    | 捕获 API 409       | `Variant already exists. Please enter the correct content` |
| **记录不存在**    | 捕获 API 404       | `Variant does not exist. Please enter the correct content` |
| **导出失败**      | 捕获 API 400/500   | `导出失败，请联系管理员`                                   |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理表单数据 `formData`, `errorMessage`, `isLoading`。
    - 若是列表页内嵌编辑，需管理 `dataSource` 和 `selectedRowKeys`。
2.  **表单校验**：
    - 使用 Ant Design Form 或类似库进行 `Variable` 必填项校验。
    - `Type` 下拉框建议使用 `<Select>` 组件，选项固定。
3.  **UI 细节**：
    - **只读字段**：`Created by user` 和 `Date` 在编辑模式下应显示为禁用状态。
    - **按钮状态**：在执行 API 请求期间，所有操作按钮应设为 `disabled`，防止重复提交。
    - **删除确认**：点击 Delete 按钮时，必须弹出 `Modal.confirm` 进行二次确认。
    - **导出交互**：点击 Excel 按钮后，建议显示 loading 状态，直到文件下载开始或失败。
4.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 对输入内容进行 sanitization，防止 XSS 攻击。
    - 删除和更新操作应在后端再次校验用户权限。
