## 1. 背景 (Background)

本模块的核心功能是提供对车辆铭牌（VIN Plate）数据的查询与状态管理。用户可通过输入底盘编号（Chassis number）来查看对应车辆的铭牌详情，并执行重新生成、确认完成、切换版本等操作，支持生产流程中的状态控制。

- **目标**：实现 VIN Plate 生命周期的关键节点控制（重置、完成、类型切换），并提供快速查询入口。
- **安全性**：
  - 仅允许授权用户访问此页面。
  - 所有状态变更操作需经过后端权限校验。
  - 数据更新由后端统一控制，防止并发冲突。
  - 所有通信使用 HTTPS 加密。
- **用户体验**：
  - 界面简洁，突出核心操作按钮。
  - 支持快速输入与状态变更。
  - 所有操作均有明确的成功/失败反馈提示。
  - 操作逻辑清晰，避免误操作（如空值拦截）。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击任意操作按钮时执行。

### 3.1 处理流程

1.  **开始**：用户点击 [View Info], [Set Regenerate], [Set OK], [Change to Basic], 或 [Change to Advanced] 按钮。
2.  **前置处理**：获取 `Chassis number` 输入值，执行 `trim()`。
3.  **空值校验 (Frontend Check)**：
    - 若 `Chassis number` 为空：
      - 设置 `ErrorMessage` = `Please enter a chassis number.`
      - **终止**流程，不调用 API。
4.  **API 调用 (Backend Check)**：
    - **View Info**: 调用 `GET /api/UD15SelecthdocsenddatavinplateApi/UD15ViewInfo`。
    - **Set Regenerate / Set OK**: 调用 `PUT /api/vinplate/status`。
    - **Change to Basic / Advanced**: 调用 `PUT /api/vinplate/type`。
5.  **结果处理**：
    - **View Info 成功**：跳转至 VIN Plate 详细页面。
    - **View Info 失败 (404)**：显示 `Chassis number XXX not found.`。
    - **Update 成功**：显示成功消息（如“状态已更新为新增”），并可选刷新下方状态标签。
    - **Update 失败**：显示后端返回的错误消息或通用错误“操作失败，请稍后重试”。

## 4. 接口定义 (API Specification)

### 4.1 View Info (查询详情)

- **功能**：获取指定底盘的车辆铭牌信息，用于验证存在性或跳转前预检。
- **Method**: `GET`
- **Endpoint**: `/api/UD15SelecthdocsenddatavinplateApi/UD15ViewInfo`

#### Request Parameters (Query or Body)

```json
{
  "chassisNumber": "JPCT 013945"
}
```

#### Response Success (200 OK)

```json
{
  "chassisNumber": "JPCT 013945",
  "plateType": 1,
  "status": 0,
  "registerDateTime": "2022-01-10 18:29",
  "docReady": true,
  "sentToCABFactory": false,
  "printItems": ["AXLE_CONF", "WB_MM"],
  "vpData": {
    "variantName": "E2-OMEGA",
    "value": "1234"
  }
}
```

#### Response Error (404 Not Found)

```json
{
  "error": "Not Found",
  "message": "Chassis number JPCT 013945 not found."
}
```

### 4.2 Update Status (更新状态)

- **功能**：更新车辆铭牌的处理状态（0=新增, 1=已完成）。
- **Method**: `PUT`
- **Endpoint**: `/api/vinplate/status`

#### Request Body

```json
{
  "chassisNumber": "JPCT 013945",
  "status": 0
}
```

#### Response Success (200 OK)

```json
{
  "success": true,
  "message": "状态已更新为新增"
}
```

#### Response Error (403 Forbidden)

```json
{
  "error": "Forbidden",
  "message": "您没有权限执行此操作"
}
```

### 4.3 Update Type (更新类型)

- **功能**：更新车辆铭牌的类型（1=基础版, 2=高级版），并通常伴随状态重置为 0。
- **Method**: `PUT`
- **Endpoint**: `/api/vinplate/type`

#### Request Body

```json
{
  "chassisNumber": "JPCT 013945",
  "type": 2,
  "status": 0
}
```

#### Response Success (200 OK)

```json
{
  "success": true,
  "message": "已切换为高级信息模式"
}
```

#### Response Error (400 Bad Request)

```json
{
  "error": "Invalid type",
  "message": "类型必须为1或2"
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景                | 处理方式           | Message 显示内容                |
| :---------------------- | :----------------- | :------------------------------ |
| **网络断开/超时**       | 捕获 Network Error | `网络连接失败，请检查网络设置`  |
| **权限不足**            | 捕获 API 403       | `您没有权限执行此操作`          |
| **底盘编号不存在**      | 捕获 API 404       | `Chassis number XXX not found.` |
| **数据库异常/并发冲突** | 捕获 Server Error  | `系统繁忙，请稍后再试`          |
| **参数非法**            | 捕获 API 400       | `请求参数错误`                  |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `chassisInput`, `currentChassisInfo` (用于展示下方 Label), `errorMessage`, `isLoading`。
    - `isLoading` 用于在 API 请求期间禁用所有按钮，防止重复提交。
2.  **交互细节**：
    - **View Info**：成功响应后，使用 `navigate('/vin-plate-detail', { state: { chassisNo } })` 或类似方式跳转。
    - **Update Operations**：成功响应后，建议使用 `message.success()` 提示用户，并可选择性地再次调用 View Info 接口刷新下方的 `Plate Type` 和 `Status` 标签，以保持界面数据一致性。
    - **Error Display**：`ErrorMessage` 应在每次新操作开始时清空。
3.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 后端应校验当前登录用户是否有权限修改该底盘的状态（例如，仅限特定角色）。
    - 对 `chassisNumber` 进行 sanitization，防止 SQL 注入或路径遍历。
4.  **UI 布局**：
    - 输入框与按钮组可放置于页面上方。
    - 状态展示区域（Label）可放置于下方或侧边，初始状态可为空或显示“未查询”。
