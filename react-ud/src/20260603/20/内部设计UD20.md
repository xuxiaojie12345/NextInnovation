## 1. 背景 (Background)

本模块的核心功能是展示从 `HDOC_DOCUMENT_LIST` 表中查询出的市场文档配置数据列表。该页面作为“市场文档设置”流程的输出界面，支持用户对检索结果进行选择、打印和跳转操作。

- **目标**：清晰展示查询结果，支持用户选择特定配置返回上一级页面，或查看相关用户详情，并提供打印功能以备归档。
- **安全性**：
  - 仅允许授权用户访问此页面。
  - 所有通信使用 HTTPS 加密。
  - 不暴露敏感信息（如内部 ID）。
  - 打印功能不包含系统按钮和操作栏，确保输出整洁。
- **用户体验**：
  - 支持多行勾选（虽 Prompt 描述为“勾选一条”，但通常表格支持多选，此处依 Prompt 4.2 “勾选一条数据”及 5.1.1 “未勾选任何数据”推断，可能为单选或多选，设计为支持多选更灵活，但 Select 动作可限制为单选或返回所选集合）。_注：Prompt 4.2 说“勾选一条”，5.1.1 说“未勾选任何...阻止”，建议前端实现为 Radio 或限制 Checkbox 只能选一个，或者 Select 按钮只处理第一个选中项。为通用性，设计为 Checkbox，Select 时若多选则提示或取首个，或依业务定义返回集合。此处按“支持勾选，点击 Select 返回”设计。_
  - 提供清晰的数据字段展示。
  - User 列可点击跳转，增强信息追溯能力。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有操作逻辑均在用户点击相应按钮或链接时执行。

### 3.1 处理流程

1.  **开始**：页面加载或用户点击操作按钮/链接。
2.  **前置处理**：
    - 页面加载时，从 URL 或 State 获取上一页传来的查询条件（如 `doctype`, `businessUnit`）。
    - 调用 API 获取数据列表。
3.  **空值/状态校验 (Frontend Check)**：
    - 若点击 **Select**：
      - 检查是否有至少一行被勾选。
      - 若无选中项，设置 `Message` = `请至少选择一条记录`，**终止**流程。
      - _(可选)_ 若勾选多于一条，根据业务需求决定是报错、只取第一条还是返回集合。Prompt 4.2 暗示“勾选一条”，建议前端限制为单选（Radio）或在 Select 时若多选则提示“请只选择一条记录”。此处假设支持多选但 Select 动作可能只处理主要需求，或依具体后端定义。为稳妥，建议前端限制为**单选**（使用 Radio Button 代替 Checkbox，或 Checkbox 互斥逻辑）。_修正_：Prompt 表格中未明确 Radio/Checkbox，但 4.2 说“勾选一条”，5.1.1 说“未勾选...阻止”。为实现简单且符合“选择并返回”的常见模式，建议使用 **Radio Button** 进行单选，或 Checkbox 但 Select 时校验 `selectedCount === 1`。此处设计为 **Checkbox** 但 Select 时校验**必须且只能选择一条**（依 4.2 描述）。若业务允许多选返回，则移除“只能一条”的限制。鉴于 4.2 明确说“勾选一条”，我们将校验逻辑设为：**必须选中且仅选中一条**。
4.  **API 调用 (Backend Check)**：
    - **Load Data**: 调用 `GET /api/document/settings`。
    - **User Profile**: 点击 User 链接时，前端直接跳转路由，或由新页面调用 `GET /user/profile/{id}`。
5.  **结果处理**：
    - **Select**: 将选中行的数据（如 `documentType`, `businessUnit`）通过 State 或 Callback 回传至父页面/上一级页面，并执行返回操作。
    - **Back**: 直接执行路由返回。
    - **Print**: 调用浏览器 `window.print()`，并通过 CSS `@media print` 隐藏按钮、Checkbox 列等非必要元素。
    - **User Link**: 跳转至 `/user/profile/{userId}`。

## 4. 接口定义 (API Specification)

### 4.1 Get Document Settings (获取列表)

- **功能**：获取市场文档配置列表。
- **Method**: `GET`
- **Endpoint**: `/api/document/settings`

#### Request Parameters (Query)

```text
?doctype=COC_EUB1&businessUnit=VBC
```

#### Response Success (200 OK)

```json
{
  "data": [
    {
      "documentType": "COC_EUB1",
      "businessUnit": "VBC",
      "user": "a304598",
      "date": "2022-01-10"
    }
  ],
  "totalCount": 1
}
```

#### Response Error (400 Bad Request)

```json
{
  "error": "Invalid parameters",
  "message": "查询参数格式错误"
}
```

### 4.2 Get User Profile (获取用户详情)

- **功能**：获取用户详细信息。
- **Method**: `GET`
- **Endpoint**: `/api/user/profile/{id}`

#### Response Success (200 OK)

```json
{
  "userId": "a304598",
  "name": "张三",
  "department": "研发部",
  "role": "Engineer"
}
```

#### Response Error (404 Not Found)

```json
{
  "error": "Not Found",
  "message": "用户不存在"
}
```

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `dataSource` (列表数据), `selectedRowKey` (选中项的唯一标识，因要求单选，可用 String 而非 Array), `loading`, `message`。
    - 使用 `useLocation` 或 `useSearchParams` 获取上一页传来的查询条件。
2.  **UI 细节**：
    - **单选实现**：虽然 Prompt 表格写的是 DataTable，但为了实现“勾选一条”，建议使用 Ant Design Table 的 `rowSelection` 属性，并设置 `type: 'radio'` 以实现严格的单选逻辑。
    - **打印样式**：编写专门的 CSS `@media print` 规则，隐藏 `.no-print` 类（包含按钮、Checkbox 列等），确保打印输出只包含数据表格。
    - **用户链接**：`User` 列渲染为 `<Link to={`/user/profile/${record.user}`}>{record.user}</Link>`。
    - **计数显示**：`Count` Label 动态更新为 `Total: ${dataSource.length}`。
3.  **交互反馈**：
    - 点击 `Select` 时，若未选中或选中多条，给予明确 Toast 或 Message 提示。
    - 操作成功后，使用 `message.success` 提示用户（如需）。
4.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 对 URL 参数进行编码，防止注入攻击。
