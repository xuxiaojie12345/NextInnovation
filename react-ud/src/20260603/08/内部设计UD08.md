## 1. 背景 (Background)

本模块用于管理系统中的认证参数（Homologation Variables），支持对用户定义规则的查询、新增、修改和删除操作。

- **目标**：提供灵活的 CRUD 操作界面，确保数据完整性（主键唯一性、变量有效性），并自动记录审计信息（创建人、时间）。
- **安全性**：
  - `Product class`、`Number`、`Market` 组合为主键，禁止重复。
  - `Variable` 必须存在于 `HDOC_VARIABLES` 表中。
  - 所有写入操作需验证权限（由后端控制）。
  - 自动记录 `Created by user` 和 `Date` 字段，不可手动编辑。
- **用户体验**：
  - 查询条件清晰排列，关键字段带星号标识必填项。
  - 操作按钮集中放置于顶部，便于快速访问。
  - 支持实时校验，减少提交错误。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 **[Add]**, **[Update]**, **[Delete]** 或 **[Search]** 按钮时执行。

### 3.1 处理流程

1.  **初始化处理**: 页面加载时调用 `UD08SelectProductclassmaster`, `UD08SelectMarketmaster`, `UD08SelectHdocvariables` 获取选项。
2.  **开始**：用户点击操作按钮。
3.  **前置处理**：获取表单数据。
4.  **空值校验 (Frontend Check)**：
    - 若点击 **Add** 或 **Update**：
      - 检查 `Product class`, `Number`, `Market` 是否为空。
      - 若任一为空，设置 `ErrorMessage` = `Product class, Number, Market 是必填项`，**终止**流程。
    - 若点击 **Delete**：
      - 检查是否已选中记录（通过主键判断）。
      - 若未选中，设置 `ErrorMessage` = `请选择要删除的记录`，**终止**流程。
5.  **更新校验**：
    - 点击 **Add**：
      - 检查主键是否冲突。
      - 若数据库中已经存在该数据，设置 `ErrorMessage` = `Primary key conflict, Please enter the correct content`，**终止**流程。
    - 若点击 **Add**：
      - 检查变量书否存在于 HDOC_VARIABLES
      - 若不存在，设置 `ErrorMessage` = `Variant does not exist, Please enter the correct content`，**终止**流程。
    - 若点击 **Update/Delete**：
      - 检查数据库中记录是否存在
      - 若不存在，设置 `ErrorMessage` = `Data does not exist, Please enter the correct content`，**终止**流程。
6.  **API 调用 (Backend Check)**：
    - **Search**: 调用 `GET /api/.../ud08selectproductclassmaster` (注：此处可能指代查询列表接口，需根据实际后端定义调整，假设有一个统一的查询接口)。
    - **Add**: 调用 `POST /api/.../ud08add`。
    - **Update**: 调用 `PUT /api/.../ud08update`。
    - **Delete**: 调用 `DELETE /api/.../ud08delete`。
    - **初始化下拉框**: 页面加载时调用 `UD08SelectProductclassmaster`, `UD08SelectMarketmaster`, `UD08SelectHdocvariables` 获取选项。
7.  **结果处理**：
    - **成功**：提示“操作成功”，刷新列表或清空表单。
    - **失败**：显示后端返回的错误消息（如主键冲突、变量不存在等）。

## 4. 接口定义 (API Specification)

### 4.1 获取下拉列表数据

- **功能**：获取 Product Class, Market, Variable 的可选列表。
- **Method**: `GET`
- **Endpoints**:
  - `/api/ud08homologationvariablesapi/ud08selectproductclassmaster`
  - `/api/ud08homologationvariablesapi/ud08selectmarketmaster`
  - `/api/ud08homologationvariablesapi/ud08selecthdocvariables`

#### Response Success (200 OK)

```json
{
  "data": [
    ······
  ]
}
```

### 4.2 UD08Add (新增)

- **功能**：新增一条认证参数记录。
- **Method**: `POST`
- **Endpoint**: `/api/ud08homologationvariablesapi/ud08add`

#### Request Body

```json
{
  "productClass": "E2",
  "number": 1,
  "market": "-EU",
  "variable": "ENG_TORQUE",
  "value": "1000",
  "variantString1": "E2-OMEGA",
  "variantString2": "",
  "comments": "Engine Torque",
  "Add": "当前画面中Add的值",
  "Delete": "当前画面中Delete的值",
  "Created by user": "当前画面中Created by user的值",
  "Date": "当前画面中Date的值"
}
```

_(注：Add, Delete, CreatedBy, Date 由后端自动填充)_

#### Response Success (201 Created)

```json
{
  "success": true,
  "message": "添加成功"
}
```

#### Response Error (409 Conflict)

```json
{
  "error": "Conflict",
  "message": "Primary key conflict, Please enter the correct content"
}
```

### 4.3 UD08Update (更新)

- **功能**：更新现有记录。
- **Method**: `PUT`

## 5. 异常处理 (Exception Handling)

| 异常场景          | 处理方式           | Message 显示内容                                           |
| :---------------- | :----------------- | :--------------------------------------------------------- |
| **网络断开/超时** | 捕获 Network Error | `网络连接失败，请检查网络设置`                             |
| **数据库异常**    | 捕获 Server Error  | `系统繁忙，请稍后再试`                                     |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理表单数据 `formData`, `errorMessage`, `isLoading`, `dropdownOptions`。
    - `dropdownOptions` 在组件挂载时并行请求三个接口获取。
2.  **表单校验**：
    - 使用 Ant Design Form 或类似库进行必填项校验。
    - `Number` 字段应限制只能输入数字。
3.  **UI 细节**：
    - **只读字段**：`Add`, `Delete`, `Created by user`, `Date` 在新增/编辑模式下应显示为禁用状态或纯文本，明确告知用户不可编辑。
    - **按钮状态**：在执行 API 请求期间，所有操作按钮应设为 `disabled`，防止重复提交。
    - **错误提示**：`ErrorMessage` 建议使用红色字体，并在操作成功后自动清除。
4.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 对输入内容进行 sanitization，防止 XSS 攻击。
    - 敏感操作（Add/Update/Delete）应在后端再次校验用户权限。
