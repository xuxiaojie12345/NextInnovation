## 1. 背景 (Background)

本模块用于展示车辆的详细配置信息，基于 VDA（德国汽车工业协会）标准格式。主要功能包括展示底盘编号、型号、生产周、VIN、发动机号等基本信息，以及完整的车辆配置项列表。

- **目标**：提供清晰、标准化的车辆配置视图，支持工程师、操作员及质检人员快速查阅车辆技术细节。
- **安全性**：数据仅读取，不可编辑；所有字段均来自系统数据库，无外部输入风险。
- **用户体验**：
  - 页面布局清晰，关键信息前置。
  - 使用表格形式展示大量配置项，便于快速浏览。
  - 提供 Tooltip 功能，帮助用户理解缩写或专业术语。
  - 支持响应式设计，适配不同屏幕尺寸。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

1.  **开始**：用户访问 `/UD07VehicleSpecification/{chassisNo}` 页面。
2.  **前置处理**：
    - 从 URL 参数中获取 `chassisNo`。
    - 执行非空校验。
3.  **空值校验 (Frontend Check)**：
    - 若 `chassisNo` 为空：
      - 设置 `ErrorMessage` = `无法加载数据，请检查输入`
      - **终止**流程，不调用 API。
4.  **API 调用 (Backend Check)**：
    - 若校验通过，调用 `GET /api/UD07VehicleSpecification/Selest/{chassisNo}`。
5.  **结果处理**：
    - **成功 (200)**：
      - 渲染基本信息（Chassis no, Model, VIN 等）。
      - 解析 `symbols` 数组，生成带 Tooltip 的配置项列表。
      - 若存在 `sNotes`，渲染 S-Note 列表。
    - **失败 (404/500)**：
      - 设置 `ErrorMessage` = `数据加载失败，请稍后重试` 或具体错误消息（如 `Chassis not found`）。

### 3.2 校验详细规格表

| No. |   检查时机   |      检查对象      |                检查条件                |         错误消息 (Message Content)          |            动作             |
| :-: | :----------: | :----------------: | :------------------------------------: | :-----------------------------------------: | :-------------------------: |

## 4. 接口定义 (API Specification)

### 4.1 UD07VehicleSpecificationAPI

- **功能**：获取指定底盘的 VDA 车辆规格详细信息。
- **Method**: `GET`
- **Endpoint**: `/api/UD07VehicleSpecification/Selest/{chassisNo}`

#### Request Parameters

- `chassisNo`: String (Path Param, e.g., "JPCT013945")

#### Response Success (200 OK)

```json
{
  "chassisNo": "JPCT 013945",
  "model": "UD-HDE",
  "builtWeek": "1617",
  "productType": "EM 64 R",
  "vin": "JPCZZ30D8GT013945",
  "engineNo": "428328",
  "countryOfOperation": "IDN",
  "symbols": [
    {
      "symbol": "G3-MY",
      "description": "Engine Type: EM 64 R"
    },
    {
      "symbol": "EM 64 R",
      "description": "Engine Model: EM 64 R"
    },
    {
      "symbol": "T-RYPE-EM",
      "description": "Transmission Type: EM"
    }
  ],
  "sNotes": ["S161011", "S161014"]
}
```

#### Response Error (404 Not Found)

```json
{
  "error": "Not Found",
  "message": "Chassis not found"
}
```

#### Response Error (500 Internal Server Error)

```json
{
  "error": "Internal Server Error",
  "message": "System busy, please try again later"
}
```

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `vehicleData`, `errorMessage`, `isLoading`。
    - `vehicleData` 应包含基本信息对象和 `symbols` 数组。
2.  **UI 细节**：
    - **Tooltip 实现**：遍历 `symbols` 数组，为每个 `symbol` 包裹一个 Tooltip 组件。例如：
      ```jsx
      <Tooltip title={item.description}>
        <span>{item.symbol}</span>
      </Tooltip>
      ```
    - **布局**：基本信息部分使用 Grid 或 Flex 布局，确保标签对齐。配置项列表部分使用 `<pre>` 标签或带有 `white-space: pre-wrap` 的 `<div>` 以保持格式。
    - **S-Notes**：若 `sNotes` 数组非空，在页面底部或侧边栏显示，建议使用列表样式。
3.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 对 URL 参数进行编码，防止注入攻击。
    - 所有数据仅用于展示，严禁在前端进行任何写操作。
4.  **性能优化**：
    - 若 `symbols` 数量巨大（超过几百个），考虑使用虚拟滚动或分页加载，但通常 VDA 规格书长度可控，直接渲染即可。
