## 1. 背景 (Background)

本模块的核心功能是提供对车辆铭牌（VIN Plate）模板文件的上传、删除和校验操作。用户可通过该页面将 `.rtf` 格式的模板文件上传至指定市场目录，或从目录中移除不再使用的模板，并在上传前进行格式校验。

- **目标**：实现模板文件的集中化管理，确保文件格式合规（.rtf），并按市场分类存储。
- **安全性**：
  - 仅允许授权用户访问此页面。
  - 上传文件需严格校验为 `.rtf` 格式，防止恶意文件注入。
  - 删除操作需经过前端二次确认。
  - 所有通信使用 HTTPS 加密。
  - 文件路径由后端统一管理，避免直接暴露服务器文件系统结构。
- **用户体验**：
  - 提供清晰的上传与删除区域划分。
  - 支持市场选择，确保模板按区域分类存储。
  - 提供模板校验链接，引导用户先校验再上传。
  - 所有操作均有明确的成功/失败反馈提示。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 **[Upload file]** 或 **[Delete]** 按钮时执行。

### 3.1 处理流程

1.  **开始**：用户点击操作按钮。
2.  **前置处理**：获取表单数据或选中项。
3.  **空值/格式校验 (Frontend Check)**：
    - **上传操作**：
      - 若未选择文件：设置 `ErrorMessage` = `NO FILE UPLOADED`，**终止**流程。
      - 若文件扩展名不是 `.rtf`：设置 `ErrorMessage` = `仅支持 .rtf 文件`，**终止**流程。
      - 若文件大小超过 10MB：设置 `ErrorMessage` = `文件过大，请压缩后上传`，**终止**流程。
    - **删除操作**：
      - 若 `Market (Delete)` 为空：设置 `ErrorMessage` = `请选择市场`，**终止**流程。
      - 若 `Templates` 为空：设置 `ErrorMessage` = `请选择模板`，**终止**流程。
      - 弹出确认对话框：“Do you really want to delete template?”。若用户取消，**终止**流程。
4.  **API 调用 (Backend Check)**：
    - **Upload**: 调用 `POST /api/template/upload`。
    - **Delete**: 调用 `DELETE /api/template/delete`。
    - **Check Link**: 点击链接直接跳转至 `/template-check`，无需 API 调用。
5.  **结果处理**：
    - **成功**：
      - 上传：提示 `TEMPLATE XXX WAS SUCCESSFULLY UPLOADED TO MARKET JPN`，清空文件输入框。
      - 删除：提示 `TEMPLATE XXX WAS SUCCESSFULLY DELETE FROM MARKET JPN`，刷新 `Templates` 下拉列表。
    - **失败**：显示后端返回的错误消息。

| No. |   检查时机   |    检查对象    |        检查条件         | 错误消息 (Message Content) |       动作        |

## 4. 接口定义 (API Specification)

### 4.1 Template Upload (上传)

- **功能**：上传 VIN plate 模板文件至指定市场目录。
- **Method**: `POST`
- **Endpoint**: `/api/template/upload`

#### Request Body (Multipart/Form-Data 或 JSON with Base64)

_建议采用 Multipart/Form-Data 以支持大文件流式传输，若依 prompt 要求使用 JSON Base64：_

```json
{
  "file": "base64-encoded-rtf-content...",
  "market": "JPN"
}
```

#### Response Success (201 Created)

```json
{
  "success": true,
  "message": "TEMPLATE VIN_PLATE_JPN.rtf WAS SUCCESSFULLY UPLOADED TO MARKET JPN"
}
```

#### Response Error (400 Bad Request)

```json
{
  "error": "Invalid file type",
  "message": "Only .rtf files are allowed"
}
```

### 4.2 Template Delete (删除)

- **功能**：从指定市场目录删除模板文件。
- **Method**: `DELETE`
- **Endpoint**: `/api/template/delete`

#### Request Body

```json
{
  "market": "JPN",
  "templateName": "VIN_PLATE_JPCT.rtf"
}
```

#### Response Success (200 OK)

```json
{
  "success": true,
  "message": "TEMPLATE VIN_PLATE_JPCT.rtf WAS SUCCESSFULLY DELETE FROM MARKET JPN"
}
```

#### Response Error (404 Not Found)

```json
{
  "error": "Not Found",
  "message": "Template not found"
}
```

### 4.3 Get Templates List (获取模板列表 - 辅助接口)

_注：Prompt 中未明确列出此接口，但为了实现“Market (Delete)”联动“Templates”下拉框，必须存在此接口。_

- **功能**：获取指定市场下的模板文件列表。
- **Method**: `GET`
- **Endpoint**: `/api/template/list/{market}`

#### Response Success (200 OK)

```json
{
  "templates": ["VIN_PLATE_JPN.rtf", "DIM_PLATE_JPN.rtf"]
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景           | 处理方式           | Message 显示内容               |
| :----------------- | :----------------- | :----------------------------- |
| **网络断开/超时**  | 捕获 Network Error | `网络连接失败，请检查网络设置` |
| **权限不足**       | 捕获 API 403       | `您没有权限执行此操作`         |

| **模板不存在**     | 捕获 API 404       | `模板不存在`                   |
| **服务器内部错误** | 捕获 Server Error  | `系统繁忙，请稍后再试`         |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `uploadFile`, `uploadMarket`, `deleteMarket`, `deleteTemplate`, `templateOptions` (用于删除下拉框), `errorMessage`, `isLoading`。
    - `templateOptions` 需在 `deleteMarket` 变化时通过 `useEffect` 重新 fetch。
2.  **文件处理**：
    - 使用 `<input type="file" accept=".rtf" />` 限制文件选择器默认只显示 .rtf 文件，但仍需在后端和前端 JS 中再次校验扩展名，以防用户强行选择所有文件。
    - 若使用 Base64 上传，注意大文件可能导致内存溢出或请求体过大，建议评估是否改用 `FormData` + `axios.post`。
3.  **UI 细节**：
    - **联动逻辑**：`Market (Delete)` 选择后，若 `Templates` 下拉框为空，应显示 Loading 状态直到数据返回。
    - **删除确认**：使用 `Modal.confirm` 进行二次确认，标题为“Confirm Delete”，内容为“Do you really want to delete template?”。
    - **成功提示**：使用 `message.success` 展示后端返回的具体成功消息（包含文件名和市场）。
4.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 后端应严格校验上传文件的 MIME Type 和魔数（Magic Number），不仅仅依赖扩展名。
    - 删除接口的 `templateName` 应防止路径遍历攻击（如 `../../etc/passwd`），后端应只允许文件名，并拼接到固定的市场目录下。
