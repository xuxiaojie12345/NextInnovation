## 1. 背景 (Background)

本模块用于支持用户对车辆铭牌模板中的变量值进行修改，并保存修改后的数据。主要功能包括展示当前车辆的 VIN 及相关字段的当前值，允许用户编辑部分字段并提交修改，同时提供下载空白铭牌文件和跳转至底盘详细信息页面的功能。

- **目标**：提供便捷的变量修改入口，确保修改操作经过校验，防止覆盖未发布版本，并记录操作日志。
- **安全性**：修改操作需校验是否已发布版本存在；所有修改必须经过系统验证后才允许提交；操作日志由后端记录。
- **用户体验**：
  - 界面简洁，重点突出可编辑字段。
  - 明确区分输入项与输出项。
  - 提供清晰的操作反馈（如保存成功提示）。
  - 支持快速访问相关联的数据（如底盘详情、模板文件）。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 **[Save]** 按钮时执行。

### 3.1 处理流程

1.  **开始**：用户点击 [Save] 按钮。
2.  **前置处理**：
    - 获取当前页面所有 `Modified value` 字段的输入值。
    - 对比 `Modified value` 与 `Current value`，识别出所有发生变化的字段。
3.  **空值/变更校验 (Frontend Check)**：
    - 若没有任何字段被修改（即所有 `Modified value` 为空或与 `Current value` 一致）：
      - 设置 `ErrorMessage` = `NO UNRELEASED VERSION EXISTS!`
      - **终止**流程，不调用 API。
4.  **API 调用 (Backend Check)**：
    - 若校验通过，构造请求体，调用 `POST /api/UD05ModifyDocumentApi/UD05UpdateHdocAdcaModification`。
5.  **结果处理**：
    - **成功**：跳转至 `/document/confirm-modify` 页面，展示修改内容列表。
    - **失败**：设置 `ErrorMessage` = `保存失败，请检查输入内容` 或后端返回的具体错误信息。

### 3.2 校验详细规格表

| No. |   检查时机   |    检查对象     |      检查条件       |   错误消息 (Message Content)    |            动作             |
| :-: | :----------: | :-------------: | :-----------------: | :-----------------------------: | :-------------------------: |
|  1  |  Click Save  | Modified Values | 无任何字段发生改变  | `NO UNRELEASED VERSION EXISTS!` | 显示 ErrorMessage，阻止提交 |
|  2  | API Response |  Update Result  | `Status != Success` |   `保存失败，请检查输入内容`    |      显示 ErrorMessage      |

## 4. 接口定义 (API Specification)

### 4.1 UD05SelectVariableModificationAPI

- **功能**：获取当前底盘的变量修改信息及当前值。
- **Method**: `GET`
- **Endpoint**: `/api/UD05ModifyDocumentApi/UD05SelectVariableModification`

#### Request Parameters

- `SERIE`: String (Query Param, e.g., "JPCT")
- `CHNO`: String (Query Param, e.g., "028321")

#### Response Success (200 OK)

```json
{
  "chassisNo": "JPCT028321",
  "market": "AUS",
  "templateFile": "aus/UD_TEST.odt",
  "modifications": [
    {
      "variable": "VIN",
      "description": "Vehicle Identification Number",
      "currentValue": "JPCYZ50A2LT028321",
      "modifiedValue": null
    },
    {
      "variable": "ENGINE_TYPE",
      "description": "Engine Type Code",
      "currentValue": "D13K",
      "modifiedValue": ""
    }
  ]
}
```

#### Response Error (404 Not Found)

```json
{
  "error": "Not Found",
  "message": "Chassis data not found"
}
```

### 4.2 UD05UpdateHdocAdcaModificationAPI

- **功能**：提交文档修改请求，记录变更内容并生成待发布版本。
- **Method**: `POST`
- **Endpoint**: `/api/UD05ModifyDocumentApi/UD05UpdateHdocAdcaModification`

#### Request Body

```json
{
  "chassisNo": "JPCT028321",
  "market": "AUS",
  "templateFile": "aus/UD_TEST.odt",
  "modifications": [
    {
      "variable": "VIN",
      "currentValue": "JPCYZ50A2LT028321",
      "modifiedValue": "JPCYZ50A2LT028322"
    }
  ]
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "Success",
  "data": {
    "redirectUrl": "/document/confirm-modify"
  }
}
```

#### Response Error (400/500)

```json
{
  "error": "Bad Request",
  "message": "保存失败，请检查输入内容"
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景          | 处理方式           | Message 显示内容                |
| :---------------- | :----------------- | :------------------------------ |
| **网络断开/超时** | 捕获 Network Error | `网络连接失败，请检查网络设置`  |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `chassisInfo`, `modificationsList`, `errorMessage`, `isLoading`。
    - `modificationsList` 应包含原始数据副本，以便在提交时对比变化。
2.  **交互细节**：
    - `Modified value` 输入框建议添加 `onChange` 事件，实时标记该行是否“已修改”（例如行背景色变浅黄），提升用户体验。
    - [Save](file://e:\git20260511\NextInnovation\react-ud\src\UD05\UD05.tsx#L10-L10) 按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
3.  **跳转逻辑**：
    - `Chassis no` 点击跳转至 `/chassis-detail/${chassisNo}`。
    - `Template Link` 点击直接触发下载，不跳转页面。
    - 保存成功后，使用 [navigate](file://e:\git20260511\NextInnovation\react-ud\src\Login\Login.tsx#L23-L23) 或 `window.location.href` 跳转至确认页面。
4.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 对输入内容进行 sanitization，防止 XSS 攻击。
    - 严禁在前端日志中打印敏感的车辆配置数据。
