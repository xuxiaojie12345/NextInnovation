## 1. 背景 (Background)

本模块是认证文档生成流程的入口页面。用户通过输入车辆底盘系列（Chassis series）、底盘编号（Chassis no）和文档类型（Document type），发起文档生成请求。

- **目标**：提供简洁的查询入口，支持自动回填上次检索条件以提升效率，并校验输入合法性后跳转至生成页面。
- **用户体验**：
  - 界面简洁，仅包含必要输入项（左侧为入力框名称，右侧为入力框以及下拉框，入力框和下拉框左面的对齐的。底板的三个按钮都为浅蓝色，按钮中的字体为深蓝色）。
  - 提供“Help”链接便于查阅说明。
  - 错误信息在页面内明确提示，避免弹窗打断。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 **[Submit]** 按钮时执行。

### 3.1 处理流程

#### 3.1.1 初期处理

1. 初期进入画面的时候，调用API获取下拉列表中的值（UD03SelectHdocdocumentlistApi）。

#### 3.1.2 [Submit] 按钮处理

1.  **开始**：用户点击 [Submit] 按钮。
2.  **前置处理**：获取 `Chassis series`, `Chassis no`, `Document type`，执行 `trim()` 去除首尾空白。
3.  **空值校验 (Frontend Check)**：
    - 若 `Chassis series` 为空 **或** `Chassis no` 为空：
      - 设置 `ErrorMessage` = `Chassis series and chassis no are required.`
      - **终止**流程。
    - 若 `Document type` 未选择（值为空或默认占位符）：
      - 设置 `ErrorMessage` = `Please select a document type.`
      - **终止**流程。
4.  **结果处理**：
    - **校验/验证成功**：携带参数跳转至 `Generate document` 页面。
    - **验证失败**：设置 `ErrorMessage` = `Chassis no is not exists`。

#### 3.1.3 [Reset] 按钮处理

1.  **开始**：用户点击 [Reset] 按钮。
2.  **结果处理**：
    - **成功**：画面的初期状态表示。

#### 3.1.4 [HDoc Help] 按钮处理

1.  **开始**：用户点击 [HDoc Help] 按钮。
2.  **结果处理**：
    - **成功**：转移到Help画面。

## 4. 接口定义 (API Specification)

### 4.1 UD03SelectHdocdocumentlistApi

- **功能**：获取文档类型下拉列表数据。
- **Method**: `GET`
- **Endpoint**: `/api/ud03selecthdocdocumentlistapi/types`

#### Request Body

无参数。

#### Response Success (200 OK)

```json
[
  { "doctyp": "Dimension Plate" },
  { "doctyp": "VIN Plate" },
  { "doctyp": "COC" }
]
```

#### Response Error (500 Internal Server Error)

```json
{
  "error": "Internal Server Error",
  "message": "Failed to load document types"
}
```

_(注：若提交时需要验证底盘存在性，应另有 API，如 `POST /api/chassis/verify`，此处仅列出模板中明确的 API)_

## 5. 异常处理 (Exception Handling)

| 异常场景                 | 处理方式              | Message 显示内容                                 |
| :----------------------- | :-------------------- | :----------------------------------------------- |
| **网络断开/超时**        | 捕获 Network Error    | `Network error. Please check your connection.`   |
| **底盘编号不存在**       | 捕获 API 404/业务错误 | `Chassis no is not exists`                       |
| **服务器内部错误 (500)** | 捕获 Server Error     | `System error. Please contact administrator.`    |
| **获取下拉列表失败**     | 禁用 Submit 或提示    | `Failed to load document types. Please refresh.` |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `chassisSeries`, `chassisNo`, `documentType`, `errorMessage`, `isLoading`, `docTypeOptions`。
    - `ErrorMessage` Label 默认隐藏（内容为空时不占位或高度为0）。
2.  **数据持久化**：
    - 为了支持“自动回填上一次的检索条件”，建议在 `localStorage` 或 `sessionStorage` 中保存用户最后成功提交的查询条件。页面加载时读取并填充表单。
3.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 对输入内容进行 sanitization，防止 XSS 攻击（虽然主要是跳转，但需确保参数编码正确）。
4.  **UI 细节**：
    - [Submit]按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
    - `ErrorMessage` 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
    - `Reset` 按钮点击后，除了清空表单，也应清除 `localStorage` 中的临时缓存（可选，视产品定义而定，通常 Reset 仅清空当前视图）。
