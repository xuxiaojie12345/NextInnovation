1. 背景 (Background)

本模块的核心功能是配置用户对各类认证文档的操作权限。用户可通过输入 User ID，从 Saviynt 系统获取用户名，并查询其在 HDoc 中可分配的文档权限列表。系统支持勾选多个文档类型并提交更新，确保权限配置准确且安全。

  • 目标：实现细粒度的文档级权限控制，确保用户仅能访问被授权的文档类型，并与 Saviynt 系统中的用户主数据保持一致。
  • 安全性：
    • 仅允许授权用户（如系统管理员）访问此页面。
    • 所有权限变更需经过后端校验及确认。
    • 数据更新由后端统一控制，防止并发冲突。
    • 所有通信使用 HTTPS 加密。
  • 用户体验：
    • 界面简洁，突出核心操作区域（查询、文档勾选、提交）。
    • 支持快速输入与权限查看。
    • 权限项以复选框或列表形式展示，直观易懂。
    • 所有操作均有明确的成功/失败反馈提示。

3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 [User Info] 或 [Update] 按钮时执行。

3.1 处理流程

  1. 开始：页面加载或用户点击操作按钮。
  2. 初始化 (Page Mount)：
    • 调用 GET /api/UD18HDocUserDocAdministrationApi/UD20SelectHdocDocumentList 获取所有可用文档类型。
    • 渲染文档列表，默认均为未选中状态。
  3. 前置处理：获取 [UserID](file://e:\git20260511\NextInnovation\react-ud\src\Login_x\Login.tsx#L5-L5) 输入值，执行 trim()。
  4. 空值校验 (Frontend Check)：
    • 若点击 User Info 或 Update：
      • 检查 [UserID](file://e:\git20260511\NextInnovation\react-ud\src\Login_x\Login.tsx#L5-L5) 是否为空。
      • 若为空，设置 Message = 请输入用户 ID，终止流程。
  5. API 调用 (Backend Check)：
    • User Info:
      1. 调用 GET /api/AuthenticationApi/Login (注：Prompt 中以此接口获取用户信息，实际应为专门的 User Info 接口，此处依 Prompt 定义) 获取用户姓名。
      2. 同时/随后调用后端接口（如 UD18SelectHdocUserDoc）获取该用户已拥有的文档权限列表。
      3. 若 UserID 不存在于 HDOC_FUNCTION_AUTH，返回错误。
    • Update:
      1. 收集当前所有被勾选的文档 ID。
      2. 调用后端更新接口（Prompt 中列出了多个 Update/Delete/Create 接口，建议后端封装为一个统一的 Update 接口，或前端依次调用）。
      3. 后端校验 UserID 有效性。
  6. 结果处理：
    • User Info 成功：
      • 显示 User Name。
      • 根据返回的权限列表，勾选 Document List 中对应的 Checkbox。
    • User Info 失败 (404)：显示 We didn't recognize the userid you entered. Please try again.，清空姓名和勾选状态。
    • Update 成功：提示“权限更新成功”。
    • Update 失败：提示具体错误（如“您没有权限执行此操作”或“用户不存在”）。

6. 实现注意事项 (Implementation Notes)

  1. 状态管理：
    • 使用 React State 管理 userId, userName, allDocuments (列表), userPermissions (Set 或 Array), message, isLoading。
    • allDocuments 在 useEffect (Mount) 时加载。
    • userPermissions 在点击 User Info 成功后更新。
  2. 交互细节：
    • Loading 状态：点击 User Info 或 Update 时，禁用相关按钮并显示 Loading 图标。
    • Checkbox 绑定：Document List 中的每个 Checkbox 的 checked 属性应绑定到 userPermissions.includes(doc)。
    • Update 逻辑：前端只需提交当前所有被选中的文档列表给后端，由后端决定哪些需要插入 HDOC_USER_DOC 表，哪些需要删除，简化前端逻辑。
    • Message 样式：成功消息绿色，错误消息红色。
  3. 安全性：
    • API 请求必须通过 HTTPS 发送。
    • 后端需校验当前操作员是否有“用户文档权限管理”权限。
    • UserId 输入需进行 sanitization，防止注入攻击。
  4. 数据一致性：
    • User Name 仅从 Saviynt (AuthenticationApi) 读取，不可在前端编辑。
    • 文档列表应从 HDOC_DOCUMENT_LIST 动态获取，避免硬编码。
