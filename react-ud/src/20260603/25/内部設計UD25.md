## 1. 背景 (Background)

本模块的核心功能是展示用户在 EDB 系统中的基本信息，包括 User ID、负责人姓名、职位和电子邮件。该页面用于提供用户信息的只读视图，支持系统管理员或相关人员查阅用户资料。

- **目标**：以只读表单形式呈现 EDB 用户信息，便于用户快速查阅用户资料。
- **面向的用户群体**：
  - 系统管理员
  - IT 运维人员
  - 安全管理人员
- **用户体验**：
  - 界面简洁，仅包含必要字段
  - 所有字段均为输出型，不可编辑
  - 支持快速浏览与返回操作
  - 提供清空按钮，便于重新查询
- **安全性**：
  - 仅允许授权用户访问此页面
  - 所有通信使用 HTTPS 加密
  - 数据来源为 Saviynt 的 AuthenticationApi，确保一致性
  - 不暴露敏感信息

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有逻辑均在页面加载时自动执行。

### 3.1 处理流程

1.  **开始**：用户访问 EDB User View 页面。
2.  **前置处理**：无前端校验，直接加载数据。
3.  **空值校验 (Frontend Check)**：
    - 无前端校验，直接加载数据。
4.  **API 调用 (Backend Check)**：
    - 调用 `POST /api/AuthenticationApi/login`（仅传 `userid`，不传密码）获取用户信息。
5.  **结果处理**：
    - **成功**：正常渲染 Userid、Responsible、User Position、E-mail 字段。
    - **失败**：显示错误消息：「无法加载用户信息，请稍后重试」。

### 3.2 清空功能处理流程

1.  **开始**：用户点击「Clear」按钮。
2.  **处理**：清空页面所有文本框内容。
3.  **结束**：页面恢复初始状态。

### 3.3 返回功能处理流程

1.  **开始**：用户点击「Back」按钮。
2.  **处理**：系统跳转至前一个页面，不保存当前状态。
3.  **结束**：页面跳转完成。

### 3.4 校验详细规格表

| No. |  检查时机  | 检查对象 |     检查条件     | 错误消息 (Message Content) |     动作     |
| :-: | :--------: | :------: | :--------------: | :------------------------: | :----------: |
|  1  | 页面加载时 |  Userid  | 不存在于 Saviynt |       「用户不存在」       | 显示警告信息 |

## 4. 接口定义 (API Specification)

### 4.1 获取用户信息接口

- **功能**：获取指定用户的详细信息。
- **Method**: `POST`
- **Endpoint**: `/api/AuthenticationApi/login`

#### Request Body

```json
{
  "userid": "t009667"
}
```

> **注**：仅传入 `userid` 时，系统执行用户信息查询（不验证密码）。
> 同时传入 `userid` 和 `password` 时，系统执行登录认证。

#### Response Success (200 OK)

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "userid": "t009667",
    "responsible": "Mats Gustafsson",
    "userPosition": "Senior Solution Leader",
    "email": "mats.e.gustavsson@volvo.com"
  }
}
```

#### Response Error (404 Not Found)

```json
{
  "code": 404,
  "msg": "用户不存在",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景                 | 处理方式                 | Message 显示内容                 |
| :----------------------- | :----------------------- | :------------------------------- |
| **网络超时**             | 重试一次，若仍失败则提示 | 「网络连接失败，请检查网络设置」 |
| **用户不存在 (404)**     | 返回错误响应             | 「用户不存在」                   |
| **数据库异常**           | 回滚事务，记录日志       | 「系统繁忙，请稍后再试」         |
| **服务器内部错误 (500)** | 捕获 Server Error        | 「无法加载用户信息，请稍后重试」 |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `userInfo`（用户信息数据）、`isLoading`（加载状态）、`errorMessage`（错误消息）。
    - 页面初始化时自动触发数据加载。
2.  **加载状态**：
    - 数据加载期间应显示 Loading 指示器（如 Spin 或 Skeleton），提升用户体验。
3.  **错误处理**：
    - API 调用失败时，页面中央显示错误消息，并提供重试按钮或提示用户刷新页面。
4.  **UI 细节**：
    - Userid 字段可在页面顶部突出显示，作为用户标识。
    - E-mail 字段建议渲染为超链接（`mailto:`），便于快速发送邮件。
    - 「Clear」与「Back」按钮应置于页面底部或表单下方，保持布局一致。
5.  **按钮交互**：
    - 「Clear」按钮点击时，无需调用 API，仅清空前端状态。
    - 「Back」按钮可使用 `window.history.back()` 或路由导航实现返回功能。
