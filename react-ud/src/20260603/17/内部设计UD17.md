## 1. 背景 (Background)

本模块的核心功能是提供对 HDoc 系统用户的权限配置与管理。用户可通过输入 User ID，从 Saviynt 系统获取用户基本信息，并查询其在 HDoc 中的现有权限，支持更新或删除角色配置。

- **目标**：实现用户权限的集中化管理，确保权限分配准确、可追溯，并与 Saviynt 系统中的用户主数据保持一致。
- **安全性**：
  - 仅允许授权用户（如系统管理员）访问此页面。
  - 所有权限变更需经过后端校验及确认。
  - 数据更新由后端统一控制，防止并发冲突。
  - 所有通信使用 HTTPS 加密。
- **用户体验**：
  - 界面简洁，突出核心操作区域（查询、权限勾选、提交）。
  - 支持快速输入与权限查看。
  - 权限项以复选框形式展示，直观易懂。
  - 所有操作均有明确的成功/失败反馈提示。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 **[USER INFO]**, **[Update Role]**, 或 **[Delete Role]** 按钮时执行。

### 3.1 处理流程

1.  **开始**：用户点击操作按钮。
2.  **前置处理**：获取 [UserID]输入值，执行 `trim()`。
3.  **空值校验 (Frontend Check)**：
    - 若点击 **USER INFO**, **Update Role**, 或 **Delete Role**：
      - 检查 [UserID]是否为空。
      - 若为空，设置 `Message` = `请输入用户 ID`，**终止**流程。
4.  **二次确认 (Delete Only)**：
    - 若点击 **Delete Role**：
      - 弹出确认对话框：“确定要删除该用户的所有权限吗？”
      - 若用户取消，**终止**流程。
5.  **API 调用 (Backend Check)**：
    - **USER INFO**: 调用 `GET /api/ud17hdocuseradministrationapi/ud17userinfo`。
    - **Update Role**: 收集所有被勾选的 Checkbox 状态及 Market 选择，调用 `PUT /api/ud17hdocuseradministrationapi/ud17updaterole`。
    - **Delete Role**: 调用 `DELETE /api/ud17hdocuseradministrationapi/ud17deleterole`。
6.  **结果处理**：
    - **USER INFO 成功**：
      - 显示 `User Name`。
      - 根据返回的 roles 列表勾选对应的 Checkbox。
      - 设置 Market 下拉框默认值。
    - **USER INFO 失败 (404)**：显示 `We didn't recognize the userid you entered. Please try again.`，清空下方权限区域。
    - **Update 成功**：提示“权限更新成功”。
    - **Update 失败**：提示具体错误（如“您没有权限执行此操作”）。
    - **Delete 成功**：提示“权限已清除”，重置所有 Checkbox 为未选中状态。

## 4. 接口定义 (API Specification)

### 4.1 Get User Info (获取用户信息及权限)

- **功能**：从 Saviynt 获取用户姓名，并从 HDoc 数据库获取现有权限。
- **Method**: `GET`
- **Endpoint**: `/api/ud17hdocuseradministrationapi/ud17userinfo`

#### Request Parameters (Query or Body)

```json
{
  "userId": "v0c6900"
}
```

#### Response Success (200 OK)

```json
{
  "userName": "John Doe",
  "roles": ["Standard User", "Rule Admin"],
  "market": "-EU"
}
```

_(注：roles 数组中的字符串需与前端 Checkbox 的 value 严格匹配)_

#### Response Error (404 Not Found)

```json
{
  "error": "Not Found",
  "message": "We didn't recognize the userid you entered. Please try again."
}
```

### 4.2 Update Role (更新权限)

- **功能**：更新指定用户的角色权限和市场关联。
- **Method**: `PUT`
- **Endpoint**: `/api/ud17hdocuseradministrationapi/ud17updaterole`

#### Request Body

```json
{
  "userId": "v0c6900",
  "roles": ["Standard User", "Rule Admin", "Template Admin"],
  "market": "-EU"
}
```

#### Response Success (200 OK)

```json
{
  "success": true,
  "message": "权限更新成功"
}
```

#### Response Error (403 Forbidden)

```json
{
  "error": "Forbidden",
  "message": "您没有权限执行此操作"
}
```

### 4.3 Delete Role (删除权限)

- **功能**：清空指定用户的所有 HDoc 权限。
- **Method**: `DELETE`
- **Endpoint**: `/api/ud17hdocuseradministrationapi/ud17deleterole`

#### Request Body

```json
{
  "userId": "v0c6900"
}
```

#### Response Success (200 OK)

```json
{
  "success": true,
  "message": "权限已清除"
}
```

#### Response Error (404 Not Found)

```json
{
  "error": "Not Found",
  "message": "User not found"
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景             | 处理方式           | Message 显示内容                                                |
| :------------------- | :----------------- | :-------------------------------------------------------------- |
| **网络断开/超时**    | 捕获 Network Error | `网络连接失败，请检查网络设置`                                  |
| **用户不存在**       | 捕获 API 404       | `We didn't recognize the userid you entered. Please try again.` |
| **数据库异常**       | 捕获 Server Error  | `系统繁忙，请稍后再试`                                          |
| **Saviynt 同步失败** | 捕获 API 500       | `无法获取用户主数据，请稍后重试`                                |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `userId`, `userName`, `permissions` (对象或数组), `selectedMarket`, `message`, `isLoading`。
    - `permissions` 状态应映射到各个 Checkbox 的 `checked` 属性。
2.  **交互细节**：
    - **Loading 状态**：点击 `USER INFO` 或 `Update Role` 时，禁用相关按钮并显示 Loading 图标。
    - **Checkbox 绑定**：建议使用受控组件，当 `USER INFO` 返回数据时，批量更新 Checkbox 状态。
    - **Delete 确认**：必须使用 `Modal.confirm` 进行二次确认，防止误删。
    - **Message 样式**：成功消息绿色，错误消息红色。
3.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 后端需校验当前操作员是否有“用户管理”权限，防止普通用户篡改他人权限。
    - `UserId` 输入需进行 sanitization，防止注入攻击。
4.  **数据一致性**：
    - `User Name` 仅从 Saviynt 读取，不可在前端编辑。
    - 权限列表（Roles）建议由后端字典接口动态获取，以便未来扩展新角色时无需修改前端代码（若角色固定则硬编码亦可）。
