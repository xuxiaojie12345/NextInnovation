2. 背景 (Background)
  本模块的核心功能是对 `ADCA Change` 表中的数据进行新增、删除和校验操作。用户可通过输入 Serie-Chnr（底盘系列+编号）组合，执行相应的CRUD操作，并在系统中保存变更记录。

  面向的用户群体：
  - 系统管理员
  - 生产工程师
  - 认证管理人员

  用户体验方面的考虑：
  - 界面简洁，仅包含必要控件
  - 支持快速输入与操作
  - 所有操作均有明确反馈提示
  - 校验结果以警告形式展示

  安全性或特殊要求：
  - 所有操作需确认
  - 数据更新由后端统一控制，防止并发冲突
  - 所有通信使用 HTTPS 加密

4. 功能描述 (Functional Description)

    4.1 新增功能
    功能说明：用户输入 Serie-Chnr 和 Desc 后点击“ADD”按钮，将新记录插入数据库。
    操作步骤：
      1. 用户在 Serie-Chnr 字段中输入底盘系列+编号（如 JPCT013945）
      2. 在 Desc 字段中输入描述信息（可选）
      3. 点击“ADD”按钮
      4. 系统校验输入合法性
      5. 若通过，则调用接口插入记录
      6. 成功后提示：“新增成功”

    4.2 删除功能
    功能说明：用户输入 Serie-Chnr 后点击“DELETE”按钮，从数据库中移除对应记录。
    操作步骤：
      1. 用户在 Serie-Chnr 字段中输入要删除的底盘编号
      2. 点击“DELETE”按钮
      3. 弹出确认对话框：“确定要删除该记录吗？”
      4. 用户确认后，系统调用接口执行删除
      5. 成功后提示：“删除成功”

    4.3 校验检查功能
    功能说明：用户输入 Serie-Chnr 后点击“CHECK”按钮，系统检查该记录是否已激活。
    操作步骤：
      1. 用户在 Serie-Chnr 字段中输入底盘编号
      2. 点击“CHECK”按钮
      3. 系统查询 HDOC_ADCA_CHANGE 表
      4. 若 ACT 字段为 'Y'，则返回正常
      5. 若 ACT 字段为 'N' 或不存在，则显示警告：“AFTER DEF CHANGE IS NOT ACTIVATED”
      6. 提示用户当前状态不可用

5. 业务逻辑与校验规则 (Business Logic & Checks)

   5.1 处理流程

      开始：用户点击 ADD / DELETE / CHECK 按钮
      前置处理：获取 serieChnr 参数

      5.1.1 空值校验等 (Frontend Check)：
       若点击 ADD 或 DELETE 且 serieChnr 为空：
        设置Message = “Serie-Chnr 是必填项”
        终止流程

      5.1.2 API调用 (Backend Check)：
        调用 `POST /api/UD16ADChangeApi/UD16InsertHdocAdcaChange` 添加记录
        调用 `DELETE /api/UD16ADChangeApi/UD16UpdateHdocAdcaChange` 删除记录
        调用 `GET /api/UD16ADChangeApi/UD16SelectHdocAdcaChange` 校验状态

   5.2 结果处理：
       成功：显示提示消息“操作成功”
       失败：显示错误消息“操作失败，请稍后重试”

   5.3 校验详细规格表

   | No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 (Message Content) | 动作 |
   |-----|---------|---------|---------|--------------------------|------|
   | 1   | 点击 ADD/DELETE | Serie-Chnr | 为空 | “Serie-Chnr 是必填项” | 阻止提交 |
   | 2   | 校验时 | ACT 字段 | 不为 'Y' | “AFTER DEF CHANGE IS NOT ACTIVATED” | 显示警告 |

6. 接口定义 (API Specification)

   UD16ADChangeApi
     功能：新增一条 ADCA Change 记录
     Method：POST
     Endpoint：/api/UD16ADChangeApi/UD16InsertHdocAdcaChange

     Request [json]
     {
       "serieChnr": "JPCT013945",
       "desc": "Test description"
     }

     Response Success (201)
     {
       "success": true,
       "message": "新增成功"
     }

     Response Error (409)
     {
       "error": "Conflict",
       "message": "Record already exists"
     }

     功能：删除指定 ADCA Change 记录
     Method：DELETE
     Endpoint：/api/UD16ADChangeApi/UD16UpdateHdocAdcaChange

     Request [json]
     {
       "serieChnr": "JPCT013945"
     }

     Response Success (200)
     {
       "success": true,
       "message": "删除成功"
     }

     Response Error (404)
     {
       "error": "Not Found",
       "message": "Record not found"
     }

     功能：校验 ADCA Change 状态
     Method：GET
     Endpoint：/api/UD16ADChangeApi/UD16SelectHdocAdcaChange

     Request [json]
     {
       "serieChnr": "JPCT013945"
     }

     Response Success (200)
     {
       "activated": true,
       "message": "AFTER DEF CHANGE IS ACTIVATED"
     }

     Response Error (400)
     {
       "error": "Not Activated",
       "message": "AFTER DEF CHANGE IS NOT ACTIVATED"
     }

7. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message显示内容 |
|---------|---------|----------------|
| 网络超时 | 重试一次，若仍失败则提示 | “网络连接失败，请检查网络设置” |
| 记录已存在 | 返回错误响应 | “Record already exists” |
| 记录不存在 | 返回错误响应 | “Record not found” |
| 数据库异常 | 回滚事务，记录日志 | “系统繁忙，请稍后再试” |
