## 1. 背景 (Background)

本模块的核心功能是对 `HDOC_ADCA_CHANGE` 表中的数据进行新增、删除和校验操作。用户可通过输入 Serie-Chnr（底盘系列+编号）组合，执行相应的 CRUD 操作，并在系统中保存变更记录。

- **目标**：提供便捷的 AD/CA 变更管理入口，确保变更记录的准确性，并提供激活状态的快速校验。
- **安全性**：
  - 仅允许授权用户访问此页面。
  - 所有操作需经过后端权限校验。
  - 数据更新由后端统一控制，防止并发冲突。
  - 所有通信使用 HTTPS 加密。
- **用户体验**：
  - 界面简洁，仅包含必要控件（输入框、三个操作按钮）。
  - 支持快速输入与操作。
  - 所有操作均有明确的成功/失败反馈提示。
  - 校验结果以警告形式展示（如未激活提示）。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 **[ADD]**, **[DELETE]**, 或 **[CHECK]** 按钮时执行。

### 3.1 处理流程

1.  **开始**：用户点击操作按钮。
2.  **前置处理**：获取 `Serie-Chnr` 和 `Desc`（仅 Add 需要）输入值，执行 `trim()`。
3.  **空值校验 (Frontend Check)**：
    - 若点击 **ADD** 或 **DELETE** 或 **CHECK**：
      - 检查 `Serie-Chnr` 是否为空。
      - 若为空，设置 `Message` = `Serie-Chnr 是必填项`，**终止**流程。
4.  **二次确认 (Delete Only)**：
    - 若点击 **DELETE**：
      - 弹出确认对话框：“确定要删除该记录吗？”
      - 若用户取消，**终止**流程。
5.  **API 调用 (Backend Check)**：
    - **ADD**: 调用 `POST /api/UD16ADChangeApi/UD16InsertHdocAdcaChange`。
    - **DELETE**: 调用 `DELETE /api/UD16ADChangeApi/UD16UpdateHdocAdcaChange` (注：Endpoint 名称虽为 Update，但 Method 为 DELETE，依 Prompt 定义)。
    - **CHECK**: 调用 `GET /api/UD16ADChangeApi/UD16SelectHdocAdcaChange`。
6.  **结果处理**：
    - **ADD 成功**：提示“新增成功”，清空 Desc 输入框（可选）。
    - **ADD 失败 (409)**：提示“Record already exists”。
    - **DELETE 成功**：提示“删除成功”。
    - **DELETE 失败 (404)**：提示“Record not found”。
    - **CHECK 成功 (Activated)**：提示“AFTER DEF CHANGE IS ACTIVATED” (绿色/正常色)。
    - **CHECK 失败 (Not Activated)**：提示“AFTER DEF CHANGE IS NOT ACTIVATED” (警告色)。

## 4. 接口定义 (API Specification)

### 4.1 Insert ADCA Change (新增)

- **功能**：新增一条 ADCA Change 记录。
- **Method**: `POST`
- **Endpoint**: `/api/UD16ADChangeApi/UD16InsertHdocAdcaChange`

#### Request Body

```json
{
  "serieChnr": "JPCT013945",
  "desc": "Test description"
}
```

#### Response Success (201 Created)

```json
{
  "success": true,
  "message": "新增成功"
}
```

#### Response Error (409 Conflict)

```json
{
  "error": "Conflict",
  "message": "Record already exists"
}
```

### 4.2 Delete ADCA Change (删除)

- **功能**：删除指定 ADCA Change 记录。
- **Method**: `DELETE`
- **Endpoint**: `/api/UD16ADChangeApi/UD16UpdateHdocAdcaChange`

#### Request Body

```json
{
  "serieChnr": "JPCT013945"
}
```

#### Response Success (200 OK)

```json
{
  "success": true,
  "message": "删除成功"
}
```

#### Response Error (404 Not Found)

```json
{
  "error": "Not Found",
  "message": "Record not found"
}
```

### 4.3 Select ADCA Change (校验状态)

- **功能**：校验 ADCA Change 记录的激活状态。
- **Method**: `GET`
- **Endpoint**: `/api/UD16ADChangeApi/UD16SelectHdocAdcaChange`

#### Request Parameters (Query or Body)

```json
{
  "serieChnr": "JPCT013945"
}
```

#### Response Success (200 OK) - Activated

```json
{
  "activated": true,
  "message": "AFTER DEF CHANGE IS ACTIVATED"
}
```

#### Response Error (400 Bad Request) - Not Activated

```json
{
  "error": "Not Activated",
  "message": "AFTER DEF CHANGE IS NOT ACTIVATED"
}
```

_(注：Prompt 中将未激活定义为 Error 400，前端需据此显示警告)_

## 5. 异常处理 (Exception Handling)

| 异常场景          | 处理方式           | Message 显示内容                    |
| :---------------- | :----------------- | :---------------------------------- |
| **网络断开/超时** | 捕获 Network Error | `网络连接失败，请检查网络设置`      |
| **权限不足**      | 捕获 API 403       | `您没有权限执行此操作`              |
| **记录已存在**    | 捕获 API 409       | `Record already exists`             |
| **记录不存在**    | 捕获 API 404       | `Record not found`                  |
| **数据库异常**    | 捕获 Server Error  | `系统繁忙，请稍后再试`              |
| **未激活状态**    | 捕获 API 400       | `AFTER DEF CHANGE IS NOT ACTIVATED` |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `serieChnr`, `desc`, `message`, `messageType` (success/error/warning), `isLoading`。
    - `messageType` 用于控制 Message Label 的颜色样式。
2.  **交互细节**：
    - **Loading 状态**：点击按钮后，禁用所有输入框和按钮，直到 API 返回结果。
    - **Delete 确认**：使用 `Modal.confirm` 进行二次确认，确保用户意图明确。
    - **Check 反馈**：由于 Check 是一种查询而非修改，其“错误”状态（未激活）实际上是业务警告，UI 上应区别于系统错误（如网络失败）。建议使用黄色/橙色图标或文字。
3.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 对 `serieChnr` 进行 sanitization，防止 SQL 注入。
    - 后端应校验当前用户是否有权限执行增删操作。
4.  **UI 布局**：
    - 输入框在上，按钮在下居中排列。
    - Message Label 位于按钮下方或页面顶部显眼位置。
