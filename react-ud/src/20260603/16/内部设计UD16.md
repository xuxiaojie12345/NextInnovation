## 1. 背景 (Background)

本模块的核心功能是对 `HDOC_ADCA_CHANGE` 表中的数据进行新增、删除和校验操作。用户可通过输入 Serie-Chnr（底盘系列+编号）组合，执行相应的操作。

- **目标**：提供便捷的 AD/CA 变更管理入口，确保变更记录的准确性，并提供激活状态的快速校验。
- **用户体验**：
  - 界面简洁，仅包含必要控件（输入框、三个操作按钮）。
  - 所有操作均有明确的成功/失败反馈提示。
  - 校验结果以警告形式展示（如未激活提示）。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

1. **开始**：用户点击操作按钮。
2. **前置处理**：获取 `Serie-Chnr` 和 `Desc` 输入值。
3. **空值校验**：
   - 若点击任意按钮且 `Serie-Chnr` 为空：设置 `Message` = `Serie-Chnr 是必填项`，**终止**流程。
4. **机能处理**：
   - 点击ADD按钮，调用/api/ud16adchangeapi/ud16inserthdocadcachange
   - 点击DELETE按钮，调用/api/ud16adchangeapi/ud16updatehdocadcachange
   - 点击CHECK按钮，调用/api/ud16adchangeapi/ud16selecthdocadcachange
5. **二次确认 (Delete Only)**：
   - 若点击 DELETE：弹出确认对话框，用户取消则**终止**。
6. **API 调用**：
   - **ADD**: `POST /api/ud16adchangeapi/ud16inserthdocadcachange`
   - **DELETE**: `POST /api/ud16adchangeapi/ud16updatehdocadcachange`
   - **CHECK**: `POST /api/ud16adchangeapi/ud16selecthdocadcachange`
7. **结果处理**：
   - 成功：显示绿色成功消息。
   - 失败：显示红色错误消息。
   - CHECK 未激活：显示橙色警告消息。

### 3.2 校验详细规格表

| No. |   检查时机   |     检查对象      |                检查条件                |     错误消息 (Message Content)      |          动作          |
| :-: | :----------: | :---------------: | :------------------------------------: | :---------------------------------: | :--------------------: |
|  1  |  Click Any   |    Serie-Chnr     | `Value == null` OR `Trim(Value) == ""` |        `Serie-Chnr 是必填项`        | 显示 Message，焦点停留 |
|  2  | API Response | Record Existence  |         `Status == 409` (Add)          |       `Record already exists`       |      显示 Message      |
|  3  | API Response | Record Existence  |        `Status == 404` (Delete)        |         `Record not found`          |      显示 Message      |
|  4  | API Response | Activation Status |      `activated == false` (Check)      | `AFTER DEF CHANGE IS NOT ACTIVATED` |  显示 Warning Message  |

## 4. 接口定义 (API Specification)

### 4.1 Insert (新增)

- **Method**: `POST`
- **Endpoint**: `/api/ud16adchangeapi/ud16inserthdocadcachange`
- **Request**: `{ "serieChnr": "JPCT013945", "desc": "description" }`
- **Response Success**: `{ "code": 200, "msg": "新增成功" }`
- **Response Error**: `{ "code": 409, "msg": "Record already exists" }`

### 4.2 Delete (删除)

- **Method**: `POST`
- **Endpoint**: `/api/ud16adchangeapi/ud16updatehdocadcachange`
- **Request**: `{ "serieChnr": "JPCT013945" }`
- **Response Success**: `{ "code": 200, "msg": "删除成功" }`
- **Response Error**: `{ "code": 404, "msg": "Record not found" }`

### 4.3 Select (校验)

- **Method**: `POST`
- **Endpoint**: `/api/ud16adchangeapi/ud16selecthdocadcachange`
- **Request**: `{ "serieChnr": "JPCT013945" }`
- **Response Success**: `{ "code": 200, "msg": "AFTER DEF CHANGE IS ACTIVATED" }`
- **Response Warning**: `{ "code": 400, "msg": "AFTER DEF CHANGE IS NOT ACTIVATED" }`

## 5. 异常处理 (Exception Handling)

| 异常场景            | 处理方式           | Message 显示内容                    |
| :------------------ | :----------------- | :---------------------------------- |
| **Serie-Chnr 为空** | 前端校验           | `Serie-Chnr 是必填项`               |
| **网络断开/超时**   | 捕获 Network Error | `网络连接失败，请检查网络设置`      |
| **记录已存在**      | API 返回 409       | `Record already exists`             |
| **记录不存在**      | API 返回 404       | `Record not found`                  |
| **未激活状态**      | API 返回 400       | `AFTER DEF CHANGE IS NOT ACTIVATED` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：使用 React State 管理 `serieChnr`, `desc`, `message`, `messageType`, `isLoading`。
2. **消息类型**：success=绿色, error=红色, warning=橙色。
3. **Desc 清空**：ADD 成功后清空 Desc 输入框。
4. **DELETE 确认**：点击 DELETE 前弹出 confirm 对话框。
