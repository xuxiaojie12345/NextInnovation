1. 背景 (Background)

本模块的核心功能是提供对 HDoc 系统用户的检索能力，支持通过用户 ID、用户名或权限类型进行查询。系统从 Saviynt 获取用户基本信息，并结合本地权限表查询其关联市场与角色权限。

  • 目标：为管理员提供灵活的用户检索工具，支持正向（ID查名）和反向（名查ID）查询，以及基于角色的筛选。
  • 安全性：
    • 仅允许授权用户访问此页面。
    • 所有通信使用 HTTPS 加密。
    • 用户信息从 Saviynt 获取，确保主数据一致性。
    • 权限筛选基于数据库校验，防止越权访问。
  • 用户体验：
    • 界面简洁，支持多种查询条件组合。
    • 提供清晰的表格展示查询结果。
    • 所有操作均有明确反馈提示。

3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 [Search] 按钮时执行。

3.1 处理流程

  1. 开始：用户点击 [Search] 按钮。
  2. 前置处理：获取 Userid, User, Market, Role (Radio value) 输入值。
  3. 空值校验 (Frontend Check)：
    • 检查是否至少有一个查询条件有效：
      • Userid 非空 OR
      • User 非空 OR
      • Role 不为 "Not set" (若 "Not set" 意为“无角色筛选”，则需结合其他条件；若 "Not set" 意为“查询无角色用户”，则本身即为条件。根据 Prompt 5.1.1，“若未选择任何 Radio 且 Userid 和 User 均为空”才报错。通常 Radio 必有其一选中，故主要校验 Text 字段是否为空且 Radio 是否为“无意义”状态。此处依 Prompt：若 Text 全空 且 用户意图不明确时报错。修正理解：Prompt 指出“若未选择任何 Radio...”，但 Radio 通常默认选中一个。假设逻辑为：如果 Text 为空 且 Radio 为 "Not set" (意指不筛选角色)，则相当于无条件查询所有用户，这可能被允许或被禁止。Prompt 5.1.1 说“请输入查询条件”，暗示不允许无条件全量查询。因此：若 Userid 空 AND User 空 AND Role == 'Not Set' (或无特定筛选意图)，则报错。)
      • 简化逻辑：若 Userid 为空 且 User 为空，且 Role 未指定特定过滤（如 Rule/Template），则提示“请输入查询条件”。
    • 若校验失败，设置 Message = 请输入查询条件，终止流程。
  4. API 调用 (Backend Check)：
    • 调用 GET /api/user/search，传入查询参数。
    • 后端负责整合 Saviynt 用户信息和本地权限数据。
  5. 结果处理：
    • 成功：
      • 渲染 Result Table，显示 Userid, User, Market。
      • 更新 Count 标签显示总记录数。
      • 清空 Message。
    • 失败 (404/Empty)：
      • 清空表格。
      • 设置 Message = No matching user found 或 用户不存在。
    • 错误 (500)：
      • 设置 Message = 查询失败，请稍后重试。

4. 接口定义 (API Specification)

4.1 User Search (综合查询)

注：为了简化前端逻辑，建议后端提供一个统一的搜索接口，内部处理 Saviynt 和本地 DB 的 join/logic。

  • 功能：执行用户查询，支持 ID、姓名、市场、角色筛选。
  • Method: GET
  • Endpoint: /api/user/search

Request Parameters (Query) 

?userid=a420064&user=Jenna%20Wang&market=-EU&role=Rule

(注：role 参数值可为 "Rule", "Template", 或 "None/All")

Response Success (200 OK) 

{
  "data": [
    {
      "userid": "a420064",
      "user": "Jenna Wang",
      "market": "-EU"
    },
    {
      "userid": "b531175",
      "user": "John Doe",
      "market": "DEU"
    }
  ],
  "totalCount": 2
}

Response Error (404 Not Found) 

{
  "error": "Not Found",
  "message": "No matching user found"
}

4.2 (Optional) Saviynt User Info (若后端不统一处理)

  • 功能：从 Saviynt 获取用户信息。
  • Method: GET
  • Endpoint: /api/saviynt/user

(此处省略详细定义，因建议采用 4.1 的统一接口)

6. 实现注意事项 (Implementation Notes)

  1. 状态管理：
    • 使用 React State 管理 searchParams (userid, user, market, role), searchResults (array), totalCount, message, isLoading。
  2. 交互细节：
    • Loading 状态：点击 Search 后，禁用按钮并显示 Loading 图标，直到 API 返回。
    • Radio 联动：确保三个 Radio Box 互斥。
    • 表格展示：若结果为空，表格显示“暂无数据”。
    • Message 样式：错误消息红色，警告消息橙色。
  3. 安全性：
    • API 请求必须通过 HTTPS 发送。
    • 后端需校验当前操作员是否有“用户查询”权限。
    • 对输入参数进行 sanitization，防止注入攻击。
  4. 性能优化：
    • 若查询结果集过大，建议后端支持分页，或前端限制最大显示条数（如 100 条）。
