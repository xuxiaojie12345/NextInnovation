## 1. 背景 (Background)

本模块的核心功能是对上传的 `.rtf` 格式模板文件进行内容校验，确保其符合系统规范。主要校验逻辑包括检查文件可访问性、提取 `$` 符号之间的变量文本（如 `$AXLE_CONF$`）、统计变量数量并验证是否存在有效变量。

- **目标**：在模板正式上传使用前，提前发现格式错误或变量缺失问题，降低生产环境风险。
- **安全性**：
  - 仅允许授权用户访问此页面。
  - 上传文件需严格校验为 `.rtf` 格式，防止恶意文件注入。
  - 文件读取与解析在后端执行，避免前端安全风险及性能瓶颈。
  - 所有通信使用 HTTPS 加密。
- **用户体验**：
  - 界面简洁，仅包含必要控件（上传、校验、下载）。
  - 错误信息明确（如“无法访问文件”、“内容不正确”），便于快速定位问题。
  - 校验成功后提供处理后的文件下载链接。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 **[Check]** 按钮时执行。

### 3.1 处理流程

1.  **开始**：用户点击 [Check] 按钮。
2.  **前置处理**：获取上传的文件对象。
3.  **空值/格式校验 (Frontend Check)**：
    - 若未选择文件：设置 `ErrorMessage` = `请选择要校验的模板文件`，**终止**流程。
    - 若文件扩展名不是 `.rtf`：设置 `ErrorMessage` = `仅支持 .rtf 文件`，**终止**流程。
4.  **API 调用 (Backend Check)**：
    - 调用 `POST /api/template/check` 接口，将文件流发送至后端。
    - 后端执行以下逻辑：
      - 尝试读取/解析文件。若失败，返回 `ERROR: Unable to access file!`。
      - 使用正则表达式提取所有 `$...$` 格式的变量。
      - 若未找到任何有效变量，返回 `ERROR: The file content is incorrect!`。
      - 若校验通过，生成处理后的文件（可能包含元数据或标准化格式），并返回下载路径或文件流。
5.  **结果处理**：
    - **成功**：
      - 隐藏 `ErrorMessage`。
      - 显示 `SuccessMessage` = `校验完成`。
      - 显示/激活 `Download Link`，指向生成的文件。
    - **失败**：
      - 隐藏 `SuccessMessage` 和 `Download Link`。
      - 显示 `ErrorMessage` 为后端返回的具体错误信息。

## 4. 接口定义 (API Specification)

### 4.1 Template Check (校验)

- **功能**：上传并校验 RTF 模板文件，提取变量，返回校验结果及处理后的文件。
- **Method**: `POST`
- **Endpoint**: `/api/template/check`

#### Request Body (Multipart/Form-Data)

- Key: `file`
- Value: Binary File Stream (.rtf)

#### Response Success (200 OK)

_方案 A：返回 JSON 包含下载 Token/URL_

```json
{
  "success": true,
  "message": "校验完成",
  "downloadUrl": "/api/template/download/checked_12345.rtf",
  "variableCount": 5,
  "variables": ["$AXLE_CONF$", "$WB_MM$"]
}
```

_方案 B：直接返回文件流 (Content-Disposition: attachment)_

- Content-Type: `application/octet-stream` 或 `application/rtf`
- Content-Disposition: `attachment; filename="checked_template.rtf"`
- Body: [File Stream]

_(注：根据 Prompt 描述“生成可下载的检查结果文件”，建议采用方案 A 以便前端先显示成功消息再点击下载，或方案 B 直接触发浏览器下载行为。此处以方案 A 为例，更符合“显示提示...并生成链接”的描述)_

#### Response Error (400 Bad Request)

```json
{
  "error": "Invalid Content",
  "message": "ERROR: The file content is incorrect!"
}
```

#### Response Error (500 Internal Server Error)

```json
{
  "error": "Processing Error",
  "message": "ERROR: Unable to access file!"
}
```

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `selectedFile`, `errorMessage`, `successMessage`, `downloadUrl`, `isLoading`。
    - `downloadUrl` 初始为 `null`，校验成功后更新。
2.  **文件处理**：
    - 使用 `<input type="file" accept=".rtf" />` 限制文件选择器。
    - 建议使用 `FormData` 对象封装文件并通过 `axios.post` 发送，设置 `headers: { 'Content-Type': 'multipart/form-data' }`。
3.  **UI 细节**：
    - **Loading 状态**：点击 Check 后，按钮应显示 Loading 图标并禁用，防止重复提交。
    - **消息展示**：`ErrorMessage` 使用红色 (`#ff4d4f`)，`SuccessMessage` 使用绿色 (`#52c41a`)。两者互斥显示。
    - **下载链接**：可以使用 `<a href={downloadUrl} download>` 标签，或者在成功回调中使用 `window.location.href = downloadUrl` 触发下载。
4.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 后端应对上传的文件进行严格的类型检查（MIME Type 和 Magic Number），而不仅仅是扩展名。
    - 生成的临时文件应在一定时间后自动清理，避免服务器存储膨胀。
