1. 背景 (Background)

本模块是 Engineering Database (EDB) 系统的入口，负责验证用户身份。用户通过输入 Outlook ID (UserID) 和密码 (Password)，经由前端校验后调用后端 ISAM 接口 (AuthenticationApi) 进行认证。

  • 目标：确保只有授权用户能进入系统，并提供清晰的错误反馈及备用登录指引。
  • 安全性：密码字段需掩码显示，所有敏感数据传输需通过 HTTPS 加密。
  • 用户体验：
    • 界面采用左右分栏设计：左侧展示品牌与支持信息，右侧聚焦登录操作。
    • 采用 Label 形式在页面内（Login 按钮上方）显示错误信息，避免频繁弹窗打断操作流。
    • 支持键盘快捷键（Enter 键触发登录）。

3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 [Login] 按钮或按下 Enter 键时执行。

3.1 处理流程

  1. 开始：用户点击 [Login] 按钮或按 Enter 键。
  2. 前置处理：获取 UserID 和 Password，执行 trim() 去除首尾空白。
  3. 空值校验 (Frontend Check)：
    • 若 UserID 为空 或 Password 为空：
      • 设置 Message = Username and password are required.
      • 终止流程，不调用 API。
  4. API 调用 (Backend Check)：
    • 若校验通过，调用 POST /api/Authenticationapi/login。
  5. 结果处理：
    • 认证成功 (200)：清空 Message，保存 Token，跳转至 /dashboard。
    • 认证失败 (401/403)：
      • 设置 Message = We didn't recognize the username or password you entered. Please try again.
      • 建议清空 Password 字段以便重新输入。

3.2 校验详细规格表

4. 接口定义 (API Specification)

4.1 AuthenticationApi

  • 功能：验证用户凭证并返回认证结果。
  • Method: POST
  • Endpoint: /api/authenticationapi/login

Request Body 

{
  "userId": "string (Max 10, Alphanumeric)",
  "password": "string (Max 32, Alphanumeric + Symbols)"
}

Response Success (200 OK) 

{
  "success": true,
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": "A451340",
    "name": "张三",
    "role": "Engineer"
  }
}

Response Error (401 Unauthorized / 403 Forbidden) 

{
  "error": "Unauthorized",
  "message": "Invalid credentials"
}

6. 实现注意事项 (Implementation Notes)

  1. 状态管理：
    • 使用 React State 管理 userID, password, message, isLoading。
    • Message Label 默认隐藏（内容为空时不占位或高度为0），出错时显示红色文字。
  2. 安全性：
    • 严禁在前端日志中打印明文密码。
    • API 请求必须通过 HTTPS 发送。
  3. UI 细节：
    • [Login]按钮在 isLoading 期间应设为 disabled，防止重复提交。
    • 左侧品牌区域背景色需与右侧登录区域形成对比，确保视觉清晰。
