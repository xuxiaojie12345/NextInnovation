# UD01 与 UD02 页面串联说明

## 📋 功能概述

实现登录页面（UD01）与主菜单页面（UD02）的无缝衔接，用户登录成功后自动跳转至主菜单。

## 🔗 页面流转

```
UD01 (登录页) → 登录成功 → UD02 (主菜单页)
```

## 📤 参数传递

### 传递方式：localStorage

UD01 登录成功后，将以下信息保存到 `localStorage`：

| 参数名 | 值 | 说明 |
|--------|-----|------|
| `user_info` | JSON 字符串 | 用户信息对象，包含 userId、name 等字段 |
| `auth_token` | String | 认证令牌（当前使用 userId 作为 token） |

### 代码实现

**UD01.tsx - 登录成功处理：**
```typescript
if (response.data && response.data.code === 200) {
  // 保存用户信息到 localStorage（UD02 需要读取）
  localStorage.setItem("user_info", JSON.stringify(response.data.user));
  localStorage.setItem("auth_token", trimmedUserId); // 使用 userId 作为 token
  
  // 跳转到 UD02 主菜单页面
  navigate("/UD02");
}
```

**UD02.tsx - 读取用户信息：**
```typescript
const getCurrentUser = (): User | null => {
  const userStr = localStorage.getItem("user_info");
  if (!userStr) return null;
  
  try {
    const userInfo = JSON.parse(userStr);
    const token = localStorage.getItem("auth_token");
    
    return {
      userId: userInfo.userId || "",
      name: userInfo.name || "",
      token: token || "",
    };
  } catch (error) {
    console.error("解析用户信息失败:", error);
    return null;
  }
};
```

## 🔄 会话验证流程

### UD02 页面加载时：

1. **读取 localStorage** 中的用户信息
2. **验证 Token** 是否存在且有效
3. **验证通过** → 显示主菜单
4. **验证失败** → 重定向回登录页 `/login`

```typescript
useEffect(() => {
  const currentUser = getCurrentUser();

  if (
    !currentUser ||
    !currentUser.token ||
    isTokenExpired(currentUser.token)
  ) {
    // 会话过期或无用户，重定向至登录页
    navigate("/login", { replace: true });
    return;
  }

  setUser(currentUser);
  setIsLoading(false);
}, [navigate]);
```

## ✅ 测试步骤

1. **启动前端服务**
   ```bash
   cd react-ud
   npm start
   ```

2. **访问登录页**
   - 浏览器打开：`http://localhost:3000/UD01`

3. **输入登录信息**

   - Password: 任意密码

4. **点击 Login 按钮**
   - 登录成功后自动跳转到 `http://localhost:3000/UD02`
   - 显示主菜单页面

5. **验证数据传递**
   - 打开浏览器开发者工具（F12）
   - 查看 Application → Local Storage
   - 确认存在 `user_info` 和 `auth_token`

## ⚠️ 注意事项

### 开发环境
- 当前 UD02 的会话验证已临时注释，方便直接访问测试
- 生产环境需要恢复会话验证代码

### 安全建议
1. **Token 管理**：当前使用 userId 作为 token，生产环境应使用 JWT 或其他安全令牌
2. **HTTPS**：所有通信必须使用 HTTPS 加密
3. **Token 过期**：实现真实的 Token 过期验证逻辑
4. **敏感信息**：不要在前端存储密码等敏感信息

### 后端接口要求
确保后端登录接口返回的数据格式符合预期：
```json
{
  "code": 200,
  "msg": "登录成功",
  "user": {
    "userId": "A451340",
    "name": "张三",
    "password": "" // 不应返回密码
  }
}
```
