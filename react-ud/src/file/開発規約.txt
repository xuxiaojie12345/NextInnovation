开发规范

1.代码内注释全部使用中文，禁止中日文混用。
2.手动删除内部设计文档、测试规格书中多余的描述内容。
3.禁止使用特殊字符。
4.函数名、方法名统一采用小驼峰命名法。
5.官方 Hook 必须通过 import 方式引入使用。
6.组件使用 React.FC 或普通函数形式定义。
7.必须在代码顶层调用 Hooks。
8.代码中专业词汇使用日语片假名（例：バリデーション、コンポーネント）。
9.组件名采用大驼峰命名法（PascalCase）。
10.文件名采用短横线命名法（kebab-case）。
11.各类文档使用日文编写。
12.页面展示的错误提示使用中文。
13.组件 Props 必须使用 TypeScript interface 定义类型。
14.UI 组件库统一使用 Ant Design。
15.数据校验统一使用 Zod 库。
16.JavaScript / React 相关规范
17.列表渲染时，JSX 元素必须设置 key 属性。
18.合理使用 useMemo、useCallback，避免组件不必要的重渲染。
19.组件做到职责拆分，控制单个组件复杂度。
20.事件处理函数命名统一以 on 为前缀（示例：onClickButton）。
21.传递 Props 时优先使用解构赋值语法。


样式规范

22.CSS 类名采用 BEM 命名规范，或使用 Tailwind CSS 原子化样式写法。
23.CSS 类名、样式名称使用日文命名。
24.单个组件的样式，单独拆分 CSS 文件管理，或采用 CSS-in-JS 方案。


测试规范

25.后端单元测试使用 JUnit 5。
26.JUnit 测试类命名规则：[原有类名]Test.java。
27.测试方法必须添加 @Test 注解。
28.测试用例按照 AAA 模式（准备 - 执行 - 断言） 编写。
29.所有测试方法需支持独立运行。
30.测试数据初始化，可使用 @TestInstance(Lifecycle.PER_CLASS)、@BeforeEach、@AfterEach 注解。
31.模拟对象（Mock）使用 Mockito 框架实现。
32.断言校验使用 JUnit 自带 Assert 类或 Hamcrest 匹配器。


Git 工作流规范

32.Git 提交说明使用日文编写。
33.分支命名规则：feature/功能名、fix/修复内容 等格式。
34.提交合并请求（PR）时，必须指定评审人。
35.提交粒度要细化，按单个功能拆分提交。
36.国际化规范
37.如需做多语言适配，统一使用 i18n 类国际化库。
38.页面展示文本全部抽离，由翻译文件统一管理。


安全规范

39.必须对用户输入内容做校验，防范 XSS 攻击。
40.接口通信统一使用 HTTPS 协议。
41.会话管理、身份认证环节需落实完善的安全防护措施。


性能规范

42.大数据量渲染场景，使用虚拟滚动等方案做性能优化。
43.图片等静态资源需实现懒加载。
44.及时清理事件监听器，避免内存泄漏。
