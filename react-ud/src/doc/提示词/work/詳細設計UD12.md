## 1. 背景 (Background)

本模块提供 HDoc Template 的上传和删除功能。用户可以上传 Template 文件到指定 Market 文件夹，也可以从指定 Market 文件夹删除 Template 文件。同时提供链接跳转到 HDoc Template Check 页面进行模板校验。

- **目标**：为 Template Admin 权限用户提供直观的模板管理界面，支持文件的上传、删除和校验功能。
- **安全性**：文件格式校验（仅支持 rtf 文件）、文件上传大小限制、防止路径遍历攻击、删除操作二次确认。
- **用户体验**：直观的文件上传界面、清晰的 Market 和 Template 选择、明确的操作反馈消息、提供模板校验链接。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 **[Upload file]** 或 **[Delete]** 按钮时执行。

### 3.1 处理流程

#### 3.1.1 页面初始化

1. **开始**：页面加载。
2. **API调用**：
   - 呼出时点：画面加载时
   - 呼出方法：POST请求
   - 参数：无
   - 调用 `UD12SelectMarket` 获取Market列表。
3. **处理**：
   - Upload区域的Market下拉列表：加载所有Market选项。
   - Delete区域的Market下拉列表加载所有Market选项。
   - Delete区域的Templates下拉列表动态加载Market文件夹中的文件名。
4. **结果处理**：
   - **成功**：两个Market下拉列表均显示所有Market选项。
   - **失败**：显示错误消息"System error. Please contact administrator."。

#### 3.1.2 点击 [Upload file] 按钮

1. **开始**：用户点击 [Upload file] 按钮。
2. **前置处理**：获取 Template File 和 Market 的值。
3. **条件选择校验 (Frontend Check)**：
   - 若 `Template File` 未选择文件：
     - 设置 `Message` = `NO FILE UPLOADED`
     - **终止**流程，不调用 API。
   - 若 `Market` 未选择：
     - 设置 `Message` = `NO Market UPLOADED`
     - **终止**流程，不调用 API。
4. **API 调用**：
   - 呼出时点：用户点击Upload file按钮后
   - 呼出方法：POST请求（Multipart Form Data）
   - 参数：画面のTemplate File、画面のMarket
   - 调用 `UD12UploadFlie`
5. **结果处理**：
   - **上传成功**：显示成功消息 `TEMPLATE XXX WAS SUCESSFULLY UPLOADED TO MARKET JPN`
   - **上传失败**：显示错误消息 `File upload failed. Please try again.`

#### 3.1.3 点击 [Delete] 按钮

1. **开始**：用户选择 Market 和 Templates，点击 [Delete] 按钮。
2. **前置处理**：获取 Market 和 Templates 的值。
3. **条件选择校验 (Frontend Check)**：
   - 若 `Template File` 未选择文件：
     - 设置 `Message` = `NO FILE UPLOADED`
     - **终止**流程，不调用 API。
   - 若 `Market` 未选择：
     - 设置 `Message` = `NO Market UPLOADED`
     - **终止**流程，不调用 API。
4. **删除确认 (Confirmation Dialog)**：
   - 显示确认对话框：`Do you really want to delete template?`
   - 若用户取消：**终止**流程，不执行删除。
   - 若用户确认：继续执行删除操作。
5. **API 调用**：
   - 呼出时点：用户确认删除后
   - 呼出方法：POST请求
   - 参数：画面のMarket、画面のTemplates
   - 调用 `UD12DeleteFlie`
5. **结果处理**：
   - **删除成功**：显示成功消息 `TEMPLATE XXX WAS SUCESSFULLY DELETE FROM MARKET JPN`
   - **删除失败**：显示错误消息 `File deletion failed. Please try again.`

#### 3.1.4 点击链接 'Check Template (Only for rtf files)'

1. **开始**：用户点击链接 'Check Template (Only for rtf files)'。
2. **页面跳转**：跳转到「HDoc Template Check」页面。

### 3.2 校验详细规格表

| No. |   检查时机   |     检查对象      |                检查条件                |                          错误消息 (Message Content)                           |                 动作                 |

## 4. 接口定义 (API Specification)

### 4.1 UD12SelectMarket

- **功能**：获取Market列表（初期化时加载）。
- **所属api名**: `UD12UploadDeletetemplatApi`
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/template/selectMarket`

#### Request Body

```json
{}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "查询成功",
  "data": {
    "marketList": ["MARKET001", "MARKET002"]
  }
}
```

#### Response Error (500 Internal Server Error)

```json
{
  "code": 500,
  "message": "System error. Please contact administrator.",
  "data": null
}
```

### 4.2 UD12UploadFlie

- **功能**：上传 Template 文件到指定 Market 文件夹
- **所属api名**: `UD12UploadDeletetemplatApi`
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/template/upload`

#### Request Body (Multipart Form Data)

```
file: [binary]
market: "string"
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "TEMPLATE XXX WAS SUCESSFULLY UPLOADED TO MARKET JPN",
  "data": null
}
```

#### Response Error (400 Bad Request)

```json
{
  "code": 400,
  "message": "NO FILE UPLOADED",
  "data": null
}
```

### 4.3 UD12DeleteFlie

- **功能**：从指定 Market 文件夹删除 Template 文件
- **所属api名**: `UD12UploadDeletetemplatApi`
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/template/delete`

#### Request Body

```json
{
  "market": "string",
  "template": "string"
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "TEMPLATE XXX WAS SUCESSFULLY DELETE FROM MARKET JPN",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景                 | 处理方式           | Message 显示内容                               |
| :----------------------- | :----------------- | :--------------------------------------------- |
| **未选择文件就点击 Upload** | 前端校验拦截       | `NO FILE UPLOADED`                             |
| **文件上传失败**         | API 返回错误       | `File upload failed. Please try again.`        |
| **删除确认取消**         | 用户取消操作       | 不执行删除                                     |
| **文件删除失败**         | API 返回错误       | `File deletion failed. Please try again.`      |
| **网络断开/超时**        | 捕获 Network Error | `Network error. Please check your connection.` |
| **服务器内部错误 (500)** | 捕获 Server Error  | `System error. Please contact administrator.`  |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理 `selectedFile`, `uploadMarket`, `deleteMarket`, `selectedTemplate`, `message`, `isLoading`。
   - `Message` Label 默认隐藏（内容为空时不占位或高度为0）。
2. **安全性**：
   - 严禁在前端日志中打印文件内容或敏感路径信息。
   - API 请求必须通过 HTTPS 发送。
   - 后端需验证文件扩展名是否为 `.rtf`。
   - 防止路径遍历攻击：对传入的 market 和 template 参数进行严格校验，禁止包含 `../` 等路径穿越字符。
3. **UI 细节**：
   - 按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
   - `Message` 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用，成功消息可使用绿色 (`#52c41a`)。
   - Market 下拉列表变化时，若为 Delete 区域，需自动加载该 Market 下的 Templates 列表。
4. **文件校验**：
   - 前端可选校验文件大小（如限制为 10MB）。
   - 前端可选校验文件扩展名是否为 `.rtf`，提供即时反馈。
5. **删除确认**：
   - 使用模态对话框或浏览器原生 `confirm()` 实现删除确认。
   - 确认对话框应清晰显示将要删除的 Template 名称。
