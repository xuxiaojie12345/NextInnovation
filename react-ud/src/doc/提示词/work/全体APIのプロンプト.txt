3. API功能概述
    3.1.【AuthenticationApi】：用户登录账号密码校验、身份认证，签发登录 Token 并留存登录日志
    3.2.【UD03SelectHdocdocumentlistApi】：全量查询系统文档类型基础数据，对外返回文档编码与描述列表
    3.3.【UD04SelectGeneratedocumentApi】：根据底盘系列、底盘编号查询整车基础数据，支撑文档生成页面数据渲染
    3.4.【UD05ModifyDocumentApi】：分为两个能力，①根据底盘系列、编号查询变量修改详情；②对指定车型变量进行数值更新，维护文档变量配置数据
    3.5.【UD06SaveModificationsApi】：依据底盘系列、底盘号查询 ADCA 配置变量信息，获取文档版本与变量配置数据
    3.6.【UD07VehicleSpecificationApi】：根据车型系列、底盘号分两次查询，整合车型基础信息 + KOLA 选配配置，实现车型详情查询
    3.7.【UD08HomologationVariablesApi】： homolog 认证自定义规则管理，包含产品分类 / 市场字典下拉查询、变量重复性校验、自定义规则新增 / 修改 / 删除 / 主键查重全生命周期维护
    3.8.【UD09DeleteHdocuserdefinedrulesApi】：自定义规则多条件模糊检索、选中规则批量删除，管理 HDOC_USER_DEFINED_RULES 业务数据
    3.9.【UD10HdocvariablesApi】：系统通用变量字典维护，实现业务变量的新增、编辑、删除操作
    3.10.【UD11HdocvariablesApi】：多条件组合动态检索系统变量信息，按变量名、类型、操作人等筛选变量列表
    3.11.【UD12UploadDeleteTemplateApi】：市场字典查询、业务模板文件本地上传、已上传模板文件物理删除，管理各市场文档模板资源
    3.12.【UD14SearchresultistApi】：市场基础数据下拉查询、按市场 + 文件名条件检索自定义规则关联变量列表
    3.13.【UD15SelecthdocsenddatavinplateApi】：VIN 单据下发记录管理，支持单据详情查看、单据状态重置重生成 / 标记完成、单据类型切换（基础 / 高级信息）
    3.14.【UD16ADChangeApi】：ADCA 变更记录管理，按车型参数统计变更条数、新增单条变更记录、全量批量置为非活性状态（ACT='N'）
    3.15.【UD17HDocUserAdministrationApi】：用户权限管理，查询用户功能 + 市场权限、全量替换用户权限、清空用户已有权限
    3.16.【UD18HDocUserDocAdministrationApi】：用户文档权限管理，①删除用户文档权限；②新增用户文档权限；③统计用户绑定功能权限数量；④查询用户已配置文档类型清单
    3.17.【UD19SelectMarketMasterApi】：全量市场数据下拉、多字段（用户 ID / 用户名 / 市场类型）动态筛选用户权限信息
    3.18.【UD20GetDocumentListApi】：查询全量文档配置信息，返回文档类型、创建人、创建时间等文档基础列表
    3.19.【UD20MarketDocumentSettingsApi】：更新市场文档设置信息，根据文档类型、注册用户、注册时间更新HDOC_DOCUMENT_LIST表中的记录


4. 处理流程
    3.1对应的api：【AuthenticationApi】
        4.1 客户端通过POST请求访问接口 /api/v1/hdoc/login，将用户名、密码等请求参数，以JSON格式发送至后端服务。

        4.2 后端【LoginController】接收前端请求，通过【LoginRequest】实体对象封装并校验请求参数，完成请求入口层的参数接收与初步格式验证。

        4.3 控制器层调用【LoginService】接口中的 login() 方法，将校验后的请求对象传递至业务逻辑层处理。

        4.4 【LoginServiceImpl】业务实现层执行核心登录逻辑：
            • 对请求参数进行非空、长度、格式等合法性校验
            • 对密码格式、账号状态进行前置校验
            • 校验不通过则直接返回参数异常响应

        4.5 业务层通过【UserMapper】数据访问层，根据用户名查询数据库中的用户信息，获取用户实体对象。

        4.6 登录核心验证逻辑：
            • 判断用户是否存在，不存在则返回“账号不存在”
            • 比对前端传递密码与数据库加密密码是否一致
            • 密码错误则返回“密码不正确”
    
        4.7 验证全部通过后：
            • 生成Token（包含用户ID、用户名等）
            • 可记录登录日志（登录时间、IP、设备信息）
            • 构建登录成功响应体，包含Token、用户基础信息

        4.8 封装【LoginResponse】响应对象，统一返回标准格式：
        {
            "code": 200,
            "msg": "登录成功",
            "data": {
                "token": "xxxx",
                "userId": "xxx",
                "username": "xxx"
            }
        }

6. 开发指导原则

6.1 代码编写规范
    - 遵循MVC三层架构模式
    - 使用Lombok减少样板代码
    - 保持Controller、Service、Mapper层职责分离
    - 所有INSERT操作必须设置REGISTER_DATETIME、REGISTER_USER、REGISTER_PROCESS、UPDATE_DATETIME、UPDATE_USER、UPDATE_PROCESS字段
    - 所有UPDATE操作必须更新UPDATE_DATETIME、UPDATE_USER、UPDATE_PROCESS字段

6.2 错误处理
    - 对输入参数进行验证
    - 合理捕获和处理异常
    - 返回有意义的错误信息

6.3 时间字段处理规范
    - REGISTER_DATETIME: 记录数据首次创建的时间，使用NOW()函数
    - REGISTER_USER: 记录创建数据的用户ID，从当前登录用户获取
    - REGISTER_PROCESS: 记录创建数据的程序/接口名称，使用API编号如'UD08Add'
    - UPDATE_DATETIME: 记录数据最后更新的时间，使用NOW()函数
    - UPDATE_USER: 记录最后更新数据的用户ID，从当前登录用户获取
    - UPDATE_PROCESS: 记录最后更新数据的程序/接口名称，使用API编号如'UD08Update'
