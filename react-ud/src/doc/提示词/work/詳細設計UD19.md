## 1. 背景 (Background)

本模块提供用户查询功能，支持通过多种条件查询HDoc系统中的用户信息。用户可以通过输入UserID、User、Market等条件进行精确或模糊查询，并可根据不同权限类型(Rule Admin、Template Admin)筛选用户，最终显示用户的基本信息及权限情况。

- **目标**：提供灵活的用户查询功能，便于管理员进行用户管理。
- **面向用户**：HDoc系统管理员和具有用户管理权限的操作员
- **用户体验**：提供多种查询方式，提高查询效率，清晰的结果展示界面便于识别用户信息。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 **[Search]** 按钮时同步或异步执行。

### 3.1 处理流程

#### 3.1.1 页面初始化

1. **开始**：页面加载。
2. **API调用**：
   - 呼出时点：画面加载时
   - 呼出方法：POST请求
   - 参数：无
   - 调用 `UD19SelectMarketMaster` 获取Market列表。
3. **处理**：
   - 显示所有Market供用户选择。
   - 默认不选择Market。
4. **结果处理**：
   - **成功**：Market下拉列表显示所有Market选项。
   - **失败**：显示错误消息"System error. Please contact administrator."。

#### 3.1.2 点击 [Search] 按钮

1. **开始**：用户点击 [Search] 按钮。
2. **前置处理**：准备查询参数，包括Userid、User、Market以及权限筛选选项。
3. **API 调用**：
   - 呼出时点：用户点击Search按钮后
   - 调用 `UD19SearchHdoc`（Endpoint: `/api/v1/hdoc/ud19/searchHdoc`）获取用户信息。
4. **结果处理**：
   - **查询成功**：在DataTable中显示查询到的用户列表，更新COUNT标签显示记录总数。
   - **查询失败**：显示相应的错误消息。

### 3.2 校验详细规格表

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 (Message Content) | 动作 |
| :-: | :--- | :--- | :--- | :--- | :--- |
| 1 | API Response | 用户权限 | 当前用户无查询权限 | 您没有权限执行此操作 | 显示 Message，阻止查询操作 |
| 2 | API Response | 查询结果 | 查询结果为空数组 | 没有找到匹配的用户 | 显示提示信息 |

## 4. 接口定义 (API Specification)
### 4.1 UD19SelectMarketMaster

- **功能**：获取Market列表
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/ud19/selectMarketMaster`

#### Request Body

```json
{}
```

#### Response Success (200 OK)

```json
{
    "code": 200,
    "message": "查询成功",
    "data": {
        "marketList": [
            {
                "market": "MARKET-A",
                "description": "A市场说明文本"
            },
            {
                "market": "MARKET-B",
                "description": "B市场说明文本"
            }
      ]
    }
}
```

#### Response Error (400 Bad Request)

```json
{
  "code": 400,
  "data": null,
  "message": "Invalid request parameters"
}
```

### 4.2 UD19SearchHdoc

- **功能**：获取用户信息
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/ud19/searchHdoc`

#### Request Body

```json
{
  "userid": "string (Max 10, Alphanumeric)",
  "user": "string",
  "check": "string",
  "market": "string"
}
```

#### Response Success (200 OK)

```json
{
    "code": 200,
    "message": "查询成功",
    "data": {
        "hdocList": [
            {
                "userid": "U001",
                "username": "测试用户01",
                "market": "MARKET01"
            },
            {
                "userid": "U002",
                "username": "测试用户02",
                "market": "MARKET02"
            }
        ]
    }
}
```

#### Response Error (400 Bad Request)

```json
{
  "code": 400,
  "data": null,
  "message": "Invalid request parameters"
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :--- | :--- | :--- |
| **网络断开/超时** | 捕获 Network Error | 网络连接失败，请稍后重试 |
| **服务器内部错误 (500)** | 捕获 Server Error | 系统错误，请联系管理员 |
| **用户无查询权限** | 捕获权限错误 | 您没有权限执行此操作 |
| **API连接失败** | 捕获连接错误 | 系统暂时不可用，请稍后重试 |
| **查询结果为空** | 显示提示信息 | 没有找到匹配的用户 |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理 `userid`, `username`, `market`, `permissionFilter`, `searchResults`, `recordCount` 等状态。
   - 实现单选按钮组的互斥选择逻辑（Not set、Rule、Template）。
2. **安全性**：
   - 验证用户是否有查询权限，确保只有授权用户可以使用此功能。
   - API 请求必须通过 HTTPS 发送。
3. **UI 细节**：
   - [Search] 按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
   - DataTable 应支持分页和排序功能以提升用户体验。
   - 权限筛选的单选按钮应正确实现互斥选择逻辑。
