## 1. 背景 (Background)

本模块用于显示用户的详细信息，为系统提供用户信息查看功能。用户可以从其他模块（如MarketDocumentSettingsList）通过点击User链接跳转至此画面，查看指定用户的完整信息。

- **目标**：提供清晰、完整的用户信息展示界面，便于用户了解相关人员的详细资料。
- **安全性**：仅显示经过授权的用户信息，确保数据隐私和安全。
- **用户体验**：界面简洁明了，信息展示完整，操作按钮直观易用。

面向的用户群体:
- HDoc系统管理员
- 具有用户信息查看权限的普通用户

用户体验方面的考虑:
- 信息展示区域布局合理，便于阅读
- 提供Clear按钮快速重置界面
- 提供Back按钮方便返回来源页面
- 错误信息清晰明确，便于用户理解问题所在

安全性或特殊要求:
- 需要验证当前用户是否有查看目标用户信息的权限
- 敏感信息（如邮箱地址）需按照公司安全策略进行适当处理
- 所有数据传输必须通过HTTPS加密

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户执行相应操作时同步执行。

### 3.1 处理流程

#### EDB User View画面加载流程

1. **开始**：进入EDB User View画面。
2. **前置处理**：从画面参数获取userid。
3. **API调用**：
   - 呼出时点：画面加载时
   - 呼出方法：GET请求
   - 参数：画面のuserid
   - 调用`Authentication2Api`（Endpoint: `/api/v1/hdoc/userinfo`）从Saviynt表获取用户信息。
   - **注意**：此Endpoint在现有后端代码中不存在，实际使用时需确认。
4. **结果处理**：
   - **成功**：显示用户详细信息（Userid、Responsible、User Position、E-mail）。
   - **失败**：显示相应错误消息并保持在当前页面。

#### Clear功能流程

1. **开始**：用户点击 [Clear] 按钮。
2. **处理**：清除所有输入字段的内容。
3. **结果**：重置界面到初始状态。

#### Back功能流程

1. **开始**：用户点击 [Back] 按钮。
2. **处理**：返回到调用此画面的前一个画面。
3. **结果**：保持前画面的状态，完成画面跳转。

## 4. 接口定义 (API Specification)

### 4.1 Authentication2Api

- **功能**：从HDOC_USER_INFOR表获取用户认证信息。
- **Method**: `GET`
- **Endpoint**: `/api/v1/hdoc/userinfo`

#### Request Parameters

```json
{
  "userid": "string (用户ID)"
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "Userid": "用户ID",
    "Responsible": "负责人",
    "UserPosition": "用户职位",
    "Email": "邮箱地址"
  }
}
```

#### Response Error (400 Bad Request)

```json
{
  "code": 400,
  "message": "用户ID不能为空",
  "data": null
}
```

#### Response Error (403 Forbidden)

```json
{
  "code": 403,
  "message": "您没有权限查看此用户信息",
  "data": null
}
```

#### Response Error (500 Internal Server Error)

```json
{
  "code": 500,
  "message": "系统暂时不可用，请稍后重试",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message显示内容 |
| :----------------------- | :----------------- | :--------------------------------------------- |
| **无法获取用户信息** | 显示错误消息，保持当前页面 | `无法获取用户信息` |
| **API调用失败** | 显示错误消息，保持当前页面 | `[具体错误信息]` |
| **用户无查看权限** | 拒绝访问，返回错误信息 | `您没有权限查看此用户信息` |
| **网络断开/超时** | 捕获 Network Error | `网络连接失败，请稍后重试` |
| **服务器内部错误** | 捕获 Server Error | `系统错误，请联系管理员` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理用户信息、Message等状态。
   - Message Label 默认隐藏（内容为空时不占位或高度为0）。
2. **安全性**：
   - 在页面加载时验证用户权限，确保只有授权用户能访问。
   - API 请求必须通过 HTTPS 发送。
   - 邮箱地址等敏感信息应按照公司安全策略进行适当处理。
3. **UI 细节**：
   - 所有TextField控件设置为只读状态（readOnly=true）。
   - Clear按钮在界面加载完成后始终可用。
   - Back按钮应记录来源页面，确保正确返回。
   - Message 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
4. **数据源**：
   - 用户信息来源于Saviynt表或HDOC_USER_INFOR表。
   - 确保数据字段映射正确：Userid、Responsible、User Position、E-mail。
