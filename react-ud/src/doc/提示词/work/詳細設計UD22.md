## 1. 背景 (Background)

本模块用于显示HDoc系统中可用的文档类型列表，包括文档类型的键值和描述，为用户提供清晰的文档类型参考。

- **目标**：提供完整的文档类型列表，便于用户识别和选择合适的文档类型，支持系统其他模块的文档类型选择功能。
- **安全性**：需验证用户权限，确保只能访问授权的文档类型信息，保护系统配置数据。
- **用户体验**：提供清晰的文档类型列表展示，便于用户识别和选择合适的文档类型，界面简洁直观。

面向的用户群体:
- 需要了解文档类型的业务人员
- HDoc系统管理员
- 具有文档类型查看权限的用户

用户体验方面的考虑:
- 文档类型按字母顺序或逻辑顺序排列，便于查找
- 信息展示区域布局合理，字段对齐清晰
- 加载过程显示进度指示器，提升用户体验
- 错误信息清晰明确，便于用户理解问题所在

安全性或特殊要求:
- 需要验证当前用户是否有查看文档类型信息的权限
- 敏感文档类型信息需按照公司安全策略进行适当处理
- 所有数据传输必须通过HTTPS加密

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户进入画面时自动执行。

### 3.1 处理流程

#### Document Types画面加载流程

1. **开始**：用户进入Document Types画面。
2. **前置处理**：准备调用API获取HDOC_DOCUMENT_LIST表数据。
3. **API调用**：
   - 呼出时点：画面加载时
   - 呼出方法：POST请求
   - 参数：无
   - 调用`UD20SelectHdocDocumentList` 获取HDOC_DOCUMENT_LIST表数据。
4. **结果处理**：
   - **成功**：正常显示文档类型列表信息（Key、Description）。
   - **失败**：显示相应错误消息并保持在当前页面。

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 (Message Content) | 动作 |
| :-: | :----------: | :---------------: | :------------------------------------: | :---------------------------------------------------------------------------: | :----------------------------------: |
| 1 | 进入画面时 | 文档类型数据获取 | 无法获取文档类型数据 | `无法获取文档类型信息` | 显示错误消息，保持当前页面 |

## 4. 接口定义 (API Specification)

### 4.1 UD20SelectHdocDocumentList

- **功能**：获取市场文档设置列表信息。
- **所属Api**：UD20GetDocumentListApi 
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/ud20/getDocumentList`

#### Request

```json
{
  "doctype": "",
  "registerUser": "",
  "registerDatetime": ""
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "documents": [
      {
        "doctype": "string",
        "description": "string",
        "businessUnit": "BU",
        "registerUser": "string",
        "registerDatetime": "datetime"
      }
    ]
  }
}
```

#### Response Error (400 Bad Request)

```json
{
  "code": 400,
  "message": "error message",
  "data": null
}
```

#### Response Error (500 Internal Server Error)

```json
{
  "code": 500,
  "message": "系统暂时不可用，请稍后重试",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message显示内容 |
| :----------------------- | :----------------- | :--------------------------------------------- |
| **无法获取文档类型数据** | 显示错误消息，保持当前页面 | `无法获取文档类型信息` |
| **API调用失败** | 显示错误消息，保持当前页面 | `系统错误，请稍后重试` |
| **用户无查看权限** | 拒绝访问，返回错误信息 | `您没有权限查看文档类型信息` |

| **服务器内部错误** | 捕获 Server Error | `系统错误，请联系管理员` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理文档类型数据列表、Message等状态。
   - Message Label 默认隐藏（内容为空时不占位或高度为0）。
   - 加载状态使用`isLoading`标志控制。
2. **安全性**：
   - 在页面加载时验证用户权限，确保只有授权用户能访问。
   - API 请求必须通过 HTTPS 发送。
   - 敏感文档类型信息应按照公司安全策略进行适当处理。
3. **UI 细节**：
   - 所有TextField控件设置为只读状态（readOnly=true）。
   - 文档类型列表建议使用表格形式展示，便于阅读和对比。
   - 加载过程中显示Loading指示器，提升用户体验。
   - Message 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
4. **数据源**：
   - 文档类型信息来源于HDOC_DOCUMENT_LIST表。
   - 确保数据字段映射正确：Key对应DOCTYPE，Description对应Description字段。
   - HDOC_DOCUMENT_LIST表主键为DOCTYPE，包含字段：DOCTYPE, DESCRIPTION, REGISTER_DATETIME等。
5. **性能优化**：
   - 考虑文档类型数据量较大时的分页或虚拟滚动实现。
   - 数据缓存策略：文档类型数据相对静态，可考虑客户端缓存减少API调用。
6. **系统集成**：
   - Document Types模块是MarketDocumentSettingsList → DocumentTypes → MarketsinHDoc → EDBUserView数据流的重要组成部分。
   - 该模块的数据可能被其他模块引用，确保数据的一致性和准确性。
