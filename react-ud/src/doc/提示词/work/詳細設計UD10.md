## 1. 背景 (Background)

本模块用于管理Homologation文档系统中现有的变量（Variables），提供变量的查询、新增、更新、删除和导出功能。

- **目标**：允许系统管理员和业务用户查看和维护系统中的VDA标准变量和用户自定义变量。
- **核心功能**：支持按条件搜索变量、新增变量记录、更新现有变量、删除变量以及导出CSV文件。
- **用户体验**：提供清晰的输入校验和错误提示，操作按钮布局合理，支持快速清空搜索条件。
- **安全性**：所有输入字段仅允许半角英数字和记号，防止注入攻击；变量操作前进行存在性校验，避免重复添加或删除不存在的记录。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击相应按钮时同步或异步执行。

### 3.1 处理流程

#### 3.1.1 初期表示

1. **开始**：用户进入Existing HDoc Variables画面。
2. **画面状态**：
   - Type下拉列表显示固定选项：VDA、User Defined，默认未选择。
   - 其他输入字段（Variable、Description、Created by user、Date）均为空。
   - 所有按钮均处于激活状态，Message标签默认隐藏。
3. **结果**：页面处于等待用户操作状态。

#### 3.1.2 [Search] 按钮压下

1. **开始**：用户点击 [Search] 按钮。
2. **前置处理**：获取所有输入字段的值（Variable, Type, Description, Created by user, Date）。
3. **空值校验 (Frontend Check)**：
   - 若所有搜索条件均为空：
     - 设置 `Message` = `请输入至少一个搜索条件`
     - **终止**流程。
4. 携带检索条件 跳转到 ExistingHdocVariablesResultList 画面

#### 3.1.3 [Clear] 按钮压下

1. **开始**：用户点击 [Clear] 按钮。
2. **处理**：清空所有输入字段

#### 3.1.4 [Back] 按钮压下

1. **开始**：用户点击 [Back] 按钮。
2. **处理**：系统返回到调用此页面的前一个页面。

#### 3.1.5 [Add] 按钮压下

1. **开始**：用户点击 [Add] 按钮。
2. **前置处理**：获取 Variable、Type、Description 等字段值。
3. **空值校验 (Frontend Check)**：
   - 若 `Variable` 为空：
     - 设置 `Message` = `Variable为必填项`
     - **终止**流程。
4. **Variable存在性校验**：
   - 调用 `UD08SelectHdocvariables` 检查Variable是否存在于HDOC_VARIABLES表中
   - 若存在，显示错误消息 `Variant already exists. Please enter the correct content`，**终止**流程
5. **API 调用**：
   - 呼出时点：用户点击Add按钮后
   - 呼出方法：POST请求
   - 参数：画面のVariable、画面のType、画面のDescription
   - 调用 `UD10Add`（Endpoint: `/api/v1/hdoc/variables/add`）接口。
6. **结果处理**：
   - **成功**：显示消息"变量添加成功"，清空输入框。
   - **失败**：设置 "变量添加失败"

#### 3.1.6 [Update] 按钮压下

1. **开始**：用户点击 [Update] 按钮。
2. **前置处理**：获取 Variable 及要更新的字段值。
3. **空值校验 (Frontend Check)**：
   - 若 `Variable` 为空：
     - 设置 `Message` = `Variable为必填项`
     - **终止**流程。
4. **Variable存在性校验**：
   - 调用 `UD08SelectHdocvariables` 检查Variable是否存在于HDOC_VARIABLES表中
   - 若不存在，显示错误消息 `Variant does not exists. Please enter the correct content`，**终止**流程
5. **API 调用**：
   - 呼出时点：用户点击Update按钮后
   - 呼出方法：POST请求
   - 参数：画面のVariable、画面のType、画面のDescription
   - 调用 `UD10Update`（Endpoint: `/api/v1/hdoc/variables/update`）接口。
6. **结果处理**：
   - **成功**：显示消息"变量更新成功"。
   - **失败**：设置 `Message` = "变量更新失败"

#### 3.1.7 [Delete] 按钮压下

1. **开始**：用户点击 [Delete] 按钮。
2. **前置处理**：获取 Variable 字段值。
3. **空值校验 (Frontend Check)**：
   - 若 `Variable` 为空：
     - 设置 `Message` = `Variable为必填项`
     - **终止**流程。
4. **Variable存在性校验**：
   - 调用 `UD08SelectHdocvariables` 检查Variable是否存在于HDOC_VARIABLES表中
   - 若不存在，显示错误消息 `Variant does not  exists. Please enter the correct content`，**终止**流程
5. **确认对话框**：
   - 显示 "Do you really want to delete this variant?"
   - 若用户取消：**终止**流程。
6. **API 调用**：
   - 呼出时点：用户点击Delete按钮后
   - 呼出方法：POST请求
   - 参数：画面のVariable
   - 调用 `UD10Delete`（Endpoint: `/api/v1/hdoc/variables/delete`）接口。
7. **结果处理**：
   - **成功**：显示消息"变量删除成功"，清空输入框。
   - **失败**：设置 "变量删除失败"

#### 3.1.8 [Excel] 按钮压下

1. **开始**：用户点击 [Excel] 按钮。
2. **处理**：
   - 设置文件名：`HDoc_Variables_YYYYMMDD.csv`
   - 触发浏览器下载。
   - 显示消息"CSV文件导出成功"。

### 3.2 校验详细规格表

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 (Message Content) | 动作 |
| :-: | :------: | :------: | :------: | :------------------------: | :--: |
| 1 | Click Add | Variable | `Value == null` OR `Trim(Value) == ""` | `Variable为必填项` | 显示 Message，阻止提交 |
| 2 | Click Add | Type | 未选择类型 | `请选择变量类型` | 显示 Message，阻止提交 |
| 3 | API Response (Add) | Variable | 后端校验-变量已存在 | `Variant already exists. Please enter the correct content` | 显示 Message，阻止提交 |
| 4 | Click Update | Variable | `Value == null` OR `Trim(Value) == ""` | `Variable为必填项` | 显示 Message，阻止提交 |
| 5 | API Response (Update) | Variable | 后端校验-变量不存在 | `Variant does not exists. Please enter the correct content` | 显示 Message，阻止提交 |
| 6 | Click Delete | Variable | `Value == null` OR `Trim(Value) == ""` | `Variable为必填项` | 显示 Message，阻止提交 |
| 7 | API Response (Delete) | Variable | 后端校验-变量不存在 | `Variant does not exists. Please enter the correct content` | 显示 Message，阻止提交 |
| 8 | Click Search | 所有搜索条件 | 全部为空 | `请输入至少一个搜索条件` | 显示 Message，阻止提交 |

## 4. 接口定义 (API Specification)

### 4.1 UD08SelectHdocvariables

- **功能**：检查变量是否存在。
- **所属 API**：UD08HomologationVariablesApi
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/ud08/checkVariable`

#### Request Body

```json
{
  "variable": "string"
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "変数校验成功",
  "data": {
    "variable": "xxx",
    "exists": true,
    "count": 1
  }
}
```


### 4.2 UD10Add - 新增变量

- **功能**：向HDOC_VARIABLES表中添加新的变量记录。
- **所属 API**：UD10HdocvariablesApi
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/variables/add`

#### Request Body

```json
{
  "variable": "VAR_NEW",
  "type": "VDA",
  "description": "新变量描述",
  "createdByUser": "admin",
  "date": "2023-10-15"
}
```

#### Response Success (200 OK)

```json
{
      "code": 200,
      "message": "变量添加成功",
      "data": {
          "variable": "变量名"
      }
}
```

#### Response Error (409 Conflict)

```json
{
  "code": 409,
  "message": "变量添加失败",
  "data": null
}
```

### 4.3 UD10Update - 更新变量

- **功能**：更新HDOC_VARIABLES表中现有变量的信息。
- **所属 API**：UD10HdocvariablesApi
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/variables/update`

#### Request Body

```json
{
  "variable": "VAR001",
  "type": "VDA",
  "description": "更新后的描述",
  "createdByUser": "admin",
  "date": "2023-10-15"
}
```

#### Response Success (200 OK)

```json
{
    "code": 200,
    "message": "变量更新成功",
    "data": {
        "variable": "变量名"
    }
}
```

#### Response Error (404 Not Found)

```json
{
  "code": 404,
  "message": "变量更新失败",
  "data": null
}
```

### 4.4 UD10Delete - 删除变量

- **功能**：从HDOC_VARIABLES表中删除指定的变量记录。
- **所属 API**：UD10HdocvariablesApi
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/variables/delete`

#### Request Body

```json
{
  "variable": "VAR001"
}
```

#### Response Success (200 OK)

```json
{
    "code": 200,
    "message": "变量删除成功",
    "data": {
        "variable": "变量名"
    }
}
```

#### Response Error (404 Not Found)

```json
{
  "code": 404,
  "message": "变量删除失败",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :------- | :------- | :--------------- |
| **数据库连接失败** | 捕获SQLException，记录日志，返回友好错误提示 | `系统繁忙，请稍后重试` |
| **变量已存在（Add操作）** | 捕获唯一约束冲突异常，返回409状态码 | `Variant already exists. Please enter the correct content` |
| **变量不存在（Update/Delete操作）** | 查询结果为空，返回404状态码 | `Variant does not exists. Please enter the correct content` |
| **参数校验失败** | 前端校验拦截，不发送请求 | 根据具体校验项显示相应错误消息 |
| **CSV导出失败** | 捕获IO异常，记录日志 | `CSV导出失败，请联系管理员` |
| **网络超时** | 设置请求超时时间，捕获TimeoutException | `请求超时，请检查网络连接` |
| **权限不足** | 检查用户登录状态和权限 | `您没有权限执行此操作` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理 `variable`, `type`, `description`, `createdByUser`, `date`, `message`, `isLoading`。
   - `Message` Label 默认隐藏（内容为空时不占位或高度为0）。

2. **安全性**：
   - 严禁在前端日志中打印敏感数据。
   - API 请求必须通过 HTTPS 发送。
   - 对所有输入进行严格的字符过滤，只允许半角英数字和记号。

3. **UI 细节**：
   - 所有操作按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
   - `Message` 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
   - Delete 操作建议实现二次确认对话框，避免误删。

4. **数据表**：
   - 主要数据表：`HDOC_VARIABLES`
   - 字段包括：VARIABLE, TYPE, DESCRIPTION, CREATED_BY_USER, DATE 等
