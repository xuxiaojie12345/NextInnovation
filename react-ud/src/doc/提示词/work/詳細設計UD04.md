## 1. 背景 (Background)

本模块提供Homologation Document生成功能，显示车辆相关信息、S-Note信息、轮胎信息等，并提供文档下载和修改功能。用户可以从前页面传入Chassis信息，查看生成的文档状态和相关信息。

- **目标**：清晰展示车辆关键信息，提供直观的文档下载链接，并确保数据安全。
- **安全性**：数据只读显示，防止未授权访问，文件下载权限控制。
- **用户体验**：采用清晰的信息展示布局，提供明确的错误提示信息，S-Note信息醒目提示。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有逻辑均在页面加载时同步或异步执行。

### 3.1 处理流程
#### 3.1.1 画面初期表示 
  1. **开始**：从前页面接收Chassis series和Chassis no参数。
  2. **前置处理**：
     - 若Chassis series或Chassis no为空，在Error message area显示错误消息 `Invalid chassis information.`
  3. **API调用**：
     - 呼出时点：画面加载时
     - 呼出方法：POST请求
     - 参数：画面のChassis series、画面のChassis no
     - 调用UD04SelectGeneratedocumentApi（Endpoint: `/api/v1/hdoc/generatedocument`）
  4. **数据获取**：
     - 从HDOC_REC_DATA_OM表获取Ordernumber、Build week、Spec week、CUSTOMER_ADAP
     - 从HDOC_REC_DATA_VDA_GENERAL表获取COUNTRY_OF_OPERATION
     - 从HDOC_REC_DATA_KOLA_TIRE_MASTER表获取LOAD_INDEX
     - 从HDOC_ADCA_CHANGE表获取ACT状态
     - 从HDOC_ADCA_MODIFICATION表获取VARIABLE
  5. **结果显示**：
     - 设置Master Market为固定值'-EU'
     - 设置Using template为固定值'eU/VIN PLATE_UD TRUCKS TSA INDO PHIL.rtf'
     - 设置HDoc version为固定值'4.2.1'
     - 如果有S-Note信息，显示S-Note Message
     - 如果AD-Change激活，显示Modify Doc Link
     - 显示Generated document下载链接（正常显示，但不实装下载功能）
  6. **结果处理**：
     - **成功**：显示所有信息
     - **失败**：在Error message area显示错误消息

#### 3.1.2 Chassis no点击处理
  1. **开始**：用户点击Chassis no链接。
  2. **结果处理**：画面迁移到Vehicle Specification页面，并传递Chassis series、Chassis no参数。

#### 3.1.3 Modify Doc Link点击处理
  1. **开始**：用户点击 'After def change detected. Document need to be modified.' 链接。
  2. **结果处理**：画面迁移到Modify Document画面，并把Chassis series、Chassis no、Market、userID传到后画面。

#### 3.1.4 Generated document下载处理
  1. **开始**：用户点击Generated document下载链接。
  2. **结果处理**：链接正常显示，但不实装下载功能。


### 3.2 校验详细规格表

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 | 动作 |
| :-: | :----------: | :---------------: | :------------------------------------: | :---------------------------------------------------------------------------: | :----------------------------------: |

## 4. 接口定义 (API Specification)

### 4.1 UD04SelectGeneratedocumentApi

- **功能**：获取Generate Document页面所需的所有数据。
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/generatedocument`

#### Request Body

```json
{
  "serie": "string",
  "chnr": "string"
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "ordernumber": "string",
    "buildWeek": "string",
    "specWeek": "string",
    "market": "string",
    "sNoteNo": "string",
    "loadIndex": "string",
    "modifyDocLink": boolean,
    "replacingParameters": 
      {
        "variable": "string"
      }
  }
}
```

#### Response Error (404 Not Found)

```json
{
  "code": 404,
  "message": "Vehicle data not found.",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :----------------------- | :----------------- | :--------------------------------------------- |
| **Chassis参数无效** | 前端校验拦截 | `Invalid chassis information.` |
| **车辆信息不存在** | API返回404错误 | `Vehicle data not found.` |
| **VIN Plate文件不存在** | 前端检查文件URL | `Generated document not available.` |
| **API调用失败** | 捕获异常，返回500错误 | `System error. Please contact administrator.` |
| **网络超时** | 捕获超时异常 | `Network timeout. Please try again.` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理 `vehicleData`, `documentInfo`, `errorMessage`, `isLoading`。
   - 所有数据显示为只读，不提供编辑功能。
2. **安全性**：
   - 页面访问必须验证用户登录状态。
   - 文件下载链接应包含访问令牌，防止未授权下载。
   - 所有API请求必须通过 HTTPS 发送。
3. **UI 细节**：
   - S-Note Message 应使用醒目的颜色（如橙色）以引起注意。
   - Generated document 链接应有明确的图标标识。
   - Error message 区域默认隐藏（内容为空时不占位）。
4. **性能优化**：
   - 数据应一次性加载，避免多次API调用。
   - 大量S-Note信息应支持滚动显示，避免页面过长。
