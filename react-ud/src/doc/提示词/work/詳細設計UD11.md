## 1. 背景 (Background)

本模块提供Existing HDoc Variables查询结果展示功能，以DataTable形式显示HDOC_VARIABLES表的查询结果，支持选择记录、返回、打印、Excel导出和Down操作（跳转到Homologation Variables页面并过滤Variant）。

- **目标**：清晰展示查询结果，支持记录选择和操作，显示查询结果数量，支持打印和Excel导出，Down操作可快速定位到相关Variant。
- **安全性**：数据只读显示（除删除操作外），Created by user列支持跳转到EDB User View，Down操作需要选择记录。
- **用户体验**：采用清晰的查询结果表格展示，支持记录选择和操作，显示查询结果数量。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在各操作按钮点击时同步或异步执行。

### 3.1 处理流程

#### 3.1.1 初期表示

1. **开始**：从 ExistingHdocVariables 画面携带检索条件跳转过来。
2. **API调用**：
   - 呼出时点：画面加载时
   - 呼出方法：POST请求
   - 参数：前画面传递的检索条件（Variable, Type, Description, Created by user, Date）
   - 调用 `UD11Search`（Endpoint: `/api/v1/hdoc/variables/search`）执行查询。
3. **结果显示**：
   - **成功**：在DataTable中显示查询结果，显示查询结果数量（Number of lines found: XXX）。
   - **失败**：显示相应错误消息。
4. **画面状态**：
   - Search、Down、Back、Print、Excel按钮均处于激活状态。
   - 默认未选中任何记录。
5. **结果**：页面处于等待用户操作状态。

#### 3.1.2 [Select] 按钮压下

1. **开始**：用户点击 [Select] 按钮。
2. **校验**：
   - 检查是否选择了记录
   - 如果没有选择显示错误信息”No key defined for table.“ 终止流程
2. **处理**：跳转到 ExistingHdocVariables 画面 并 自动显示所选记录的内容

#### 3.1.3 [Back] 按钮压下

1. **开始**：用户点击 [Back] 按钮。
2. **处理**：返回前页面，自动显示之前的查询条件。

#### 3.1.4 [Print] 按钮压下

1. **开始**：用户点击 [Print] 按钮。
2. **处理**：调用浏览器打印功能，打印当前页面内容。

#### 3.1.5 [Down] 按钮压下
    暂定不实装具体功能

#### 3.1.6 [Excel] 按钮压下

1. **开始**：用户点击 [Excel] 按钮。
2. **处理**：
   - 触发浏览器下载， 导出对应的csv文件 (ExistingHDocVariablesResultList_yyyymmdd.csv)
   - 显示消息"CSV文件导出成功"。

#### 3.1.7 Created by user链接点击

1. **开始**：用户点击Created by user列中的链接。
2. **处理**：
   - 获取该记录的REGISTER_USER。
   - 携带userid作为参数跳转到EDB User View页面。

## 4. 接口定义 (API Specification)

### 4.1 UD11Search

- **功能**：查询HDOC_VARIABLES。
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/variables/search`

#### Request Body

```json
{
   "variable": "string",
   "type": "string",
   "descr": "string",
   "registerUser": "string",
   "registerDatetime": "string"
}
```

#### Response Success (200 OK)

```json
{
   "code": 200,
   "message": "查询成功",
   "data": {
      "list": [
               {
                  "variable": "xxx",
                  "type": "xxx",
                  "description": "xxx",
                  "registerUser": "xxx",
                  "registerDatetime": "xxx"
               }
            ]
          }
}
            
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :----------------------- | :----------------- | :--------------------------------------------- |
| **未选择记录就点击Down** | 前端校验拦截 | `No key defined for table.` |
| **API调用失败** | 捕获异常，返回500错误 | `System error. Please contact administrator.` |
| **网络超时** | 捕获超时异常 | `Network timeout. Please try again.` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理 `searchResults`, `selectedRecord`, `errorMessage`, `isLoading`。
   - 选中记录应支持单选。
2. **安全性**：
   - API请求必须包含用户身份验证token。
   - 用户必须具有Manage Variable List权限才能访问此页面。
3. **UI 细节**：
   - DataTable应支持行选择（radio或checkbox）。
   - Created by user列应显示为可点击链接样式。
   - Count区域应醒目显示查询结果数量。
   - Down按钮在未选择记录时应禁用或给出明确提示。
4. **性能优化**：
   - 大量数据时应支持分页或虚拟滚动。
   - Excel导出应在后台进行，避免阻塞UI。
