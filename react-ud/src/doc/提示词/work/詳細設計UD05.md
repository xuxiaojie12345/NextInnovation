## 1. 背景 (Background)

本模块提供Modify Document功能，允许用户对Homologation Document进行修改。用户可以从前页面传入Chassis信息，在Modify Document页面中选择要替换的变量，并输入新的值。支持查看当前文档中的变量列表和对应的值。

- **目标**：提供直观的文档变量修改界面，确保用户能够准确地替换文档中的变量值，支持批量修改操作。
- **安全性**：变量存在性校验，防止未授权的文档修改，确保数据一致性。
- **用户体验**：清晰的变量列表展示，直观的值输入框，明确的保存和取消操作，实时的错误提示。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有逻辑均在用户执行相应操作时同步或异步执行。

### 3.1 处理流程

#### 页面加载流程
1. **开始**：从前页面接收Chassis series和Chassis no参数。
2. **前置处理**：
   - 验证参数有效性
3. **API调用**：
   - 呼出时点：画面加载时
   - 呼出方法：POST请求
   - 参数：画面のChassis series、画面のChassis no
   - 调用UD05ModifyDocumentApi 的 UD05SelectVariableModification（Endpoint: `/api/v1/hdoc/modifydocument/select`）获取当前文档的变量列表
4. **数据获取**：
   - 从HDOC_ADCA_MODIFICATION表获取VARIABLE和NEWVAL字段
   - 从HDOC_REC_DATA_KOLA_VARIANT表获取SYMBOL（如果Modify中不存在则从这里获取）
5. **结果显示**：
   - 显示Chassis no信息
   - 显示Variable列表、Description、Current value
   - Modified value初始为空或已有修改值
6. **结果处理**：
   - **成功**：正常显示变量修改界面
   - **失败**：显示错误消息

#### Chassis no点击处理
1. **开始**：用户点击Chassis no链接。
2. **结果处理**：画面迁移到Chassis详细信息页面，并传递Chassis series、Chassis no参数。

#### Template文件下载处理
1. 只显示链接，不实装具体功能

#### Save操作流程
1. **开始**：用户点击[Save]按钮。
2. **前置处理**：
   - 获取所有Variable和对应的Modified value输入值
   - 检查是否有任何Modified value被输入
   - **如果都没有输入**：显示错误消息 `NO UNRELEASED VERSION EXISTS!`，**终止**流程，不调用API
   - **如果有输入**：继续处理
3. **API调用**：
   - 呼出时点：用户点击Save按钮后
   - 呼出方法：POST请求
   - 参数：画面のVariable列表及对应的Value值
   - 调用UD05ModifyDocumentApi 的 UD05UpdateHdocAdcaModification（Endpoint: `/api/v1/hdoc/modifydocument/update`）更新HDOC_ADCA_MODIFICATION表
4. **结果处理**：
   - **成功**：跳转到「Save Modifications」页面，显示修改内容
   - **失败**：显示错误消息，保持在当前页面

### 3.2 校验详细规格表

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 | 动作 |
| :-: | :----------: | :---------------: | :------------------------------------: | :---------------------------------------------------------------------------: | :----------------------------------: |
| 1 | 页面加载 | Chassis参数 | Chassis series或Chassis no为空 | `Invalid chassis information.` | 显示错误消息 |
| 2 | Save按钮点击 | Modified value | 没有任何项目被修改 | `NO UNRELEASED VERSION EXISTS!` | 显示错误消息，不提交 |
| 3 | 输入时 | Modified value | 输入长度超过500字符 | `Input exceeds maximum length of 500 characters.` | 截断或显示警告 |
| 4 | API调用 | 数据更新 | 数据库更新失败 | `Failed to save modifications. Please try again.` | 显示错误消息 |

## 4. 接口定义 (API Specification)

### 4.1 UD05SelectVariableModification

- **功能**：获取Modify Document页面所需的变量列表数据。
- **所属 API**：UD05ModifyDocumentApi
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/modifydocument/select`

#### Request Body

```json
{
  "serie": "string",
  "chnr": "string"
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "variable": "VIN",
      "val": "12345678901234567"
    },
    {
      "variable": "ENGINE_NO",
      "val": "ENG123456"
    }
  ]
}
```

#### Response Error (404 Not Found)

```json
{
  "code": 404,
  "message": "Vehicle data not found.",
  "data": null
}
```

### 4.2 UD05UpdateHdocAdcaModification

- **功能**：更新Modify Document的变量值。
- **所属 API**：UD05ModifyDocumentApi
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/modifydocument/update`

#### Request Body

```json
{
  "serie": "string",
  "chnr": "string",
  "modifications": [
    {
      "variable": "VIN",
      "val": "NEW_VIN_VALUE"
    }
  ]
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "Variables updated successfully.",
  "data": {
    "updateCount": 2
  }
}
```

#### Response Error (400 Bad Request)

```json
{
  "code": 400,
  "message": "Value is required.",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :----------------------- | :----------------- | :--------------------------------------------- |
| **没有任何修改就点击Save** | 前端校验拦截 | `NO UNRELEASED VERSION EXISTS!` |
| **输入长度超过500字符** | 前端校验拦截 | `Input exceeds maximum length of 500 characters.` |
| **数据库更新失败** | API返回错误 | `Failed to save modifications. Please try again.` |
| **API调用失败** | 捕获异常，返回500错误 | `System error. Please contact administrator.` |
| **网络超时** | 捕获超时异常 | `Network timeout. Please try again.` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理 `chassisInfo`, `modifications`, `errorMessage`, `isLoading`。
   - modifications数组存储Variable和Value的对应关系。
2. **安全性**：
   - 页面访问必须验证用户登录状态。
   - 所有API请求必须通过 HTTPS 发送。
   - 防止SQL注入和XSS攻击。
3. **UI 细节**：
   - Value输入框应有明确的占位符提示。
   - Error message 区域默认隐藏（内容为空时不占位）。
4. **性能优化**：
   - 变量列表应支持虚拟滚动，避免大量数据时的性能问题。
   - 批量更新操作应使用单个API调用，减少网络请求次数。
