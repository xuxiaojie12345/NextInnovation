## 1. 背景 (Background)

本模块提供Homologation Variables的管理功能，包括查询、添加、更新和删除用户自定义规则。用户可以按Product class、Number、Market等条件查询，并对HDOC_USER_DEFINED_RULES表进行操作。

- **目标**：提供完整的CRUD操作功能，支持用户自定义规则的管理，确保数据的完整性和一致性。
- **安全性**：主键冲突校验，Variant存在性校验，防止SQL注入。
- **用户体验**：采用清晰的查询条件输入，直观的CRUD操作按钮，明确的校验错误提示，Variant格式自动处理（TEMPLATE-XXX）。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在各操作按钮点击时同步或异步执行。

### 3.1 处理流程

#### 初期表示
1. **开始**：页面加载。
2. **前置处理**：无。
3. **API调用**：
   - 呼出时点：画面加载时
   - 呼出方法：POST请求
   - 参数：无
   - 调用 `UD08SelectProductclassmaster` 获取Product class下拉列表
   - 调用 `UD08SelectMarketmaster` 获取Market下拉列表
4. **结果显示**：Product class和Market下拉框填充数据。
5. **结果处理**：正常显示。

#### Search按钮点击
1. **开始**：用户点击[Search]按钮。
2. **前置处理**：
   - 获取Product class、Number、Market等输入参数
   - 去除首尾空格
3. **空值校验**：
   - 若Product class、Number、Market为空，显示错误消息，**终止**流程
4. **画面迁移**：
   - 组装所有查询条件
   - 携带条件参数跳转到查询结果页面（HomologationVariablesResultList）
   
#### Clear按钮点击
1. **开始**：用户点击[Clear]按钮。
2. **处理**：
   - 清空所有输入框和下拉列表
   - 恢复初始状态

#### Add按钮点击
1. **开始**：用户点击[Add]按钮。
2. **前置处理**：
   - 获取Product class、Number、Market等输入参数
   - 去除首尾空格
3. **空值校验**：
   - 若Product class、Number、Market为空，显示错误消息，**终止**流程
4. **主键重复校验**：
   - 调用 `UD08SelectDefinedRules` 检查按Product class、Number、Market是否已存在
   - 若存在，显示错误消息 `Primary key conflict, Please enter the correct content.`，**终止**流程
5. **Variable格式处理**：
   - 若Variable是'TEMPLATE-XXX'格式，删除'TEMPLATE-'前缀
6. **Variable存在性校验**：
   - 调用 `UD08SelectHdocvariables` 检查Variable是否存在于HDOC_VARIABLES表中
   - 若不存在，显示错误消息 `Variant does not exist, Please enter the correct content.`，**终止**流程
7. **API调用**：
   - 呼出时点：用户点击Add按钮后
   - 呼出方法：POST请求
   - 参数：画面のProduct class、Number、Market等
   - 调用 `UD08Add` 插入记录
   - 设置ADD_DATE、UPDATE_USER、UPDATE_DATETIME
8. **结果处理**：
   - **成功**：显示成功消息
   - **失败**：显示错误消息

#### Update按钮点击
1. **开始**：用户点击[Update]按钮。
2. **前置处理**：
   - 获取Product class、Number、Market等输入参数
   - 去除首尾空格
3. **记录存在性校验**：
   - 调用 `UD08SelectDefinedRules` 校验按Product class、Number、Market记录是否存在
   - 若不存在，显示错误消息 `Data does not exist, Please enter the correct content.`，**终止**流程
4. **Product、number,Market更改校验**：
   - 从前Homologation Variables Result List页面跳转过来时，获取主键信息（产品、编号、市场），并将其作为修改前原始数据临时保存。
   - 点击【更新】按钮后，系统会校验主键是否被修改。
   - 若主键存在修改，显示错误消息 `Data does not exist, Please enter the correct content.`，**终止**流程
5. **Variable存在性校验**：
   - 调用 `UD08SelectHdocvariables` 检查Variable是否存在于HDOC_VARIABLES表中
   - 若不存在，显示错误消息 `Variant does not exist, Please enter the correct content.`，**终止**流程
6. **API调用**：
   - 呼出时点：用户点击Update按钮后
   - 呼出方法：POST请求
   - 参数：画面のProduct class、Number、Market等
   - 调用 `UD08Update` 更新记录
   - 更新UPDATE_USER、UPDATE_DATETIME
7. **结果处理**：
   - **成功**：显示成功消息
   - **失败**：显示错误消息

#### Delete按钮点击
1. **开始**：用户点击[Delete]按钮。
2. **前置处理**：
   - 获取Product class、Number、Market
   - 去除首尾空格
3. **记录存在性校验**：
   - 调用 `UD08SelectDefinedRules` 校验按Product class、Number、Market记录是否存在
   - 若不存在，显示错误消息 `Data does not exist, Please enter the correct content.`，**终止**流程
4. **API调用**：
   - 呼出时点：用户点击Delete按钮后
   - 呼出方法：POST请求
   - 参数：画面のProduct class、Number、Market
   - 调用 `UD08Delete` 删除记录
   - 设置DELETE_DATE
5. **结果处理**：
   - **成功**：显示成功消息
   - **失败**：显示错误消息

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :----------------------- | :----------------- | :--------------------------------------------- |
| **主键冲突** | API返回409错误 | `Primary key conflict, Please enter the correct content.` |
| **Variant不存在** | API返回400错误 | `Variant does not exist, Please enter the correct content.` |
| **记录不存在** | API返回404错误 | `Data does not exist, Please enter the correct content.` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理 `formData`, `searchResults`, `errorMessage`, `isLoading`。
   - 表单数据应在Clear操作时重置。
2. **安全性**：
   - 所有输入必须进行严格的格式校验，防止SQL注入。
   - API请求必须包含用户身份验证token。
   - 用户必须具有Rule Admin权限才能执行Add/Update/Delete操作。
3. **UI 细节**：
   - Variable字段应支持自动格式化（删除'TEMPLATE-'前缀）。
   - 必填字段应有明确的视觉标识（如红色星号）。
   - 操作按钮应根据当前状态启用/禁用（如无数据时禁用Update/Delete）。
4. **性能优化**：
   - 查询结果应支持分页，避免一次性加载大量数据。
   - 下拉列表数据应缓存，避免重复API调用。
