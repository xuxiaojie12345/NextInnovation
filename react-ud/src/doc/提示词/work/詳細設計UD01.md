## 1. 背景 (Background)

本模块是系统的入口，负责验证用户身份。用户通过输入 UserID 和 Password，经由前端校验后调用后端 `AuthenticationApi` 进行认证。

- **目标**：确保只有授权用户能进入系统，并提供清晰的错误反馈。
- **安全性**：密码字段需掩码显示，所有敏感数据传输需加密，防止SQL注入和XSS攻击。
- **用户体验**：采用 Label 形式在页面内显示错误信息，避免频繁弹窗打断操作流，提供备选登录链V接以应对账户锁定情况。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 **[Login]** 按钮时同步或异步执行。

### 3.1 处理流程

1. **开始**：用户点击 [Login] 按钮。
2. **空值校验 (Frontend Check)**：
   - 若 `UserID` 为空 **或** `Password` 为空：
     - 设置 `Message` = `Username and password are required.`
     - **终止**流程，不调用 API。
3. **API 调用**：
   - 呼出时点：用户点击Login按钮后
   - 呼出方法：POST请求
   - 参数：画面のUserID、画面のPassword
   - 调用 `AuthenticationApi`（Endpoint: `/api/v1/hdoc/login`）。
4. **结果处理**：
   - **认证成功**：清空 Message，保存 Token，跳转到 Menu 页面。
   - **认证失败（用户名或密码错误）**：设置 `Message` = `We didn't recognize the username or password you entered. Please try again.`
   - **认证失败（账户锁定）**：设置 `Message` = `Your account is locked. Please contact your system administrator.`
   - **系统异常**：设置 `Message` = `System error. Please contact administrator.`

### 3.2 校验详细规格表

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 (Message Content) | 动作 |
| :-: | :----------: | :---------------: | :------------------------------------: | :---------------------------------------------------------------------------: | :----------------------------------: |
| 1 | Click Login | UserID / Password | `Value == null` OR `Trim(Value) == ""` | `Username and password are required.` | 显示 Message，焦点停留在第一个空字段 |
| 2 | API Response | 认证结果 | 用户名或密码不正确 | `We didn't recognize the username or password you entered. Please try again.` | 显示 Message |
| 3 | API Response | 认证结果 | 账户已锁定 | `Your account is locked. Please contact your system administrator.` | 显示 Message |
| 4 | API Call | 系统状态 | 系统异常 | `System error. Please contact administrator.` | 显示 Message |

## 4. 接口定义 (API Specification)

### 4.1 AuthenticationApi

- **功能**：验证用户凭证并返回认证结果。
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/login`

#### Request Body

```json
{
  "userid": "string",
  "password": "string"
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "xxxx",
    "userid": "xxx",
    "username": "xxx"
  }
}
```

#### Response Error (401 Unauthorized)

```json
{
  "code": 401,
  "message": "We didn't recognize the username or password you entered. Please try again.",
  "data": null
}
```

#### Response Error (403 Forbidden)

```json
{
  "code": 403,
  "message": "Your account is locked. Please contact your system administrator.",
  "data": null
}
```

#### Response Error (500 Internal Server Error)

```json
{
  "code": 500,
  "message": "System error. Please contact administrator.",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :----------------------- | :----------------- | :--------------------------------------------- |
| **用户ID或密码为空** | 前端校验拦截 | `Username and password are required.` |
| **用户名或密码错误** | API返回401错误 | `We didn't recognize the username or password you entered. Please try again.` |
| **账户已锁定** | API返回403错误 | `Your account is locked. Please contact your system administrator.` |
| **数据库连接失败** | 捕获异常，返回500错误 | `System error. Please contact administrator.` |
| **网络超时** | 捕获超时异常 | `System error. Please contact administrator.` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理 `userID`, `password`, `message`, `isLoading`。
   - `Message` Label 默认隐藏（内容为空时不占位或高度为0）。
2. **安全性**：
   - 严禁在前端日志中打印明文密码。
   - API 请求必须通过 HTTPS 发送。
   - 防止SQL注入和XSS攻击。
3. **UI 细节**：
   - Login 按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
   - `Message` 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
   - 支持响应式布局，适配不同屏幕尺寸。
