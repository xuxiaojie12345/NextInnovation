## 1. 背景 (Background)

本模块提供HDoc用户文档权限管理功能，管理员可以输入UserID，从Saviynt系统获取用户信息，并设置该用户对各个文档的访问权限。支持查询、更新用户的文档权限。

- **目标**：为User Admin权限用户提供完整的用户文档权限管理界面，确保文档访问权限分配的准确性和安全性。
- **安全性**：用户ID存在性校验、文档权限变更审计日志、防止未授权权限修改。
- **用户体验**：清晰的UserID输入和用户信息显示、直观的文档权限选择、明确的存在性校验提示、自动选择用户已有权限。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户执行相应操作时同步或异步执行。

### 3.1 处理流程

#### 页面初始化流程
1. **开始**：页面加载完成。
2. **API 调用**：
   - 呼出时点：画面加载时
   - 呼出方法：POST请求
   - 参数：无
   - 调用 `UD20SelectHdocDocumentList`
3. **数据获取**：从 HDOC_DOCUMENT_LIST 表获取所有可用文档列表（DESCRIPTION字段）。
4. **结果显示**：显示Document下拉列表供用户选择。

#### User Info 操作流程
1. **开始**：用户点击 [User Info] 按钮。
2. **前置处理**：获取 UserID，执行 `trim()` 去除首尾空白。
3. **空值校验 (Frontend Check)**：
   - 若 `UserID` 为空：
     - 显示错误消息 `UserID is required`
     - **终止**流程，不调用 API。
4. **API 调用**：
   - 呼出时点：用户点击User Info按钮后
   - 调用 `UD18SelectHdocFunctionAuth`检查用户是否存在
         用户不存在：显示错误消息 `We didn't recognize the userid you entered. Please try again.`
                    终止流程
   - 若用户存在，调用 `AuthenticationApi` 取得 User 、调用 `UD18SelectHdocUserDoc` 获取文档权限 （参数：画面的UserID）

5. **结果处理**：
   - **查询失败**：显示错误消息 `We didn't recognize the userid you entered. Please try again.`
   - **查询成功**：自动勾选已有文档权限，显示用户信息

#### Update 操作流程
1. **开始**：用户点击 [Update] 按钮。
2. **前置处理**：获取 UserID 和所有文档权限选择状态。
3. **API 调用**：
   - 呼出时点：用户点击Update按钮后
   - 呼出方法：POST请求
   - 参数：画面のUserID、画面の文档权限列表
   - 首先调用 `UD18SelectHdocFunctionAuth` 检查用户是否存在
         用户不存在：显示错误消息 `We didn't recognize the userid you entered. Please try again.`
                   终止流程
   - 如果存在，调用`UD18DeleteHdocUserDoc` 删除该用户的所有文档权限  
              调用`UD18CreateHdocUserDoc`插入新的文档权限记录
4. **结果处理**：
   - **成功**：显示成功消息 `用户文档权限更新成功`
   - **失败**：显示相应错误消息

### 3.2 校验详细规格表

| No. |   检查时机   |     检查对象      |                检查条件                |                          错误消息 (Message Content)                           |                 动作                 |
| :-: | :----------: | :---------------: | :------------------------------------: | :---------------------------------------------------------------------------: | :----------------------------------: |
|  1  | Click User Info | UserID | `Value == null` OR `Trim(Value) == ""` | `We didn't recognize the userid you entered. Please try again.` | 显示 Message，阻止后续操作 |

## 4. 接口定义 (API Specification)

### 4.1 AuthenticationApi

- **功能**：验证用户凭证并返回认证结果。
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/login`

#### Request Body

```json
{
  "userid": "string"
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "xxxx",
    "userid": "xxx",
    "username": "xxx"
  }
}
```

#### Response Error (401 Unauthorized)

```json
{
  "code": 401,
  "message": "We didn't recognize the username or password you entered. Please try again.",
  "data": null
}
```

#### Response Error (403 Forbidden)

```json
{
  "code": 403,
  "message": "Your account is locked. Please contact your system administrator.",
  "data": null
}
```

#### Response Error (500 Internal Server Error)

```json
{
  "code": 500,
  "message": "System error. Please contact administrator.",
  "data": null
}
```

```json
  "message": "success",
  "data": {
    "documents": [
      {
        "doctype": "string",
        "description": "string",
        "businessUnit": "BU",
        "registerUser": "string",
        "registerDatetime": "datetime"
      }
    ]
  }
}
```

#### Response Error (400 Bad Request)

```json
{
  "code": 400,
  "message": "error message",
  "data": null
}
```

#### Response Error (500 Internal Server Error)

```json
{
  "code": 500,
  "message": "系统暂时不可用，请稍后重试",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :----------------------- | :----------------- | :--------------------------------------------- |
| **用户ID为空** | 前端校验拦截 | `We didn't recognize the userid you entered. Please try again.` |
| **用户ID不存在于功能权限表** | API返回404错误 | `We didn't recognize the userid you entered. Please try again.` |
| **Saviynt系统调用失败** | 捕获异常 | `Failed to fetch user info from Saviynt.` |
| **网络断开/超时** | 捕获 Network Error | `Network timeout. Please try again.` |
| **服务器内部错误 (500)** | 捕获 Server Error | `System error. Please contact administrator.` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理 `userId`, `userInfo`, `documents`, `selectedDocuments`, `isLoading`, `errorMessage`。
   - Document列表需要在页面初始化时加载。
2. **安全性**：
   - 仅User Admin权限用户可访问此页面。
   - 所有API调用必须通过HTTPS发送。
   - 文档权限变更需记录审计日志。
3. **UI 细节**：
   - 按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
   - 错误消息文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
   - Document权限选择建议使用复选框组形式，便于多选操作。
4. **数据源**：
   - 用户信息：Saviynt系统（通过AuthenticationApi）
   - 文档列表：HDOC_DOCUMENT_LIST.DESCRIPTION字段
   - 用户功能权限验证：HDOC_FUNCTION_AUTH表
   - 用户文档权限：HDOC_USER_DOC表
5. **操作流程**：
   - 更新操作采用"先删除后创建"的策略，确保权限数据的一致性。
   - 所有API调用都需要进行错误处理和用户反馈。
