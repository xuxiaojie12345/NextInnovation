## 1. 背景 (Background)

本模块提供AD Change管理功能，用户可以对Serie-Chnr进行添加、删除和校验操作。支持在HDOC_ADCA_CHANGE表中管理AD/CA变更记录，包括Serie-Chnr和Desc字段。

- **目标**：允许系统工程人员和其他需要管理AD/CA变更的用户进行Serie-Chnr的CRUD操作。
- **核心功能**：Serie-Chnr的添加、删除和校验功能。
- **用户体验**：清晰的Serie-Chnr输入、直观的CRUD操作按钮、明确的存在性校验提示。
- **安全性**：Serie-Chnr存在性校验、防止SQL注入。
- **HDOC_ADCA_CHANGE 表字段定义**：
  | 字段名 | 说明 | 取值 |
  | :----- | :--- | :--- |
  | ACT | 活性状态 | Y=活性（有効）、N=非活性（無効） |
  | BU  | 业务单元 | 固定值 "UD" |

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击操作按钮时同步或异步执行。

### 3.1 处理流程

#### 3.1.1 点击 [ADD] 按钮

1. **开始**：用户点击 [ADD] 按钮。
2. **前置处理**：获取Serie-Chnr和Desc输入值，去除首尾空格。
3. **API 调用**：
   - 呼出时点：用户点击ADD按钮后
   - 呼出方法：POST请求
   - 参数：画面のSerie-Chnr、画面のDesc
   - 首先调用 `UD16SelectHdocAdcaChange`（Endpoint: `/api/v1/hdoc/adca/select`）检查Serie-Chnr是否存在及 ACT 状态。
   - 如果已存在且 ACT='Y'（活性状态）：
     - 设置 `Message` = `AFTER DEF CHANGE IS NOT ACTIVATED`
     - **终止**流程。
   - 如果已存在但 ACT='N'（非活性状态）（主键为 SERIE+CHNR，不含 ACT，不可重复 insert）：
     - 调用 `UD16ReactivateHdocAdcaChange`（Endpoint: `/api/v1/hdoc/adca/reactivate`）接口，将 ACT 更新为 'Y'。
   - 如果不存在（count=0）：
     - 调用 `UD16InsertHdocAdcaChange`（Endpoint: `/api/v1/hdoc/adca/insert`）接口，ACT='Y'，BU='UD'。
4. **处理**：
   - 插入记录到HDOC_ADCA_CHANGE表。
   - ACT 设为 'Y'（活性/有効）、BU 设为 'UD'（固定值）
   - 设置REGISTER_DATETIME等字段。
5. **结果处理**：
   - **成功**：显示成功消息"Record added successfully."。
   - **失败**：显示错误消息。

#### 3.1.2 点击 [DELETE] 按钮

1. **开始**：用户点击 [DELETE] 按钮。
2. **前置处理**：获取Serie-Chnr输入值，去除首尾空格。
3. **API 调用**：
   - 呼出时点：用户点击DELETE按钮后
   - 呼出方法：POST请求
   - 参数：画面のSerie-Chnr
   - 调用 `UD16UpdateHdocAdcaChange`（Endpoint: `/api/v1/hdoc/adca/update`）接口。
4. **处理**：
   - 全量更新HDOC_ADCA_CHANGE表记录，将 ACT 置为 'N'（非活性/無効）。
5. **结果处理**：
   - **成功**：显示成功消息"Record updated/deleted successfully."。
   - **失败**：显示错误消息。

#### 3.1.3 点击 [CHECK] 按钮

1. **开始**：用户点击 [CHECK] 按钮。
2. **前置处理**：获取Serie-Chnr输入值，去除首尾空格。
3. **API 调用**：
   - 呼出时点：用户点击CHECK按钮后
   - 呼出方法：POST请求
   - 参数：画面のSerie-Chnr
   - 调用 `UD16SelectHdocAdcaChange`（Endpoint: `/api/v1/hdoc/adca/select`）接口。
4. **处理**：
   - 检查Serie-Chnr是否存在于HDOC_ADCA_CHANGE表中，并获取 ACT 状态。
5. **结果处理**：
   - **记录存在且 ACT='Y'（活性/有効）**：显示成功消息"Record found and activated."。
   - **记录存在但 ACT='N'（非活性/無効）**：显示警告消息"AFTER DEF CHANGE IS NOT ACTIVATED"。
   - **记录不存在**：显示提示信息"Record not found."。

### 3.2 校验详细规格表

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 (Message Content) | 动作 |

## 4. 接口定义 (API Specification)

### 4.1 UD16SelectHdocAdcaChange

- **功能**：查询HDOC_ADCA_CHANGE记录（返回 ACT、BU 状态）。
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/adca/select`

#### Request Body

```json
{
  "serie": "string",
  "chnr": "string"
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "查询成功",
  "data": {
    "serie": "xxx",
    "chnr": "xxx",
    "count": "1",
    "act": "Y",
    "bu": "UD"
  }
}
```

#### Response Error (404 Not Found)

```json
{

  "message": "Record not found.",
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :------- | :------- | :--------------- |
| **Serie-Chnr已存在且 ACT='Y'** | API返回警告 | `AFTER DEF CHANGE IS NOT ACTIVATED` |
| **Serie-Chnr不存在** | API返回404错误 | `Record not found.` |
| **API调用失败** | 捕获异常，返回500错误 | `System error. Please contact administrator.` |
| **网络超时** | 捕获超时异常 | `Network timeout. Please try again.` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理 `serieChnr`, `desc`, `message`, `isLoading`。
   - 根据不同操作更新页面状态。

2. **安全性**：
   - 严禁在前端日志中打印敏感数据。
   - API 请求必须通过 HTTPS 发送。
   - 对输入参数进行SQL注入防护。

3. **UI 细节**：
   - 操作按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
   - `Message` 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
   - 输入框应限制字符数（Serie-Chnr最多15字符，Desc最多4000字符）。

4. **数据表**：
   - 主要数据表：`HDOC_ADCA_CHANGE`
   - 字段包括：SERIE, CHNR, ACT, BU, REASON, REGISTER_DATETIME, UPDATE_DATETIME 等
   - **ACT**：Y=活性（有効）、N=非活性（無効）
   - **BU**：固定值 "UD"
