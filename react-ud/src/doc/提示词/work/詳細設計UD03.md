## 1. 背景 (Background)

本模块提供车辆认证文档的生成入口。用户通过输入底盘系列号（Chassis series）、底盘编号（Chassis no）和选择文档类型（Document type），系统验证车辆信息正确后，跳转到文档生成页面进行后续处理。

- **目标**：确保只有有效的车辆信息才能生成认证文档，并提供清晰的错误反馈。
- **安全性**：输入参数需要进行格式校验（Chassis series 仅允许半角英字，Chassis no 仅允许半角数字），防止 SQL 注入攻击。需要用户已登录认证，页面未登录时应重定向到登录页。
- **用户体验**：采用简洁的表单布局，输入框与标签左对齐排列，提供实时格式校验与明确的错误反馈。上次输入的条件自动保存到 localStorage，页面重新打开时自动恢复，减少重复输入。提供 Help 按钮可跳转至 HDoc Help 页面获取使用帮助。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 **[Submit]** 按钮、**[Reset]** 按钮或 **[Help]** 按钮时触发。

### 3.1 处理流程

1. **初期表示**：
   - 页面加载时，自动调用 `UD03SelectHdocdocumentlistApi`（Endpoint: `/api/v1/hdoc/document/types`）获取 Document type 下拉列表内容。
   - 呼出时点：画面加载时
   - 呼出方法：GET请求
   - 参数：无
   - 从 localStorage 恢复上次输入的条件（Chassis series、Chassis no、Document type）。

2. **开始**：用户点击 [Submit] 按钮。
   - **前置处理**：获取表单输入值，执行 `trim()` 去除首尾空白。
   - **空值校验 (Frontend Check)**：
     - 若 `Chassis series` 为空：
       - 设置 `Message` = `Chassis series is required.`
       - **终止**流程，不调用 API。
     - 若 `Chassis no` 为空：
       - 设置 `Message` = `Chassis no is required.`
       - **终止**流程，不调用 API。
     - 若 `Document type` 未选择：
       - 设置 `Message` = `Document type is required.`
       - **终止**流程，不调用 API。
   - **API 调用**：
     - 呼出时点：用户点击Submit按钮后
     - 呼出方法：POST请求
     - 参数：画面のChassis series、画面のChassis no、画面のDocument type
     - 调用 `GenerateDocumentApi`（Endpoint: `/api/v1/hdoc/generatedocument`）。
   - **结果处理**：
     - **成功（车辆存在）**：跳转至 Generate Document 页面（`/menu/generate-document/result`），传递参数 `{ serie, chnr, doctype }`。
     - **失败（车辆不存在）**：设置 `Message` = `Chassis no is not exists`
     - **系统异常**：设置 `Message` = `System error. Please contact administrator.`

3. **开始**：用户点击 [Reset] 按钮。
   - 清空 Chassis series、Chassis no、Document type 三个输入项。
   - 清空错误消息区域。
   - 清除 localStorage 中保存的上次输入条件。
   - 页面恢复至初期表示状态。

4. **开始**：用户点击 [Help] 按钮。
   - 页面跳转到 HDoc Help 页面（`/guide-user`）。

## 4. 接口定义 (API Specification)

### 4.1 UD03SelectHdocdocumentlistApi

- **功能**：从 HDOC_DOCUMENT_LIST 表获取所有可用的文档类型列表。
- **Method**: `GET`
- **Endpoint**: `/api/v1/hdoc/document/types`

#### Request

```json
{}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "success",
  "data": [
    { "doctype": "VIN_PLATE", "description": "VIN Plate Document" },
    { "doctype": "COC", "description": "Certificate of Conformity" }
  ]
}
```

#### Response Error (500 Internal Server Error)

```json
{
  "code": 500,
  "message": "System error. Please contact administrator.",
  "data": null
}
```

### 4.2 GenerateDocumentApi

- **功能**：验证底盘信息是否存在，返回文档生成所需数据。
- **Method**: `POST`
- **Endpoint**: `/api/v1/hdoc/generatedocument`

#### Request Body

```json
{
  "serie": "ABCDE",
  "chnr": "1234567890",
  "doctype": "VIN_PLATE"
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "ordernumber": "19146492",
    "buildWeek": "2020186",
    "specWeek": "202018",
    "market": "AUS",
    "sNoteNo": "SN12345",
    "loadIndex": "152",
    "modifyDocLink": false,
    "replacingParameters": { "variable": "VPGVW 2" }
  }
}
```

#### Response Error (404 Not Found)

```json
{
  "code": 404,
  "message": "Generatedocument data not found.",
  "data": null
}
```

#### Response Error (500 Internal Server Error)

```json
{
  "code": 500,
  "message": "System error. Please contact administrator.",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :----------------------- | :----------------- | :--------------------------------------------- |
| **必填字段为空** | 前端校验拦截 | `Chassis series is required.` / `Chassis no is required.` / `Document type is required.` |
| **检索结果为空** | API 返回空数据 | `Chassis no is not exists` |
| **数据库连接失败** | 捕获异常，返回 500 错误 | `System error. Please contact administrator.` |
| **网络超时** | 捕获超时异常 | `System error. Please contact administrator.` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用 React State 管理 `chassisSeries`, `chassisNo`, `documentType`, `errorMessage`, `isLoading`。
   - 表单数据应持久化存储（localStorage）以保持上次输入的条件。
   - `Message` Label 默认隐藏（内容为空时不占位或高度为 0）。
2. **安全性**：
   - 严禁在前端日志中打印敏感信息。
   - API 请求必须通过 HTTPS 发送。
   - 输入参数必须进行严格的格式校验，防止 SQL 注入攻击。
3. **UI 细节**：
   - Submit 按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
   - `Message` 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
   - Document type 下拉框应显示描述文本，但传递 DOCTYPE 值。
