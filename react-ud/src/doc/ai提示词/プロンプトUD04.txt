# GenerateDocument 详细设计提示词

## 使用说明
使用此提示词生成详细设计文档时，必须严格遵循以下要求，确保每次生成的内容保持一致。

## 1. 基本信息
- **模块名称**：GenerateDocumentPage
- **文档编号**: DES-GenerateDocumentPage-001
- **作成日期**：2026-05-20

## 2. 背景 (Background)

### 核心功能和目标
本模块用于显示和下载车辆认证文档，主要功能包括：
- 显示指定底盘号的接收信息（OM、VDA、KOLA数据）
- 显示S-Note信息和轮胎主数据
- 显示ADCA变更状态，支持跳转到修改文档页面
- 显示VIN Plate参数和模板信息
- 提供文档下载功能
- 显示系统时间和程序版本信息

### 面向的用户群体
需要查看和下载车辆认证文档的授权用户，如质量管理人员、文档管理员等

### 用户体验考虑
- 清晰的信息展示布局
- 重要的变更信息以红色高亮显示
- 提供便捷的文档下载链接
- 实时显示系统时间和版本信息

### 安全性要求
- 需要用户登录认证后才能访问
- 敏感数据需要进行权限控制
- 支持HTTPS安全传输

## 4. 功能描述 (Functional Description)

### 4.1 页面初始化功能
**功能说明**：页面加载时调用API获取并显示底盘相关信息

**操作步骤**：
1. 页面加载时，系统从路由参数或上下文中获取当前底盘号
2. 调用UD04SelectGeneratedocumentApi API获取底盘相关的所有信息
3. API返回成功后，将数据显示到对应的标签字段
4. 若ADCA变更状态为激活状态，Modify Doc Link显示为红色并启用点击功能
5. 若发生错误，在Error message area区域显示错误消息

### 4.2 显示接收信息功能
**功能说明**：显示底盘的OM、VDA、KOLA接收数据

**操作步骤**：
1. 从HDOC_REC_DATA_OM表获取并显示Chassis series、Chassis no、Model、Spec week、S-Note NO等信息
2. 从HDOC_REC_DATA_VDA_GENERAL表获取并显示Market（CountryOfOperation）信息
3. 从HDOC_REC_DATA_KOLA_TIRE_MASTER表获取并显示Load Index信息
4. 若存在S-Note信息，在S-Note Message区域显示固定提示文本

### 4.3 显示ADCA变更状态功能
**功能说明**：根据ADCA变更状态显示不同的链接样式和功能

**操作步骤**：
1. 从HDOC_ADCA_CHANGE表获取ACT字段值
2. 若ACT为激活状态：
   - Modify Doc Link显示为红色文字
   - 显示提示信息"After def change detected. Document need to be modified."
   - 启用链接点击功能
3. 若ACT为非激活状态：
   - Modify Doc Link不显示或显示为普通样式
   - 不显示提示信息
   - 链接不可点击

### 4.4 文档下载功能
**功能说明**：提供VIN Plate文档下载功能

**操作步骤**：
1. 用户点击Generated document链接
2. 系统触发文件下载
3. 下载VPPS VIN PLATE创建批处理生成的.trf文件
4. 文件包含实际填充的数据值

### 4.5 跳转功能
**功能说明**：提供跳转到其他页面的链接功能

**操作步骤**：
1. **Analyze Rules链接**：
   - 用户点击Analyze Rules链接
   - 跳转到分析规则详情页面或弹出对话框显示规则信息
   
2. **Modify Doc Link链接**：
   - 仅在ADCA变更激活时可点击
   - 用户点击链接
   - 跳转到Modify Document页面进行文档修改
   
3. **Chassis no链接**：
   - 用户点击Chassis no链接
   - 跳转到Vehicle Specification页面（UD07），携带参数chassisNo（serie + 半角空格 + chassisNo）
   - 查看底盘详细信息

### 4.6 显示系统信息功能
**功能说明**：显示当前系统时间和程序版本

**操作步骤**：
1. 从服务器获取当前时间
2. 格式化显示为"YYYY-MM-DD HH:MM:SS"格式
3. 从程序配置中获取版本号
4. 显示在Date和HDoc version字段

## 5. 业务逻辑与校验规则 (Business Logic & Checks)

### 5.1 处理流程

#### 5.1.1 页面初始化流程
**开始**：页面加载

**处理步骤**：
- 从路由参数或上下文获取底盘号
- 调用UD04SelectGeneratedocumentApi（GET方法）
- 传递参数：chassisNo（底盘号）
- 等待API响应

**结果处理**：
- **成功**：
  - 解析API返回的数据
  - 将OM接收数据显示到对应字段（Chassis no、Ordernumber、Build week、Spec week、S-Note NO）
  - 将VDA接收数据显示到Market字段
  - 将KOLA轮胎主数据显示到Load Index字段
  - 若有S-Note信息，显示固定提示消息
  - 检查ADCA变更状态，决定Modify Doc Link的显示样式
  - 显示Template信息和Replacing parameters
  - 启用Generated document下载链接
  - 显示服务器当前时间和程序版本
  
- **失败（底盘号不存在）**：
  - 在Error message area显示"Chassis not found"
  - 其他字段保持为空或显示默认值
  
- **服务器错误**：
  - 在Error message area显示"System error. Please contact administrator."
  - 其他字段保持为空或显示默认值

#### 5.1.2 ADCA变更状态判断流程
**开始**：接收到API返回的ADCA变更数据

**处理步骤**：
- 读取HDOC_ADCA_CHANGE表的ACT字段值
- **若ACT为激活状态（如"ACTIVE"或"Y"）**：
  - Modify Doc Link文字颜色设置为红色
  - 显示提示信息"After def change detected. Document need to be modified."
  - 启用链接点击事件，点击后跳转到/ModifyDocument路由
  - 从HDOC_ADCA_MODIFICATION表获取VARIABLE和NEWVAL字段，显示在Replacing parameters区域
  
- **若ACT为非激活状态（如"INACTIVE"或"N"）**：
  - Modify Doc Link不显示或显示为灰色不可点击状态
  - 不显示提示信息
  - Replacing parameters区域显示为空

#### 5.1.3 文档下载流程
**开始**：用户点击Generated document链接

**处理步骤**：
- 触发浏览器下载功能
- 请求VPPS VIN PLATE创建批处理生成的.trf文件
- 文件路径从API返回数据中获取
- 浏览器自动下载文件到本地
- 文件名包含底盘号和文档类型信息

#### 5.1.4 Chassis no Link 押下時処理
**开始**：用户点击Chassis no Link

**处理步骤**：
- 从当前页面状态中获取serie（底盘系列号）和chassisNo（底盘号）
- 拼接参数：chassisNo = serie + 半角空格 + chassisNo（例："ABC12 1234567890"）
- 跳转到Vehicle Specification页面（UD07），路由为 /vehicle-specification
- 传递参数：{ chassisNo: "ABC12 1234567890" }

**结果反馈**：
- **成功**：UD07页面加载并显示该底盘号的车辆规格详细信息
- **失败**：不进行特殊处理，由UD07页面自身处理API调用异常

### 5.2 校验详细规格表

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 | 动作 |
|-----|---------|---------|---------|---------|------|
| 1 | API调用后 | 底盘号存在性 | API返回底盘号不存在 | "Chassis not found" | 显示错误消息，其他字段保持为空 |
| 2 | API调用后 | 网络/服务器 | API返回500或其他错误状态码 | "System error. Please contact administrator." | 显示错误消息，其他字段保持为空 |
| 3 | 页面加载时 | 用户登录状态 | 用户未登录或会话过期 | "Please login first" | 跳转到登录页面 |
| 4 | 点击Modify Doc Link时 | ADCA变更状态 | ACT字段为激活状态 | 无错误消息 | 允许跳转到Modify Document页面 |
| 5 | 点击Generated document时 | 文件存在性 | 文件不存在或路径无效 | "Document file not found" | 显示错误消息 |

## 6. 接口定义 (API Specification)

### UD04SelectGeneratedocumentApi
**功能**：根据底盘号查询并返回所有相关的文档信息和数据

**Method**：POST

**Endpoint**：/api/ud04/selectgenerateddocument

**Request**：
```json
{
  "chassisSeries": "string",
  "chassisNo": "string",
  "documentType": "string"
}
```

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :---: | :---: | :--- |
| chassisSeries | string | Y | 底盘系列号，最大长度5字符 |
| chassisNo | string | Y | 底盘号，最大长度10字符 |
| documentType | string | Y | 文档类型 |

**Response Success (200)**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "chassisNo": "1234567890",
    "serie": "ABC12",
    "ordernumber": "GOLF",
    "buildWeek": "2022W45",
    "specWeek": "2022W45",
    "market": "DE",
    "masterMarket": "-EU",
    "sNoteNo": "S-NOTE-001",
    "sNoteMessage": "The S-Notes above can affect homologation documents.",
    "loadIndex": "91",
    "analyzeRules": "View Rules",
    "modifyDocLink": "ACTIVE",
    "replacingParameters": "AD Change. Modifying:PARAM1; AD Change. Modifying:PARAM2",
    "date": "2022-12-02 05:11:45",
    "hdocVersion": "v1.0.0"
```

## 7. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message显示内容 |
|---------|---------|----------------|
| 网络连接失败 | 捕获网络异常，显示通用错误消息 | "System error. Please contact administrator." |
| API超时 | 设置超时时间（建议10秒），超时后显示错误 | "System error. Please contact administrator." |
| UD04SelectGeneratedocumentApi返回404 | 显示底盘号不存在消息 | "Chassis not found" |
| UD04SelectGeneratedocumentApi返回500 | 显示系统错误消息 | "System error. Please contact administrator." |
| JSON解析失败 | 捕获解析异常，显示系统错误 | "System error. Please contact administrator." |
| 未预期的JavaScript错误 | 使用try-catch包裹关键代码，记录错误日志，显示系统错误 | "System error. Please contact administrator." |
| 用户未登录 | 检查会话状态，跳转到登录页面 | "Please login first" |
| 文件下载失败 | 捕获下载异常，显示文件不存在消息 | "Document file not found" |
