## 2. 背景 (Background)

### 核心功能和目标
本模块用于生成车辆认证文档，主要功能包括：
- 接收用户输入的车辆底盘系列号、底盘号和文档类型
- 调用后端API获取可用的文档类型列表
- 验证输入的底盘号是否存在于系统中
- 根据查询结果生成相应的认证文档
- 提供重置和帮助功能

### 面向的用户群体
需要生成车辆认证文档的授权用户，如质量管理人员、文档管理员等

### 用户体验考虑
- 默认显示上次指定的条件，提高重复操作效率
- 清晰的错误提示信息
- 简洁的操作界面
- 支持快速重置表单

### 安全性要求
- 输入字符严格限制，防止注入攻击
- 底盘号必须存在于系统中才能继续操作
- 支持HTTPS安全传输

## 4. 功能描述 (Functional Description)

### 4.1 页面初始化功能
**功能说明**：页面加载时获取文档类型列表并恢复上次的查询条件

**操作步骤**：
1. 页面加载时，系统调用getDocumentType API获取文档类型列表
2. API返回成功后，将文档类型数据填充到Document type下拉列表中
3. 从本地存储（如localStorage或sessionStorage）读取上次保存的查询条件
4. 若存在上次保存的条件，则自动填充到Chassis series、Chassis no和Document type字段
5. 若不存在上次保存的条件，则保持字段为空

### 4.2 提交生成功能
**功能说明**：用户输入查询条件后点击Submit按钮，系统进行校验

**操作步骤**：
1. 用户在Chassis series字段输入底盘系列号（半角英字，最多5字符）
2. 用户在Chassis no字段输入底盘号（半角数字，最多10字符）
3. 用户从Document type下拉列表中选择文档类型
4. 用户点击Submit按钮
5. 系统执行前端校验（必填项检查）
6. 若前端校验通过，保存当前查询条件到本地存储
7. 跳转到UD04 GenerateDocument页面，请求参数包含chassisSeries、chassisNo和documentType
8. 底盘号存在性校验由UD04页面在初始化时调用UD04SelectGeneratedocumentApi完成

### 4.3 重置功能
**功能说明**：清空所有输入字段，恢复到初始状态

**操作步骤**：
1. 用户点击Reset按钮
2. 系统清空Chassis series字段的值
3. 系统清空Chassis no字段的值
4. 系统将Document type下拉列表重置为默认选项（空）
5. 系统清空Error message area区域的错误消息
6. 不清除本地存储中保存的上次查询条件

### 4.4 帮助功能
**功能说明**：点击跳转到 User Guide 页面（/Menu/UserGuide）

**操作步骤**：
1. 用户点击Help按钮
2. 系统显示帮助对话框或跳转到帮助页面
3. 帮助内容包括字段说明、操作流程、常见问题等

### 4.5 输入过滤功能
**功能说明**：对用户输入进行实时字符过滤，确保只接受允许的字符

**操作步骤**：
1. 用户在Chassis series字段输入时，系统实时检测每个字符
2. 若字符不是半角英字（a-z, A-Z），则自动过滤掉该字符
3. 用户在Chassis no字段输入时，系统实时检测每个字符
4. 若字符不是半角数字（0-9），则自动过滤掉该字符

## 5. 业务逻辑与校验规则 (Business Logic & Checks)

### 5.1 处理流程

#### 5.1.1 页面初始化流程
**开始**：页面加载

**处理步骤**：
- 调用getDocumentType API（GET方法）
- 等待API响应
- **成功**：
  - 将返回的文档类型列表填充到Document type下拉列表
  - 从本地存储读取上次保存的查询条件
  - 若存在保存的条件，自动填充到对应字段
- **失败**：
  - 在Error message area显示"Failed to load document types. Please try again."

#### 5.1.2 提交流程
**开始**：用户点击Submit按钮

**前置处理**：
- 获取Chassis series字段的当前值
- 获取Chassis no字段的当前值
- 获取Document type下拉列表的选中值

**前端校验 (Frontend Check)**：
- 若Chassis series为空：
  - 设置Error message = "Chassis series is required."
  - 终止流程，不调用API
  
- 若Chassis no为空：
  - 设置Error message = "Chassis no is required."
  - 终止流程，不调用API
  
- 若Document type未选择：
  - 设置Error message = "Document type is required."
  - 终止流程，不调用API

**页面跳转**：
- 不调用后端API
- 保存当前查询条件到本地存储（localStorage或sessionStorage）
- 清空Error message area
- 跳转到UD04 GenerateDocument页面，请求参数包含chassisSeries、chassisNo和documentType
- 底盘号存在性校验由UD04页面在初始化时调用UD04SelectGeneratedocumentApi完成

#### 5.1.3 输入过滤流程
**开始**：用户在Chassis series或Chassis no字段输入字符

**处理步骤**：
- **Chassis series字段**：
  - 检测输入字符是否匹配正则表达式 [a-zA-Z]
  - 若匹配，保留该字符
  - 若不匹配，过滤掉该字符（不显示在输入框中）
  
- **Chassis no字段**：
  - 检测输入字符是否匹配正则表达式 [0-9]
  - 若匹配，保留该字符
  - 若不匹配，过滤掉该字符

## 6. 接口定义 (API Specification)

### getDocumentType API
**功能**：获取可用的文档类型列表

**Method**：GET

**Endpoint**：/api/documenttypes

**Request**：无请求参数

**Response Success (200)**：
```json
[
  {
    "doctype": "string",
    "description": "string"
  }
]
```

**Response Error (500)**：
```json
{
  "code": 500,
  "message": "Internal server error",
  "data": null
}
```

| 异常场景 | 处理方式 | Message显示内容 |
