# HomologationVariables 详细设计提示词

## 1. 基本信息
- **模块名称**：HomologationVariablesPage
- **文档编号**: DES-HomologationVariablesPage-001
- **作成日期**：2026-05-20

## 2. 背景 (Background)

### 核心功能和目标
本模块用于管理车辆认证系统的用户自定义规则变量，主要功能包括：
- 显示和搜索认证变量列表
- 新增认证变量规则
- 更新现有认证变量规则
- 删除认证变量规则
- 提供Product Class、Market下拉列表选择
- 验证Variable字段是否符合TEMPLATE格式规范

### 面向的用户群体
需要管理认证变量的授权用户，如系统管理员、质量管理人员等

### 用户体验考虑
- 清晰的数据展示表格
- 便捷的新增、更新、删除操作
- 明确的错误提示信息
- 支持快速清空表单

### 安全性要求
- 需要用户登录认证后才能访问
- 输入字符严格限制，防止注入攻击
- 主键冲突检测，避免重复数据
- 支持HTTPS安全传输

## 4. 功能描述 (Functional Description)

### 4.1 页面初始化功能
**功能说明**：页面加载时获取Product Class和Market下拉列表数据，以及Variable变量列表

**操作步骤**：
1. 页面加载时，调用UD08SelectProductclassmaster API获取Product Class列表
2. 调用UD08SelectMarketmaster API获取Market列表
3. 调用UD08SelectHdocvariables API获取HDOC_VARIABLES表中的所有VARIABLE字段
4. 将数据显示到对应的下拉列表中
5. 清空其他输入字段
6. 若发生错误，显示错误消息

### 4.2 搜索功能
**功能说明**：用户输入搜索条件后点击Search按钮，跳转到搜索结果页面

**操作步骤**：
1. 用户可选择性输入搜索条件（Product class、Number、Market等）
2. 用户点击Search按钮
3. 系统将搜索条件作为参数传递
4. 跳转到Homologation Variables搜索结果页面
5. 在搜索结果页面显示匹配的变量规则列表

### 4.3 清空功能
**功能说明**：清空所有输入字段，恢复到初始状态

**操作步骤**：
1. 用户点击Clear按钮
2. 系统将Product class下拉列表重置为默认选项（空）
3. 系统将Market下拉列表重置为默认选项（空）
4. 清空Number文本框
5. 清空Variable文本框
6. 清空Value文本框
7. 清空Variant string.1文本框
8. 清空Variant string.2文本框
9. 清空Comments文本框
10. 清空Add、Delete、Created by user、Date字段
11. 清空错误消息区域

### 4.4 新增功能
**功能说明**：用户输入新记录后点击Add按钮，系统进行校验并保存到数据库

**操作步骤**：
1. 用户选择Product class（必填）
2. 用户输入Number（必填，半角数字）
3. 用户选择Market（必填）
4. 用户输入Variable（可选）
5. 用户输入Value（可选）
6. 用户输入Variant string.1（可选）
7. 用户输入Variant string.2（可选）
8. 用户输入Comments（可选）
9. 用户点击Add按钮
10. 系统执行前端校验（必填项检查）
11. 若前端校验通过，调用UD08Add API
12. API执行后端校验（主键冲突、Variable存在性）
13. 根据API返回结果显示相应消息
14. 成功：显示成功消息，可选择清空表单或保持
15. 失败：显示错误消息，保持当前输入

### 4.5 更新功能
**功能说明**：用户修改现有记录后点击Update按钮，系统进行校验并更新数据库

> **前提说明**：从UD09搜索结果页点击某条记录跳转回本页面时，会将该记录的原始主键值（originalProductClass、originalNumber、originalMarket）通过路由参数传递过来，并在前端临时保存。更新时以此作为修正元的标识，不允许修改主键。

**操作步骤**：
1. 用户选择Product class（必填）
2. 用户输入Number（必填，半角数字）
3. 用户选择Market（必填）
4. 用户修改其他字段内容
5. 用户点击Update按钮
6. 系统执行前端校验（必填项检查）
7. **主键变更校验（前端）**：比较当前主键值与从UD09传入的原始主键值（originalProductClass、originalNumber、originalMarket），若不一致则显示"Primary key cannot be updated."并终止流程
8. 若前端校验通过，调用UD08Update API
9. 传递参数：Product class、Number、Market及其他字段
10. API执行后端校验（记录存在性、Variable存在性）
11. 根据API返回结果显示相应消息
12. 成功：显示成功消息
13. 失败：显示错误消息，保持当前输入

### 4.6 删除功能
**功能说明**：用户指定要删除的记录后点击Delete按钮，系统进行校验并从数据库删除

**操作步骤**：
1. 用户选择Product class（必填）
2. 用户输入Number（必填，半角数字）
3. 用户选择Market（必填）
4. 用户点击Delete按钮
5. 系统执行前端校验（必填项检查）
6. 若前端校验通过，调用UD08Delete API
7. 传递参数：Product class、Number、Market
8. API执行后端校验（记录存在性）
9. 根据API返回结果显示相应消息
10. 成功：显示成功消息，清空表单
11. 失败：显示错误消息，保持当前输入

### 4.7 输入过滤功能
**功能说明**：对用户输入进行实时字符过滤，确保只接受允许的字符

**操作步骤**：
1. Number字段：仅允许半角数字（0-9），最大长度10字符
2. 其他TextField字段：允许半角英数字+记号
3. Pull-down List字段：从预定义列表中选择
4. 实时过滤非法字符

## 5. 业务逻辑与校验规则 (Business Logic & Checks)

### 5.1 处理流程

#### 5.1.1 页面初始化流程
**开始**：页面加载

**处理步骤**：
- 调用UD08SelectProductclassmaster API（GET方法）
- 调用UD08SelectMarketmaster API（GET方法）
- 调用UD08SelectHdocvariables API（GET方法）
- 等待所有API响应

**结果处理**：
- **成功**：
  - 将Product Class列表填充到Product class下拉列表
  - 将Market列表填充到Market下拉列表
  - 将VARIABLE列表存储到内存中，用于后续校验
  
- **失败**：
  - 显示"Failed to load data. Please try again."
  - 记录错误日志

#### 5.1.2 新增流程
**开始**：用户点击Add按钮

**前置处理**：
- 获取Product class字段的当前值
- 获取Number字段的当前值
- 获取Market字段的当前值
- 获取其他字段的当前值

**前端校验 (Frontend Check)**：
- 若Product class未选择：
  - 设置Error message = "Product class is required."
  - 终止流程，不调用API
  
- 若Number为空：
  - 设置Error message = "Number is required."
  - 终止流程，不调用API
  
- 若Number包含非数字字符：
  - 设置Error message = "Number must be digits only."
  - 终止流程，不调用API
  
- 若Market未选择：
  - 设置Error message = "Market is required."
  - 终止流程，不调用API

**Variable特殊校验**：
- 若Variable字段以"TEMPLATE-"开头：
  - 去掉"TEMPLATE-"前缀
  - 检查剩余部分是否存在于HDOC_VARIABLES列表中
  - 若不存在：
    - 设置Error message = "Variant does not exist, Please enter the correct content"
    - 终止流程，不调用API

**API调用 (Backend Check)**：
- 调用UD08Add API（POST方法）
- 请求参数包含所有字段值
- 等待API响应

**后端校验**：
- 检查Product class、Number、Market组合是否已存在（主键冲突）
  - 若存在：返回错误"Primary key conflict, Please enter the correct content"
  
- 再次验证Variable存在性（若以TEMPLATE-开头）
  - 若不存在：返回错误"Variant does not exist, Please enter the correct content"

**结果处理**：
- **成功**：
  - 显示成功消息"Record added successfully."
  - 可选择清空表单或保持当前输入
  
- **失败（主键冲突）**：
  - 设置Error message = "Primary key conflict, Please enter the correct content"
  - Error message显示为错误级别
  - 保持当前页面，不清空输入框
  
- **失败（Variable不存在）**：
  - 设置Error message = "Variant does not exist, Please enter the correct content"
  - Error message显示为错误级别
  - 保持当前页面
  
- **服务器错误**：
  - 设置Error message = "System error. Please contact administrator."
  - Error message显示为错误级别
  - 保持当前页面

#### 5.1.3 更新流程
**开始**：用户点击Update按钮

**前置处理**：
- 获取Product class、Number、Market字段的当前值
- 获取其他字段的当前值

**前端校验 (Frontend Check)**：
- 同新增流程的前端校验

**Variable特殊校验**：
- 同新增流程的Variable校验

**API调用 (Backend Check)**：
- 调用UD08Update API（POST或PUT方法）
- 请求参数包含Product class、Number、Market及其他字段
- 等待API响应

**前端校验（新增-主键变更检查）**：
- 获取当前表单中的Product class、Number、Market值
- 与从UD09搜索结果页传入的原始主键值（originalProductClass、originalNumber、originalMarket）进行比较
- 若任意主键字段发生变更：
  - 设置Error message = "Primary key cannot be updated."
  - 终止流程，不调用后端API

**后端校验**：
- 检查Product class、Number、Market组合的记录是否存在
  - 若不存在：返回错误"Data does not exist, Please enter the correct content"
  
- 验证Variable存在性（若以TEMPLATE-开头）
  - 若不存在：返回错误"Variant does not exist, Please enter the correct content"

**结果处理**：
- **成功**：
  - 显示成功消息"Record updated successfully."
  
- **失败（记录不存在）**：
  - 设置Error message = "Data does not exist, Please enter the correct content"
  - Error message显示为错误级别
  
- **失败（Variable不存在）**：
  - 设置Error message = "Variant does not exist, Please enter the correct content"
  - Error message显示为错误级别
  
- **服务器错误**：
  - 设置Error message = "System error. Please contact administrator."
  - Error message显示为错误级别

#### 5.1.4 删除流程
**开始**：用户点击Delete按钮

**前置处理**：
- 获取Product class、Number、Market字段的当前值

**前端校验 (Frontend Check)**：
- 若Product class未选择：
  - 设置Error message = "Product class is required."
  - 终止流程，不调用API
  
- 若Number为空：
  - 设置Error message = "Number is required."
  - 终止流程，不调用API
  
- 若Market未选择：
  - 设置Error message = "Market is required."
  - 终止流程，不调用API

**API调用 (Backend Check)**：
- 调用UD08Delete API（POST或DELETE方法）
- 请求参数包含Product class、Number、Market
- 等待API响应

**后端校验**：
- 检查Product class、Number、Market组合的记录是否存在
  - 若不存在：返回错误"Data does not exist, Please enter the correct content"

**结果处理**：
- **成功**：
  - 显示成功消息"Record deleted successfully."
  - 清空所有输入字段
  
- **失败（记录不存在）**：
  - 设置Error message = "Data does not exist, Please enter the correct content"
  - Error message显示为错误级别
  - 保持当前页面
  
- **服务器错误**：
  - 设置Error message = "System error. Please contact administrator."
  - Error message显示为错误级别
  - 保持当前页面

#### 5.1.5 搜索流程
**开始**：用户点击Search按钮

**处理步骤**：
- 获取当前表单中的所有字段值作为搜索条件

## 6. 接口定义 (API Specification)

### 6.1 UD08SelectProductclassmaster
**功能**：获取Product Class下拉列表数据

**Method**：GET

**Endpoint**：/api/ud08/selectproductclassmaster

**Request**：无请求参数

**Response Success (200)**：
```json
[
  {
    "pc": "string",
    "description": "string"
  }
]

**Response Error (500)**：
```json
{
  "message": "Internal server error"
}
```

**功能**：获取Market下拉列表数据

**Method**：GET

**Endpoint**：/api/ud08/selectmarketmaster

**Request**：无请求参数

**Response Success (200)**：
```json
[
  {
    "market": "string",
    "description": "string"
  }
]

**Response Error (500)**：
```json
{
  "message": "Internal server error"

## 7. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message显示内容 |
|---------|---------|----------------|
| 网络连接失败 | 捕获网络异常，显示通用错误消息 | "System error. Please contact administrator." |
| API超时 | 设置超时时间（建议10秒），超时后显示错误 | "System error. Please contact administrator." |
| 初始化API失败 | 显示加载数据失败消息 | "Failed to load data. Please try again." |
| UD08Add返回409 | 显示主键冲突消息 | "Primary key conflict, Please enter the correct content" |
| UD08Add返回400 | 显示Variable不存在消息 | "Variant does not exist, Please enter the correct content" |
| UD08Update返回404 | 显示记录不存在消息 | "Data does not exist, Please enter the correct content" |
| Update主键被修改 | 前端校验拦截（与UD09传入的原始主键值比较） | "Primary key cannot be updated." |
| UD08Update返回404 | 显示记录不存在消息 | "Data does not exist, Please enter the correct content" |
| UD08Update返回400 | 显示Variable不存在消息 | "Variant does not exist, Please enter the correct content" |
| UD08Delete返回404 | 显示记录不存在消息 | "Data does not exist, Please enter the correct content" |
| JSON解析失败 | 捕获解析异常，显示系统错误 | "System error. Please contact administrator." |
| 未预期的JavaScript错误 | 使用try-catch包裹关键代码，记录错误日志 | "System error. Please contact administrator." |
