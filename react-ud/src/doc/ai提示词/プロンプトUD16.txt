# AD Change 详细设计提示词

## 1. 基本信息
- **模块名称**：ADChange
- **文档编号**: DES-ADChange-001
- **作成日期**：2026-05-20

## 2. 背景 (Background)
本模块的核心功能和目标：提供AD Change管理功能，用户可以对Serie-Chnr进行添加、删除和检查操作。支持管理ADCA变更信息的增删改查

面向的用户群体：车辆认证相关人员、需要管理ADCA变更信息的业务人员

用户体验方面的考虑：简洁的输入界面；清晰的操作按钮布局；及时的校验反馈

安全性或特殊要求：需要用户登录认证；所有操作需进行存在性校验

## 4. 功能描述 (Functional Description)

### 4.1 页面初始化
功能说明：页面加载时显示空的输入表单
操作步骤：
1. 页面加载完成后，初始化Serie-Chnr输入框为空
2. 初始化Desc输入框为空
3. 所有按钮处于激活状态
4. 不自动加载任何数据列表

### 4.2 ADD按钮点击处理
功能说明：添加新的ADCA变更记录
操作步骤：
1. 用户输入Serie-Chnr和Desc字段
2. 用户点击ADD按钮
3. 前端校验输入字段是否符合要求
4. 先调用UD16ADChangeApi执行CHECK操作，检查该Serie-Chnr是否已存在
5. 若存在：在错误消息区域显示"该Serie-Chnr已存在"，终止流程
6. 若不存在：调用UD16ADChangeApi执行ADD操作，API内部调用UD16InsertHdocAdcaChange插入数据到HDOC_ADCA_CHANGE表
7. 添加成功后，清空输入字段，显示成功消息

### 4.3 DELETE按钮点击处理
功能说明：删除指定的ADCA变更记录
操作步骤：
1. 用户输入要删除的Serie-Chnr
2. 用户点击DELETE按钮
3. 前端校验Serie-Chnr是否为空
4. 调用UD16ADChangeApi执行删除操作
5. API内部调用UD16UpdateHdocAdcaChange更新记录状态或删除记录
6. 删除成功后，清空输入字段
7. 显示成功消息

### 4.4 CHECK按钮点击处理
功能说明：检查ADCA变更记录的存在性
操作步骤：
1. 用户输入Serie-Chnr
2. 用户点击CHECK按钮
3. 前端校验Serie-Chnr是否为空
4. 调用UD16ADChangeApi执行CHECK操作，API内部调用UD16SelectHdocAdcaChange查询HDOC_ADCA_CHANGE表
5. 若记录存在：在画面弹窗（Modal/Popup）中显示对应的数据详情（Serie-Chnr、Desc、Status等）
6. 若记录不存在：在画面弹窗中显示"数据不存在"

## 5. 业务逻辑与校验规则 (Business Logic & Checks)

### 5.1 处理流程

**ADD操作流程：**
开始：用户点击ADD按钮
前置处理：获取Serie-Chnr和Desc输入值
空值校验等 (Frontend Check)：
若Serie-Chnr为空：
设置Message = "请输入Serie-Chnr"
终止流程
若Serie-Chnr长度超过15字符：
设置Message = "Serie-Chnr长度不能超过15字符"
终止流程
若Desc长度超过4000字符：
设置Message = "描述长度不能超过4000字符"
终止流程
API调用 (Backend Check)：
1. 先调用UD16ADChangeApi执行UD16SelectHdocAdcaChange（CHECK），检查Serie-Chnr是否存在
2. 若存在：返回错误"该Serie-Chnr已存在"，终止流程
3. 若不存在：调用UD16ADChangeApi执行UD16InsertHdocAdcaChange（ADD），插入数据
结果处理：
成功：清空输入字段，显示成功消息
失败（已存在）：在错误消息区域显示"该Serie-Chnr已存在"
失败（其他）：显示错误消息

**DELETE操作流程：**
开始：用户点击DELETE按钮
前置处理：获取Serie-Chnr输入值
空值校验等 (Frontend Check)：
若Serie-Chnr为空：
设置Message = "请输入要删除的Serie-Chnr"
终止流程
API调用 (Backend Check)：
调用UD16ADChangeApi
执行UD16UpdateHdocAdcaChange
结果处理：
成功：清空输入字段，显示成功消息
失败：显示错误消息

**CHECK操作流程：**
开始：用户点击CHECK按钮
前置处理：获取Serie-Chnr输入值
空值校验等 (Frontend Check)：
若Serie-Chnr为空：
设置Message = "请输入要检查的Serie-Chnr"
终止流程
API调用 (Backend Check)：
调用UD16ADChangeApi
执行UD16SelectHdocAdcaChange
结果处理：
记录存在：在画面弹窗（Modal/Popup）中显示该记录的数据详情
记录不存在：在画面弹窗中显示"数据不存在"

### 5.2 校验详细规格表

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 (Message Content) | 动作 |
|-----|---------|---------|---------|--------------------------|------|
| 1 | 点击ADD按钮时 | Serie-Chnr | 为空 | 请输入Serie-Chnr | 阻止提交，显示错误 |
| 2 | 点击ADD按钮时 | Serie-Chnr | 长度超过15字符 | Serie-Chnr长度不能超过15字符 | 阻止提交，显示错误 |
| 3 | 点击ADD按钮时 | Desc | 长度超过4000字符 | 描述长度不能超过4000字符 | 阻止提交，显示错误 |
| 4 | ADD前CHECK API返回后 | 存在性检查 | 该Serie-Chnr已存在 | 该Serie-Chnr已存在 | 在错误消息区域显示，终止流程，不执行ADD |
| 5 | 点击DELETE按钮时 | Serie-Chnr | 为空 | 请输入要删除的Serie-Chnr | 阻止提交，显示错误 |
| 6 | 点击CHECK按钮时 | Serie-Chnr | 为空 | 请输入要检查的Serie-Chnr | 阻止提交，显示错误 |
| 7 | CHECK API返回后 | 查询结果 | 记录存在 | - | 在画面弹窗中显示该记录的数据详情 |
| 8 | CHECK API返回后 | 查询结果 | 记录不存在 | 数据不存在 | 在画面弹窗中显示"数据不存在" |

## 6. 接口定义 (API Specification)

### UD16ADChangeApi

统一API名称空间，包含以下方法：**UD16SelectHdocAdcaChange**（检查记录存在性）、**UD16InsertHdocAdcaChange**（添加记录）、**UD16UpdateHdocAdcaChange**（逻辑删除）。

---

### 6.1 UD16SelectHdocAdcaChange - 检查记录存在性

**功能**：根据Serie-Chnr查询HDOC_ADCA_CHANGE表，检查记录是否存在

**Method**：POST

**Endpoint**：/api/adchange/process

**Request**：
```json
{
  "operation": "CHECK",
  "serieChnr": "string (最大15字符，必填)"
}
```

**Response Success (200) - 记录存在**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "serieChnr": "string",
    "desc": "string",
    "status": "string"
  }
}
```

**Response Success (200) - 记录不存在**：
```json
{
  "code": 200,
  "message": "数据不存在",
  "data": null
}
```

**Response Error (500)**：
```json
{
  "code": 500,
  "message": "操作失败，请稍后重试"
}
```

### 6.2 UD16InsertHdocAdcaChange - 添加记录

**功能**：向HDOC_ADCA_CHANGE表插入新的ADCA变更记录。先检查是否存在，若已存在则返回错误，不存在则执行插入。

**Method**：POST

**Endpoint**：/api/adchange/process

**Request**：
```json
{
  "operation": "ADD",
  "serieChnr": "string (最大15字符，必填)",
  "desc": "string (最大4000字符)"
}
```

**Response Success (200)**：
```json
{
  "code": 200,
  "message": "添加成功",
  "data": null
}
```

**Response Error (409) - 记录已存在**：
```json
{
  "code": 409,
  "message": "该Serie-Chnr已存在",
  "data": null
}
```

**Response Error (500)**：
```json
{
  "code": 500,
  "message": "操作失败，请稍后重试"
}
```

### 6.3 UD16UpdateHdocAdcaChange - 逻辑删除

**功能**：逻辑删除ADCA变更记录，更新ACT设置为'N'

**Method**：POST

**Endpoint**：/api/adchange/process

**Request**：
```json
{
  "operation": "DELETE",
  "serieChnr": "string (最大15字符，必填)"
}
```

**Response Success (200)**：
```json
{
  "code": 200,
  "message": "删除成功",
  "data": null
}
```

**Response Error (500)**：
```json
{
  "code": 500,
  "message": "操作失败，请稍后重试"
}
```

## 7. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message显示内容 |
|---------|---------|----------------|
| 网络连接失败 | 捕获异常，显示友好提示 | 网络连接失败，请稍后重试 |
| API超时 | 设置超时时间，超时后提示 | 请求超时，请检查网络连接 |
| 数据库异常 | 记录日志，返回通用错误 | 系统异常，请联系管理员 |
| 权限不足 | 检查用户登录状态 | 请先登录后再操作 |
