## 1. 背景 (Background)

本模块用于展示车辆的详细规格信息，基于Chassis编号从多个数据源获取并整合车辆配置数据。

- **目标**：显示车辆基本信息（型号、制造周、VIN等）、展示发动机编号及符号信息、显示国家运营区域与产品类型、提供S-Note编号信息、支持通过tooltip查看KOLA Variant的描述信息。
- **面向用户**：车辆配置工程师、质量审核人员和生产准备人员。
- **用户体验**：信息清晰、字段排列合理、关键信息突出显示。
- **安全性**：仅读取已授权访问的数据，不涉及敏感操作或写入。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

#### 3.1.1 页面初始化流程

1. **开始**：页面加载触发。
2. **前置处理**：
   - 从路由参数中获取完整Chassis编号（格式：serie + 半角空格 + chassisNo，如"ABC12 1234567890"）。
   - 将完整Chassis编号作为`chassisNo`参数调用`UD07VehicleSpecificationApi`获取车辆规格信息。
3. **空值校验 (Frontend Check)**：
   - 若Chassis编号为空：设置Message = "未指定Chassis编号"，**终止**流程。
4. **结果处理**：
   - **成功**：
     - Engine no固定值"A01"设定。
     - SYMBOL_STR处理：取Symbol先頭から8桁まで取得。8桁不足の場合、左寄せ半角スペースで補足。
     - 排序处理：按FUNCTION_GROUP（左寄せ半角スペースで4桁まで補足）+ FAMILY_ID（3桁）排序显示。
     - 正常渲染所有标签与tooltip。
   - **失败**：显示"系统内部错误，请联系管理员"。

### 3.2 校验详细规格表

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 (Message Content) | 动作 |
| :-: | :---: | :---: | :--- | :--- | :---: |
| 1 | 页面加载前 | Chassis编号 | 为空 | `未指定Chassis编号` | 终止流程 |
| 2 | 查询变体信息时 | HDOC_REC_DATA_VDA_VARIANTS | 无匹配记录 | `未找到对应变体信息` | Engine no和SYMBOL_STR设为空 |
| 3 | 查询Symbol信息时 | HDOC_REC_DATA_KOLA_VARIANT | 无匹配记录 | `无法获取发动机符号信息` | Engine no设为"N/A"，SYMBOL_STR设为"N/A" |

## 4. 接口定义 (API Specification)

### 4.1 UD07VehicleSpecificationApi

- **功能**：获取车辆规格信息，包括型号、制造周、VIN、发动机编号、变体信息等。
- **Method**：`GET`
- **Endpoint**：`/api/v1/ud07/vehiclespecification`

#### Request Parameters

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :---: | :--- |
| chassisNo | String | Y | 底盘编号（serie + 半角空格 + chassisNo，如"JPCT 013945"） |

**请求示例**：`/api/v1/ud07/vehiclespecification?chassisNo=JPCT%20013945`

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "chassisInfo": {
      "chassisNo": "JPCT 013945",
      "model": "UD-HDE",
      "buildWeek": "1617",
      "productType": "EM 64 R",
      "vin": "JPCZZ30D8GT013945",
      "countryOfOperation": "IDN"
    },
    "engineInfo": {
      "engineNo": "A01",
      "symbolStr": "FTLI-150   ",
      "description": "Front load index: FTLI-150"
    },
    "sNotes": [
      {
        "noteNo": "S1610111",
        "description": "Front load index: FTLI-150"
      }
    ]
  }
}
```

#### Response Error (400)

```json
{
  "code": 400,
  "message": "Invalid chassis number",
  "data": null
}
```

#### Response Error (500)

```json
{
  "code": 500,
  "message": "Internal server error",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :--- | :--- | :--- |
| **Chassis编号为空** | 终止流程 | `未指定Chassis编号` |
| **变体信息未找到** | 显示提示，字段留空 | `未找到对应变体信息` |
| **Symbol信息未找到** | 显示"N/A" | `无法获取发动机符号信息` |
| **API调用失败** | 显示通用错误 | `系统内部错误，请联系管理员` |
| **网络超时** | 捕获超时异常 | `系统内部错误，请联系管理员` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用React State管理所有从API返回的显示数据。
   - 所有字段为只读展示，不支持编辑操作。
2. **数据来源**：
   - 页面数据通过UD07VehicleSpecificationApi一次性获取，前端仅做展示处理。
   - Engine no和SYMBOL_STR的获取逻辑涉及多表联合查询，由后端API封装处理。
3. **Tooltip实现**：
   - DESCRIPTION字段使用React的Tooltip组件实现，鼠标悬停时显示描述内容。
   - Tooltip内容从API返回数据中的engineInfo.description获取。
4. **SYMBOL_STR格式化**：
   - 取Symbol前8位，不足时左补半角空格。
   - 排序规则：FUNCTION_GROUP（左补至4位）+ FAMILY_ID（3位）。
