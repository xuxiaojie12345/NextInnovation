## 1. 背景 (Background)

本模块提供AD Change管理功能，用户可以对Serie-Chnr进行添加、删除和检查操作，支持管理ADCA变更信息的增删改查。

- **目标**：提供ADCA变更记录的添加、删除和检查功能。
- **面向用户**：车辆认证相关人员、需要管理ADCA变更信息的业务人员。
- **用户体验**：简洁的输入界面、清晰的操作按钮布局、及时的校验反馈。
- **安全性**：需要用户登录认证、所有操作需进行存在性校验。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

#### 3.1.1 页面初始化

1. **开始**：页面加载。
2. 初始化Serie-Chnr和Desc输入框为空。
3. 所有按钮处于激活状态。
4. 不自动加载任何数据列表。

#### 3.1.2 ADD操作流程

1. **开始**：用户点击ADD按钮。
2. **前置处理**：获取Serie-Chnr和Desc输入值。
3. **前端校验**：
   - 若Serie-Chnr为空：显示"请输入Serie-Chnr"，**终止**。
   - 若Serie-Chnr长度超过15字符：显示"Serie-Chnr长度不能超过15字符"，**终止**。
   - 若Desc长度超过4000字符：显示"描述长度不能超过4000字符"，**终止**。
4. **存在性检查（后端）**：先调用`UD16ADChangeApi`的`UD16SelectHdocAdcaChange`方法，operation为"CHECK"，检查该Serie-Chnr是否已存在。
5. 若已存在：在错误消息区域显示"该Serie-Chnr已存在"，**终止**流程。
6. 若不存在：调用`UD16ADChangeApi`的`UD16InsertHdocAdcaChange`方法，operation为"ADD"，插入数据。
7. **结果处理**：成功则清空输入字段显示成功消息；失败则显示错误消息。

#### 3.1.3 DELETE操作流程

1. **开始**：用户点击DELETE按钮。
2. **前置处理**：获取Serie-Chnr输入值。
3. **前端校验**：若Serie-Chnr为空，显示"请输入要删除的Serie-Chnr"，**终止**。
4. **API调用**：调用`UD16ADChangeApi`，operation为"DELETE"，执行`UD16UpdateHdocAdcaChange`。
5. **结果处理**：同ADD操作。

#### 3.1.4 CHECK操作流程

1. **开始**：用户点击CHECK按钮。
2. **前置处理**：获取Serie-Chnr输入值。
3. **前端校验**：若Serie-Chnr为空，显示"请输入要检查的Serie-Chnr"，**终止**。
4. **API调用**：调用`UD16ADChangeApi`的`UD16SelectHdocAdcaChange`方法，operation为"CHECK"。
5. **结果处理**：
   - **记录存在**：在画面弹窗（Modal/Popup）中显示该记录的数据详情。
   - **记录不存在**：在画面弹窗中显示"数据不存在"。

### 3.2 校验详细规格表

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 (Message Content) | 动作 |
| :-: | :---: | :---: | :--- | :--- | :---: |
| 1 | 点击ADD按钮时 | Serie-Chnr | 为空 | `请输入Serie-Chnr` | 阻止提交，显示错误 |
| 2 | 点击ADD按钮时 | Serie-Chnr | 长度超过15字符 | `Serie-Chnr长度不能超过15字符` | 阻止提交，显示错误 |
| 3 | 点击ADD按钮时 | Desc | 长度超过4000字符 | `描述长度不能超过4000字符` | 阻止提交，显示错误 |
| 4 | ADD前CHECK返回后 | Serie-Chnr存在性 | 该Serie-Chnr已存在 | `该Serie-Chnr已存在` | 在错误消息区域显示，终止流程，不执行ADD |
| 5 | 点击DELETE按钮时 | Serie-Chnr | 为空 | `请输入要删除的Serie-Chnr` | 阻止提交，显示错误 |
| 6 | 点击CHECK按钮时 | Serie-Chnr | 为空 | `请输入要检查的Serie-Chnr` | 阻止提交，显示错误 |
| 7 | CHECK API返回后 | 查询结果 | 记录存在 | - | 在画面弹窗中显示该记录的数据详情 |
| 8 | CHECK API返回后 | 查询结果 | 记录不存在 | `数据不存在` | 在画面弹窗中显示"数据不存在" |

## 4. 接口定义 (API Specification)

### UD16ADChangeApi

统一API名称空间，包含以下方法：**UD16SelectHdocAdcaChange**（检查记录存在性）、**UD16InsertHdocAdcaChange**（添加记录）、**UD16UpdateHdocAdcaChange**（逻辑删除）。

---

### 4.1 UD16SelectHdocAdcaChange - 检查记录存在性

**功能**：根据Serie-Chnr查询HDOC_ADCA_CHANGE表，检查记录是否存在

- **Method**：`POST`
- **Endpoint**：`/api/adchange/process`

#### Request

```json
{
  "operation": "CHECK",
  "serieChnr": "string (最大15字符，必填)"
}
```

#### Response Success (200) - 记录存在

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "serieChnr": "string",
    "desc": "string",
    "status": "string"
  }
}
```

#### Response Success (200) - 记录不存在

```json
{
  "code": 200,
  "message": "数据不存在",
  "data": null
}
```

#### Response Error (500)

```json
{
  "code": 500,
  "message": "操作失败，请稍后重试"
}
```

---

### 4.2 UD16InsertHdocAdcaChange - 添加记录

**功能**：向HDOC_ADCA_CHANGE表插入新的ADCA变更记录。先检查是否存在，若已存在则返回错误，不存在则执行插入。

- **Method**：`POST`
- **Endpoint**：`/api/adchange/process`

#### Request

```json
{
  "operation": "ADD",
  "serieChnr": "string (最大15字符，必填)",
  "desc": "string (最大4000字符)"
}
```

#### Response Success (200)

```json
{
  "code": 200,
  "message": "添加成功",
  "data": null
}
```

#### Response Error (409) - 记录已存在

```json
{
  "code": 409,
  "message": "该Serie-Chnr已存在",
  "data": null
}
```

#### Response Error (500)

```json
{
  "code": 500,
  "message": "操作失败，请稍后重试"
}
```

---

### 4.3 UD16UpdateHdocAdcaChange - 逻辑删除

**功能**：逻辑删除ADCA变更记录，更新ACT设置为'N'

- **Method**：`POST`
- **Endpoint**：`/api/adchange/process`

#### Request

```json
{
  "operation": "DELETE",
  "serieChnr": "string (最大15字符，必填)"
}
```

#### Response Success (200)

```json
{
  "code": 200,
  "message": "删除成功",
  "data": null
}
```

#### Response Error (500)

```json
{
  "code": 500,
  "message": "操作失败，请稍后重试"
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :--- | :--- | :--- |
| **网络连接失败** | 捕获异常，显示友好提示 | `网络连接失败，请稍后重试` |
| **API超时** | 设置超时时间，超时后提示 | `请求超时，请检查网络连接` |
| **数据库异常** | 记录日志，返回通用错误 | `系统异常，请联系管理员` |
| **权限不足** | 检查用户登录状态 | `请先登录后再操作` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用React State管理Serie-Chnr和Desc输入值、错误消息。
   - 所有按钮在API调用期间应设为`disabled`，防止重复提交。
2. **输入限制**：
   - Serie-Chnr最大长度15字符。
   - Desc最大长度4000字符。
3. **操作类型**：所有按钮操作都调用同一个API端点，通过`operation`参数区分不同功能。
4. **ADD存在性检查**：点击ADD按钮时，先调用CHECK检查Serie-Chnr是否存在，若存在则显示错误"该Serie-Chnr已存在"，不存在则执行ADD插入。
5. **CHECK结果**：
   - 记录存在时在画面弹窗（Modal/Popup）中显示该记录的数据详情。
   - 记录不存在时在画面弹窗中显示"数据不存在"。
