## 1. 背景 (Background)

本模块用于管理车辆认证系统的用户自定义规则变量，主要功能包括显示和搜索认证变量列表、新增/更新/删除认证变量规则、提供Product Class和Market下拉列表选择、验证Variable字段是否符合TEMPLATE格式规范。

- **目标**：提供认证变量的完整CRUD（增删改查）管理功能。
- **面向用户**：需要管理认证变量的授权用户，如系统管理员、质量管理人员等。
- **用户体验**：清晰的数据展示表格、便捷的新增/更新/删除操作、明确的错误提示信息、支持快速清空表单。
- **安全性**：需要用户登录认证后才能访问、输入字符严格限制防止注入攻击、主键冲突检测避免重复数据、支持HTTPS安全传输。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

#### 3.1.1 页面初始化流程

1. **开始**：页面加载。
2. 调用`UD08HomologationVariablesApi`的`UD08SelectProductclassmaster`方法获取Product Class列表。
3. 调用`UD08HomologationVariablesApi`的`UD08SelectMarketmaster`方法获取Market列表。
4. 调用`UD08HomologationVariablesApi`的`UD08SelectHdocvariables`方法获取HDOC_VARIABLES表中的所有VARIABLE字段。
5. 将数据填充到对应的下拉列表中，清空其他输入字段。
6. 每个字段前方的运算符下拉框默认设置为`=`。
7. **从UD09返回时处理**：
   - 若从UD09（搜索结果页）携带记录数据返回本页面，则接收路由参数中的原始主键值（originalProductClass、originalNumber、originalMarket）。
   - 将这些原始主键值临时保存到State中，用于后续Update操作时的主键变更校验。
   - 同时将接收到的记录各字段值填充到表单对应项中。
8. **失败**：显示"Failed to load data. Please try again."。

#### 3.1.2 新增流程

1. **开始**：用户点击Add按钮。
2. **前置处理**：获取Product class、Number、Market等字段的当前值。
3. **前端校验**：
   - Product class未选择：Error message = "Product class is required."，**终止**。
   - Number为空：Error message = "Number is required."，**终止**。
   - Number包含非数字字符：Error message = "Number must be digits only."，**终止**。
   - Market未选择：Error message = "Market is required."，**终止**。
4. **Variable特殊校验**：若Variable字段以"TEMPLATE-"开头，去掉前缀后检查剩余部分是否存在于HDOC_VARIABLES列表中，若不存在则设置Error message = "Variant does not exist, Please enter the correct content"，**终止**。
5. **主键重复校验（后端）**：调用`UD08HomologationVariablesApi`的`UD08Add`方法时，后端检查Product class、Number、Market组合是否已存在，若存在返回"Primary key conflict, Please enter the correct content"。
6. **结果处理**：
   - **成功**：显示"Record added successfully."
   - **主键冲突（409）**：显示"Primary key conflict, Please enter the correct content"
   - **Variable不存在（400）**：显示"Variant does not exist, Please enter the correct content"
   - **服务器错误（500）**：显示"System error. Please contact administrator."

#### 3.1.3 更新流程

> **前提说明**：UD08画面点击Search跳转到UD09（HomologationVariablesResultList）。在UD09中点击某条记录时，会将该记录的原始主键值（originalProductClass、originalNumber、originalMarket）以及各字段值携带返回UD08。UD08接收到数据后，将原始主键值临时保存到State中，并将各字段值填充到表单。更新时以此作为修正元的标识，不允许修改主键。

1. **开始**：用户点击Update按钮。
2. **前端校验**：同新增流程的前端校验和Variable特殊校验。
3. **主键变更校验（前端）**：
   - 获取当前表单中的Product class、Number、Market值。
   - 与从搜索结果页传入的原始主键值（originalProductClass、originalNumber、originalMarket）进行比较。
   - 若任意主键字段发生变更：设置Error message = "Primary key cannot be updated."，**终止**流程，不调用后端API。
4. **记录存在性校验（后端）**：调用`UD08HomologationVariablesApi`的`UD08Update`方法时，后端检查Product class、Number、Market组合的记录是否存在，若不存在返回"Data does not exist, Please enter the correct content"。
5. **无更新字段校验**：若所有可更新字段均为空，则返回"No fields to update, Please enter the correct content"。
6. **结果处理**：
   - **成功**：显示"Record updated successfully."
   - **记录不存在（404）**：显示"Data does not exist, Please enter the correct content"
   - **Variable不存在（400）**：显示"Variant does not exist, Please enter the correct content"
   - **服务器错误（500）**：显示"System error. Please contact administrator."

#### 3.1.4 删除流程

1. **开始**：用户点击Delete按钮。
2. **前端校验**：Product class、Number、Market必填校验。
3. **记录存在性校验（后端）**：调用`UD08HomologationVariablesApi`的`UD08Delete`方法时，后端检查Product class、Number、Market组合的记录是否存在，若不存在返回"Data does not exist, Please enter the correct content"。
4. **结果处理**：
   - **成功**：显示"Record deleted successfully."，清空所有输入字段。
   - **记录不存在（404）**：显示"Data does not exist, Please enter the correct content"
   - **服务器错误（500）**：显示"System error. Please contact administrator."

#### 3.1.5 搜索流程

1. **开始**：用户点击Search按钮。
2. 获取当前表单中的所有字段值作为搜索条件（注意：Date字段`updateDatetime`仅用于展示，不作为搜索条件传递给后端）。
3. 将搜索条件编码为URL参数或存储在state中。
4. 使用React Router导航到UD09（HomologationVariablesResultList）搜索结果页面。

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用React State管理所有输入字段的值。
   - Error message区域默认隐藏，仅在发生错误时显示。
2. **输入过滤**：
   - Number字段实时过滤非数字字符，仅允许半角数字（0-9）。
   - 其他TextField字段允许半角英数字+記号。
3. **Variable校验**：
   - 若Variable以"TEMPLATE-"开头，需在Add/Update操作前校验剩余部分是否存在于HDOC_VARIABLES表中。
   - 校验列表在页面初始化时从API获取并缓存。
4. **UI细节**：
   - 页面标题显示为"EDB Engineering Database - Homologation Variables"。
   - Search、Add、Update、Delete按钮在API调用期间应设为`disabled`，防止重复提交。
   - Clear按钮仅清空输入字段，不清除任何缓存数据。
5. **搜索结果跳转**：
   - 搜索结果页面需要单独实现（HomologationVariablesResultList），本页面仅负责跳转。
   - 搜索条件通过URL参数或React Router的state传递。
