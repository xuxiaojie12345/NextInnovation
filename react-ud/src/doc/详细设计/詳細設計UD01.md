## 1. 背景 (Background)

本模块提供用户登录认证功能，是系统的入口页面。用户通过输入用户名和密码进行身份验证，认证成功后跳转到主菜单页面。

- **核心功能和目标**：实现用户登录认证，保障只有授权用户能够访问 EDB Engineering Database 系统；当认证失败时，提供清楚的错误提示，并引导用户使用备用登录链接或联系支持。
- **面向的用户群体**：系统注册用户；需要访问 EDB Engineering Database 的工程人员。
- **用户体验考虑**：界面简洁直观、提示信息清晰明了；支持响应式布局，适配不同屏幕尺寸；提供账户锁定情况下的备用登录链接提示，降低用户困惑。
- **安全性或特殊要求**：密码输入需要隐藏显示；支持半角英数字和符号；需支持账户锁定机制；前端应防止 SQL 注入、XSS 攻击和明文密码泄露。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

1. 开始：用户点击 `Login` 按钮。
2. 前置处理：获取 `username` 和 `password`，对两个字段执行 `trim()` 去除首尾空白。
3. 前端空值校验：
   - 若 `username` 或 `password` 为空：
     - 设置 `Message` = "Username and password are required."。
     - 终止后续流程，不调用后端接口。
4. 后端认证请求：
   - 调用 `AuthenticationApi`（POST `/api/authentication`），请求体包含 `{ username, password }`。
5. 响应处理（后端始终返回 HTTP 200，认证结果在响应体 `code` 字段中）：
   - `code === 200`：保存返回的 userInfo，并跳转到 `Menu` 页面。
   - `code === 401`：设置 `Message` = "We didn't recognize the username or password you entered. Please try again."。
   - `code === 403`：设置 `Message` = "Your account is locked. Please contact your system administrator."。
   - 其他错误或网络异常：设置 `Message` = "System error. Please contact administrator."。

> **注意**：后端 API 始终返回 HTTP 200，认证状态通过响应体中的 `code` 字段判断。前端不应依赖 HTTP 状态码。
6. 结果反馈：将对应错误消息显示在页面的 `Message` 区域，成功则执行页面跳转。

#### 3.2 处理说明

- 前端先对 `username` 和 `password` 进行 `trim` 处理，消除首尾空白。
- 若任一输入为空，则不调用后端接口，直接提示必要字段缺失。
- 若输入校验通过，则调用 `AuthenticationApi`。
- 根据接口返回结果执行后续处理：认证成功跳转页面，认证失败展示对应错误信息。

## 4. 接口定义 (API Specification)

### AuthenticationApi

- **功能**：验证用户凭证并返回认证结果。
- **Method**：POST
- **Endpoint**：`/api/authentication`

#### Request Body

```json
{
  "username": "string",
  "password": "string"
}
```

#### Response Success (200)

```json
{
  "code": 200,
  "message": "Authentication successful.",
  "data": {
    "success": true,
    "userInfo": {
      "userid": "string",
      "username": "string",
      "responsible": "string",
      "userposition": "string",
      "email": "string"
    }
  }
}
```

#### Response Error (401)

```json
{
  "code": 401,
  "message": "We didn't recognize the username or password you entered. Please try again.",
  "data": {
    "success": false,
    "userInfo": null
  }
}
```

#### Response Error (403)

```json
{
  "code": 403,
  "message": "Your account is locked. Please contact your system administrator.",
  "data": {
    "success": false,
    "userInfo": null
  }
}
```

#### Response Error (500)

```json
{
  "code": 500,
  "message": "System error. Please contact administrator.",
  "data": {
    "success": false,
    "userInfo": null
  }
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| --- | --- | --- |
| username 或 password 为空 | 前端校验拦截 | `Username and password are required.` |
| 用户名或密码错误 | API 返回 `code=401` | `We didn't recognize the username or password you entered. Please try again.` |
| 账户已锁定 | API 返回 `code=403` | `Your account is locked. Please contact your system administrator.` |
| 网络超时 / API 调用失败 | 捕获异常 | `System error. Please contact administrator.` |
| 数据库连接或服务器错误 | 后端返回 500 | `System error. Please contact administrator.` |

## 6. 实现注意事项 (Implementation Notes)

1. 使用 React 状态或 Hooks 管理 `username`、`password`、`message` 和 `isLoading`。
2. 密码输入框使用隐藏显示模式，避免在前端页面中泄露明文密码。
3. 登录按钮在 `isLoading` 期间应禁用，避免重复提交。
4. 失败提示使用明确的文本，避免弹窗中断用户操作流。
5. 页面应提供备用登录链接提示，帮助用户在账户锁定或异常情况下先尝试备用入口。
