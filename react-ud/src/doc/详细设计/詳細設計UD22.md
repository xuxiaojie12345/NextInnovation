## 1. 背景 (Background)

本模块用于显示HDoc系统中可用的文档类型列表，包括文档类型的键值（Key）和描述（Description）。

- **目标**：提供HDoc系统中所有可用文档类型的列表展示。
- **面向用户**：需要了解文档类型的业务人员和系统管理员。
- **用户体验**：提供清晰的文档类型列表展示，便于用户识别和选择合适的文档类型。
- **安全性**：需验证用户权限，确保只能访问授权的文档类型信息。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

#### 3.1.1 页面初始化流程

1. **开始**：用户进入Document Types画面。
2. **前置处理**：准备调用API获取HDOC_DOCUMENT_LIST表数据。
3. **API调用**：调用`UD22GetDocumentTypesApi`的`getDocumentTypes`方法（operation=GET_DOCUMENT_TYPES），从HDOC_DOCUMENT_LIST表获取文档类型信息（DOCTYPE, Description）。
4. **结果处理**：
   - **成功**：显示文档类型的键值（Key）和描述信息（Description），按照字母顺序排序展示。
   - **失败**：若获取不到文档类型数据，显示"无法获取文档类型信息"，保持在当前页面。

## 4. 接口定义 (API Specification)

### UD22GetDocumentTypesApi

统一API名称空间，包含以下方法：**getDocumentTypes**（文档类型列表查询）。

---

### 4.1 getDocumentTypes - 文档类型列表查询

**功能**：Document Typeの一覧情報を表示する。

- **Method**：`POST`
- **Endpoint**：`/api/ud22/UD22GetDocumentTypesApi`

#### Request

```json
{
  "operation": "GET_DOCUMENT_TYPES"
}
```

#### Response Success (200)

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "Key": "COC_EUB1",
      "Description": "Certificate of Conformity EU B1"
    },
    {
      "Key": "COC_EU",
      "Description": "Certificate of Conformity EU"
    },
    {
      "Key": "CL_TOTAL",
      "Description": "Total Weight Certificate"
    }
  ]
}
```

#### Response Error (500)

```json
{
  "code": 500,
  "message": "无法获取文档类型信息",
  "data": null
}
```

## 6. 实现注意事项 (Implementation Notes)

1. **纯展示页面**：本页面为纯展示性质，只读显示文档类型列表。
2. **数据排序**：按照字母顺序或其他逻辑排序展示。
3. **自动加载**：页面进入时自动获取并展示数据，无需用户手动触发。
4. **UI设计**：以清晰的表格形式展示Key和Description两列，便于用户识别和选择合适的文档类型。
