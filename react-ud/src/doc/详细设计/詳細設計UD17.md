## 1. 背景 (Background)

本模块用于管理用户权限，主要功能包括输入用户ID查询用户信息和权限、从Saviynt系统获取用户名、从HDOC_FUNCTION_AUTH表获取用户功能权限、更新用户权限配置、删除用户所有权限。

- **目标**：提供用户权限的查询、更新和删除管理功能。
- **面向用户**：需要管理用户权限的系统管理员。
- **用户体验**：清晰的权限配置界面、明确的错误提示信息、支持快速更新和删除权限操作。
- **安全性**：用户ID必须存在于系统中才能执行操作、防止未授权的权限修改、支持HTTPS安全传输。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

#### 3.1.1 页面初始化流程

1. **开始**：页面加载。
2. 调用`UD17HDocUserAdministrationApi`的`getMarketList`方法（GET `/api/ud17/markets`）获取市场列表。
3. 将所有Market下拉列表填充市场数据。
4. Standard User和Adaptation user对应的Market下拉列表默认选择-EU，其他保持为空。

#### 3.1.2 User Info处理流程

1. **开始**：用户点击User Info按钮。
2. **前置校验**：若UserID为空，显示"UserID is required."并**终止**。
3. 调用`UD17HDocUserAdministrationApi`的`UD17Userinfo`功能。
4. **结果处理**：
   - **成功**：从响应中获取用户名显示在User标签中；根据功能权限列表勾选对应复选框；根据市场权限设置Market下拉列表。
   - **失败（用户ID不存在）**：显示"We didn't recognize the userid you entered. Please try again."。
   - **服务器错误**：显示"System error. Please contact administrator."。

#### 3.1.3 Update Role处理流程

1. **开始**：用户点击Update Role按钮。
2. **前置校验**：若UserID为空，显示"UserID is required."并**终止**。
3. **存在性检查**：先调用`UD17HDocUserAdministrationApi`的`UD17Userinfo`功能检查UserID是否存在。
4. 若UserID不存在：显示"We didn't recognize the userid you entered. Please try again."，**终止**流程。
5. 若UserID存在：获取所有权限复选框状态和Market下拉列表值，调用`UD17HDocUserAdministrationApi`的`UD17UpdateRole`功能。
6. **更新逻辑（DELETE + INSERT）**：后端先删除该用户在`HDOC_FUNCTION_AUTH`和`DOC_MARKET_AUTH`表中的全部既有权限数据，再追加插入新的权限记录。画面多个权限更新时，DB以增加record的形式进行更新。
7. **结果处理**：
   - **成功**：显示"Role updated successfully."。
   - **失败**：显示对应错误消息。

#### 3.1.4 Delete Role处理流程

1. **开始**：用户点击Delete Role按钮。
2. **前置校验**：若UserID为空，显示"UserID is required."并**终止**。
3. 调用`UD17HDocUserAdministrationApi`的`UD17DeleteRole`功能，将userid作为参数传递到后台。
4. 后端根据userid删除`DOC_MARKET_AUTH`和`HDOC_FUNCTION_AUTH`表中该用户的**所有权限记录**。
5. **结果处理**：
   - **成功**：显示"Role deleted successfully."，清空所有权限配置。
   - **失败**：显示对应错误消息。

### 3.2 校验详细规格表

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 (Message Content) | 动作 |

| 1 | 点击User Info按钮时 | UserID | 值为空字符串或未填写 | `UserID is required.` | 显示错误消息，终止流程 |
| 2 | 点击Update Role按钮时 | UserID | 值为空字符串或未填写 | `UserID is required.` | 显示错误消息，终止流程 |
| 3 | Update Role前存在性检查 | 用户ID存在性 | 用户ID不存在 | `We didn't recognize the userid you entered. Please try again.` | 显示Error级别消息，终止流程，不执行更新 |
| 4 | 点击Delete Role按钮时 | UserID | 值为空字符串或未填写 | `UserID is required.` | 显示错误消息，终止流程 |

## 4. 接口定义 (API Specification)

### 4.1 getMarketList API

- **功能**：获取市场列表数据
- **Method**：`GET`
- **Endpoint**：`/api/ud17/markets`

#### Request Body

无

#### Response Success (200 OK)

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "market": "string",
      "description": "string"
    }
  ]
}
```

### 4.2 UD17HDocUserAdministrationApi

- **功能**：管理用户权限，包括查询用户信息、检查用户存在性、更新权限、删除权限
- **Method**：`POST`
- **Endpoint**：`/api/ud17/UD17HDocUserAdministrationApi`

#### Request - UD17Userinfo操作（含存在性检查）

```json
{
  "userid": "string",
  "operation": "userinfo"
}
```

#### Request - UD17UpdateRole操作（先进行存在性检查，再DELETE+INSERT）

```json
{
  "userid": "string",
  "operation": "updateRole",
  "functions": ["string"],
  "markets": [
    { "market": "string", "type": "string", "bu": "string" }
  ],
  "updateUser": "string",
  "updateProcess": "string"
}
```

#### Request - UD17DeleteRole操作

```json
{
  "userid": "string",
  "operation": "deleteRole"
}
```

#### Response Success (200) - userinfo操作

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "username": "string",
    "functions": [{ "function": "string" }],
    "markets": [{ "market": "string", "type": "string", "bu": "string" }]
  }
}
```

#### Response Success (200) - updateRole操作

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "message": "Role updated successfully."
  }
}
```

#### Response Success (200) - deleteRole操作

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "message": "Role deleted successfully."
  }
}
```

#### Response Error (404) - 用户不存在

```json
{
  "code": 404,
  "message": "We didn't recognize the userid you entered. Please try again.",
  "data": null
}
```

#### Response Error (500)

```json
{
  "code": 500,
  "message": "Internal server error",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :--- | :--- | :--- |
| **网络连接失败** | 捕获网络异常，显示通用错误消息 | `System error. Please contact administrator.` |
| **API超时** | 设置超时时间（建议10秒），超时后显示错误 | `System error. Please contact administrator.` |
| **getMarketList API失败** | 显示加载市场数据失败消息 | `Failed to load market data. Please try again.` |
| **API返回404** | 显示用户ID不存在消息 | `We didn't recognize the userid you entered. Please try again.` |
| **用户ID为空** | 前端校验拦截 | `UserID is required.` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用React State管理UserID输入值、所有复选框状态、所有Market下拉列表值、User标签显示值。
   - User标签初始为空，查询成功后显示从Saviynt获取的用户名。
2. **数据来源**：
   - Saviynt系统：获取用户名。
   - MARKET_MASTER表：获取市场列表。
   - HDOC_FUNCTION_AUTH表：存储和查询用户功能权限。
   - DOC_MARKET_AUTH表：存储和查询用户市场权限。
3. **权限类型说明**：Standard User、Rule Admin、Template Admin、Document Auth Admin、User Admin、Adaptation user、Manage Variable List、Market Super User。
4. **默认值**：Standard User和Adaptation user对应的Market下拉列表默认显示-EU。
5. **Update Role存在性检查**：点击Update Role按钮时，先调用UD17Userinfo检查用户是否存在，若不存在则显示错误消息并终止，存在则执行更新。
6. **Delete Role操作**：会删除用户的所有功能权限和市场权限。
