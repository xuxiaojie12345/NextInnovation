## 1. 背景 (Background)

本模块用于生成车辆认证文档，主要功能包括接收用户输入的车辆底盘系列号、底盘号和文档类型，调用后端API获取可用的文档类型列表，验证输入的底盘号是否存在于系统中，根据查询结果生成相应的认证文档。

- **目标**：提供底盘认证文档的查询与生成功能。
- **面向用户**：需要生成车辆认证文档的授权用户，如质量管理人员、文档管理员等。
- **用户体验**：默认显示上次指定的条件提高效率、清晰的错误提示信息、简洁的操作界面、支持快速重置表单。
- **安全性**：输入字符严格限制防止注入攻击、底盘号必须存在于系统中才能继续操作、支持HTTPS安全传输。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

#### 3.1.1 页面初始化流程

1. **开始**：页面加载。
2. 调用`UD03SelectHdocdocumentlistApi`（GET方法，Endpoint `/api/documenttypes`）获取文档类型列表。
3. API返回成功后，将文档类型数据填充到Document type下拉列表中。
4. 从本地存储（localStorage或sessionStorage）读取上次保存的查询条件。
5. 若存在上次保存的条件，则自动填充到Chassis series、Chassis no和Document type字段。
6. 若不存在上次保存的条件，则保持字段为空。
7. **失败**：在Error message area显示"Document type acquisition failed. Please try again later."

#### 3.1.2 提交流程

1. **开始**：用户点击Submit按钮。
2. **前置处理**：获取Chassis series、Chassis no、Document type的当前值。
3. **空值校验 (Frontend Check)**：
   - 若Chassis series为空：设置Error message = "Chassis series is required."，**终止**流程。
   - 若Chassis no为空：设置Error message = "Chassis no is required."，**终止**流程。
   - 若Document type未选择：设置Error message = "Document type is required."，**终止**流程。
4. **页面跳转**：
   - 不调用后端API。
   - 保存当前查询条件到本地存储，清空Error message area。
   - 跳转到UD04 GenerateDocument页面，请求参数包含chassisSeries、chassisNo和documentType。
   - 底盘号存在性校验由UD04页面在初始化时调用`UD04SelectGeneratedocumentApi`完成。

### 3.2 校验详细规格表

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 (Message Content) | 动作 |
| :-: | :---: | :---: | :--- | :--- | :---: |
| 1 | 点击Submit按钮时 | Chassis series | 值为空字符串或未填写 | `Chassis series is required.` | 显示错误消息，终止流程，不调用API |
| 2 | 点击Submit按钮时 | Chassis no | 值为空字符串或未填写 | `Chassis no is required.` | 显示错误消息，终止流程，不调用API |
| 3 | 点击Submit按钮时 | Document type | 未选择任何选项 | `Document type is required.` | 显示错误消息，终止流程，不调用API |
| 4 | 输入时（实时） | Chassis series | 输入字符不是半角英字 | 无错误消息 | 自动过滤非法字符 |
| 5 | 输入时（实时） | Chassis no | 输入字符不是半角数字 | 无错误消息 | 自动过滤非法字符 |

## 4. 接口定义 (API Specification)

### 4.1 UD03SelectHdocdocumentlistApi

- **功能**：获取可用的文档类型列表
- **Method**：`GET`
- **Endpoint**：`/api/documenttypes`

#### Request Body

无

#### Response Success (200 OK)

直接返回 DocumentType 对象数组（不包含外层 code/data 包装）。

```json
[
  {
    "doctype": "string",
    "description": "string",
      "registerDatetime": "2024-01-01T00:00:00",
      "registerUser": "string",
      "registerProcess": "string",
      "updateDatetime": "2024-01-01T00:00:00",
      "updateUser": "string",
      "updateProcess": "string"
    }
  ]
```

#### Response Error (500)

```json
{
  "code": 500,
  "message": "Internal server error",
  "data": null
}
```


## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :--- | :--- | :--- |
| **网络连接失败** | 捕获网络异常，显示通用错误消息 | `System error. Please contact administrator.` |
| **API超时** | 设置超时时间，超时后显示错误 | `System error. Please contact administrator.` |
| **必填项为空** | 前端校验拦截 | `Chassis series is required.` / `Chassis no is required.` / `Document type is required.` |
| **加载文档类型失败** | 初始化API失败时显示 | `Failed to load document types. Please try again.` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用React State管理`chassisSeries`、`chassisNo`、`documentType`、`errorMessage`、`isLoading`。
   - 使用localStorage保存上次查询条件，以便下次打开页面时自动填充。
2. **输入过滤**：
   - Chassis series字段实时过滤非英文字母字符。
   - Chassis no字段实时过滤非数字字符。
3. **UI细节**：
   - Submit按钮在`isLoading`期间应设为`disabled`，防止重复提交。
   - Error message区域使用红色文字（`#ff4d4f`）显示错误消息。
   - Reset按钮不清除本地存储中保存的上次查询条件。
