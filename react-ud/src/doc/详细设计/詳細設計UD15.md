## 1. 背景 (Background)

本模块用于查看和管理车辆底盘相关信息，主要功能包括输入底盘号查询VIN Plate详细信息、更新底盘状态为"0"（新規追加）、更新底盘状态为"1"（xml doc 作成済み）、将底盘状态更新为"0"并设置TYPE为"1"（basic）、将底盘状态更新为"0"并设置TYPE为"2"（ADVANCED with weights）。

- **目标**：提供VIN Plate底盘状态的管理功能。
- **面向用户**：需要管理和维护车辆底盘信息的授权用户，如数据管理员、质量管理人员等。
- **用户体验**：简洁的操作界面，五个功能按钮清晰明了、明确的错误提示信息、快速的状态更新操作。
- **安全性**：底盘号必须存在于系统中才能执行操作、防止非法字符输入、支持HTTPS安全传输。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

### 3.1 处理流程

所有按钮操作的共同前置处理：获取Chassis number字段值，若为空则显示"Chassis number is required."并**终止**流程，不调用API。

#### 3.1.1 View Info处理流程

1. **开始**：用户点击View Info按钮。
2. **前置校验**：Chassis number必填检查。
3. 调用`UD15SelecthdocsenddatavinplateApi`的`UD15ViewInfo`方法，operation为"viewInfo"。
4. **结果处理**：
   - **成功**：将API返回的TYPE、STATUS、MSG、REGISTER_DATETIME、DOC_READY、DOC_SENT、XML_DOC分别显示到对应的Label控件。
   - **失败（底盘号不存在）**：显示"Chassis number XXX not found."，清空各显示字段。

#### 3.1.2 Set Regenerate处理流程

1. **开始**：用户点击Set Regenerate按钮。
2. **前置校验**：Chassis number必填检查。
3. 调用`UD15SelecthdocsenddatavinplateApi`的`UD15SetRegenerate`方法，operation为"setRegenerate"。
4. 将HDOC_SEND_DATA_VIN_PLATE表中对应底盘号的Status字段更新为"0"。
5. **结果处理**：
   - **成功**：显示"Status updated successfully."。
   - **失败**：显示"Chassis number XXX not found."。

#### 3.1.3 Set OK处理流程

1. **开始**：用户点击Set OK按钮。
2. **前置校验**：Chassis number必填检查。
3. 调用`UD15SelecthdocsenddatavinplateApi`的`UD15SetOK`方法，operation为"setOK"。
4. 将Status字段更新为"1"。
5. **结果处理**：同Set Regenerate。

#### 3.1.4 Change to Basic Info处理流程

1. **开始**：用户点击Change to Basic Info按钮。
2. **前置校验**：Chassis number必填检查。
3. 调用`UD15SelecthdocsenddatavinplateApi`的`UD15ChangetoBasicInfo`方法，operation为"changeToBasicInfo"。
4. 将Status更新为"0"，Type更新为"1"。
5. **结果处理**：
   - **成功**：显示"Status and Type updated successfully."。
   - **失败**：显示"Chassis number XXX not found."。

#### 3.1.5 Change to Advanced Info处理流程

1. **开始**：用户点击Change to Advanced Info按钮。
2. **前置校验**：Chassis number必填检查。
3. 调用`UD15SelecthdocsenddatavinplateApi`的`UD15ChangetoAdvancedInfo`方法，operation为"changeToAdvancedInfo"。
4. 将Status更新为"0"，Type更新为"2"。
5. **结果处理**：同Change to Basic Info。

### 3.2 校验详细规格表

| No. | 检查时机 | 检查对象 | 检查条件 | 错误消息 (Message Content) | 动作 |
| :-: | :---: | :---: | :--- | :--- | :---: |
| 1 | 点击任意按钮时 | Chassis number | 值为空字符串或未填写 | `Chassis number is required.` | 显示错误消息，终止流程，不调用API |

## 4. 接口定义 (API Specification)

### UD15SelecthdocsenddatavinplateApi

统一API名称空间，包含以下方法：**UD15ViewInfo**（查看VIN Plate信息）、**UD15SetRegenerate**（设置再生成）、**UD15SetOK**（设置为OK）、**UD15ChangetoBasicInfo**（变更为基本信息）、**UD15ChangetoAdvancedInfo**（变更为高级信息）。

---

### 4.1 UD15ViewInfo - 查看VIN Plate信息

**功能**：根据底盘号查询VIN Plate详细信息

- **Method**：`POST`
- **Endpoint**：`/api/ud15/UD15SelecthdocsenddatavinplateApi`

#### Request

```json
{
  "chassisNumber": "string (Max 15, Required)",
  "operation": "viewInfo"
}
```

#### Response Success (200)

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "chassisNumber": "string",
    "type": "string",
    "status": "string",
    "msg": "string",
    "registerDatetime": "2024-01-01T00:00:00",
    "docReady": "string",
    "docSent": "string",
    "xmlDoc": "string"
  }
}
```

#### Response Error (404)

```json
{
  "code": 404,
  "message": "Chassis number XXX not found.",
```

## 5. 异常处理 (Exception Handling)

| 异常场景 | 处理方式 | Message 显示内容 |
| :--- | :--- | :--- |
| **网络连接失败** | 捕获网络异常，显示通用错误消息 | `System error. Please contact administrator.` |
| **API超时** | 设置超时时间（建议10秒），超时后显示错误 | `System error. Please contact administrator.` |
| **服务器内部错误** | API返回500，显示系统错误消息 | `System error. Please contact administrator.` |
| **JSON解析失败** | 捕获解析异常，显示系统错误 | `System error. Please contact administrator.` |

## 6. 实现注意事项 (Implementation Notes)

1. **状态管理**：
   - 使用React State管理Chassis number输入值和错误消息。
   - 所有按钮在API调用期间应设为`disabled`，防止重复提交。
2. **操作类型**：所有按钮操作都调用同一个API端点，通过`operation`参数区分不同功能。
3. **底盘号验证**：所有按钮操作都需要先验证底盘号是否存在，不存在时显示Warning级别的错误消息。
4. **UI细节**：
   - 页面标题显示为"EDB Engineering Database - Vin Plate"。
   - 五个功能按钮清晰排列，每个按钮对应一种状态操作。
   - 操作成功后应显示相应的成功消息。
