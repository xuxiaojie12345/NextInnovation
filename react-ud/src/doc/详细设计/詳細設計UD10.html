1. 背景 (Background)

本模块用于管理HDOC_VARIABLES表中的变量定义记录，主要功能包括显示从Homologation Variables画面传递的搜索条件、支持新增/更新/删除变量定义记录、支持清空输入字段、支持返回前画面、支持导出CSV文件。

  • 目标：提供变量定义记录的完整CRUD（增删改查）管理及CSV导出功能。
  • 面向用户：需要管理认证系统变量定义的授权用户，如系统管理员、配置管理人员等。
  • 用户体验：清晰的表单布局、明确的操作反馈、便捷的数据导出功能、完整的主键冲突检测。
  • 安全性：需要用户登录认证后才能访问、变量定义修改需要权限控制、支持HTTPS安全传输。

3. 业务逻辑与校验规则 (Business Logic & Checks)

3.1 处理流程

3.1.1 页面初始化流程

  1. 开始：页面加载。
  2. 从URL参数或state中获取前画面传递的Variable值。
  3. 将Variable值自动填充到Variable输入框中。
  4. 其他字段保持为空。
  5. 若未传递搜索条件，则所有字段均为空。

3.1.2 搜索流程

  1. 开始：用户点击Search按钮。
  2. 获取当前表单中的所有字段值。
  3. 构建搜索条件对象，存储到state或sessionStorage。
  4. 使用React Router导航到/ExistingHDocVariables/Search路由。

3.1.3 新增流程

  1. 开始：用户点击Add按钮。
  2. 前端校验：检查Variable字段是否为空，若为空则显示"Variable is required."并终止流程。
  3. Variable存在性校验（后端）：调用UD10HdocvariablesApi的UD10Add方法（POST /api/ud10/add）时，后端检查Variable是否已存在于HDOC_VARIABLES表，若已存在返回"Variant already exists. Please enter the correct content"。
  4. 结果处理：
    • 成功：显示"Record added successfully."
    • 主键冲突（409）：显示"Variant already exists. Please enter the correct content"
    • 服务器错误（500）：显示"System error. Please contact administrator."

3.1.4 更新流程

  1. 开始：用户点击Update按钮。
  2. 前端校验：检查Variable字段是否为空，若为空则显示"Variable is required."并终止流程。
  3. Variable存在性校验（后端）：调用UD10HdocvariablesApi的UD10Update方法（POST /api/ud10/update）时，后端检查Variable是否存在于HDOC_VARIABLES表，若不存在返回"Variant does not exists. Please enter the correct content"。
  4. 结果处理：
    • 成功：显示"Record updated successfully."
    • 记录不存在（404）：显示"Variant does not exists. Please enter the correct content"
    • 服务器错误（500）：显示"System error. Please contact administrator."

3.1.5 删除流程

  1. 开始：用户点击Delete按钮。
  2. 前端校验：检查Variable字段是否为空，若为空则显示"Variable is required."并终止流程。
  3. Variable存在性校验（后端）：调用UD10HdocvariablesApi的UD10Delete方法（POST /api/ud10/delete）时，后端检查Variable是否存在于HDOC_VARIABLES表，若不存在返回"Variant does not exists. Please enter the correct content"。
  4. 结果处理：
    • 成功：显示"Record deleted successfully."，清空所有表单字段。
    • 记录不存在（404）：显示"Variant does not exists. Please enter the correct content"
    • 服务器错误（500）：显示"System error. Please contact administrator."

3.1.6 导出CSV流程

  1. 开始：用户点击Excel按钮。
  2. 前端获取当前表单数据（Variable、Type、Description、Created by user、Date）。
  3. 构建CSV内容：第一行为项目名（Variable,Type,Description,Created by user,Date），第二行为当前表单值。
  4. 使用UTF-8 BOM编码生成CSV文件，设置文件名格式为HDOC_Variables_YYYYMMDD.csv。
  5. 浏览器触发文件下载。

3.1.7 清空流程

  1. 用户点击Clear按钮。
  2. 清空所有输入字段的值，Type下拉列表重置为请选择状态。
  3. 清空错误消息和成功消息区域。

3.1.8 返回流程

  1. 用户点击Back按钮。
  2. 使用React Router navigate返回/Menu页面。

4. 接口定义 (API Specification)

4.1 UD10HdocvariablesApi

UD10HdocvariablesApi包含以下方法：

方法①. UD10Search

  • 功能：根据搜索条件查询HDOC_VARIABLES变量定义列表
  • Method：POST
  • Endpoint：/api/ud10/search
Request 
{
  "variable": "string (Max 30, Optional)",
  "type": "string (Max 20, Optional)",
  "description": "string (Max 100, Optional)",
  "userid": "string (Max 16, Optional)",
  "registerDatetime": "string (Optional)",
  "variableOp": "string (Optional, Values: =/!=)",
  "typeOp": "string (Optional, Values: =/=!)",
  "descriptionOp": "string (Optional, Values: =/=!)",
  "useridOp": "string (Optional, Values: =/=!)",
  "registerDatetimeOp": "string (Optional, Values: =/GT/LT)"
}
Response Success (200 OK) 
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "variable": "VAR001",
      "type": "VDA",
      "description": "Test variable description",
      "userid": "admin",
      "registerDatetime": "2022-12-02T05:11:45",
      "registerUser": "admin",

6. 实现注意事项 (Implementation Notes)

  1. 状态管理：
    • 使用React State管理所有输入字段的值。
    • Error message区域默认隐藏，仅在发生错误时显示。
  2. Variable主键校验：
    • Add操作需要检测主键冲突（Variable已存在）。
    • Update/Delete操作需要检测记录是否存在。
  3. CSV导出：
    • 可使用前端库（如papaparse）实现CSV导出功能。
    • 文件名格式：HDOC_Variables_YYYYMMDD.csv。
  4. UI细节：
    • 页面标题显示为"EDB Engineering Database - Existing HDoc Variables"。
    • Search、Add、Update、Delete、Excel按钮在API调用期间应设为disabled，防止重复提交。
    • Clear按钮仅清空输入字段。
    • Back按钮返回/Menu页面。
  5. 数据传递：
    • 从HomologationVariables页面跳转时，通过URL参数或React Router的state传递Variable值。
    • 搜索结果页面需要单独实现，本页面仅负责搜索跳转。
