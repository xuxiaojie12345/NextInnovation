1. 背景 (Background)

本模块用于查看和管理车辆底盘相关信息，主要功能包括输入底盘号查询VIN Plate详细信息、更新底盘状态为"0"（新規追加）、更新底盘状态为"1"（xml doc 作成済み）、将底盘状态更新为"0"并设置TYPE为"1"（basic）、将底盘状态更新为"0"并设置TYPE为"2"（ADVANCED with weights）。

  • 目标：提供VIN Plate底盘状态的管理功能。
  • 面向用户：需要管理和维护车辆底盘信息的授权用户，如数据管理员、质量管理人员等。
  • 用户体验：简洁的操作界面，五个功能按钮清晰明了、明确的错误提示信息、快速的状态更新操作。
  • 安全性：底盘号必须存在于系统中才能执行操作、防止非法字符输入、支持HTTPS安全传输。

3. 业务逻辑与校验规则 (Business Logic & Checks)

3.1 处理流程

所有按钮操作的共同前置处理：获取Chassis number字段值，若为空则显示"Chassis number is required."并终止流程，不调用API。

3.1.1 View Info处理流程

  1. 开始：用户点击View Info按钮。
  2. 前置校验：Chassis number必填检查。
  3. 调用UD15SelecthdocsenddatavinplateApi的UD15ViewInfo方法，operation为"viewInfo"。
  4. 结果处理：
    • 成功：将API返回的TYPE(Plate type)、STATUS(Status)、MSG(Error Message)、REGISTER_DATETIME(Def.)、DOC_READY(Data ready)、DOC_SENT(Sent to CAB factory)、XML_DOC(Print items / VP Data)分别显示到对应的Label控件。
    • 失败（底盘号不存在）：显示"Chassis number XXX not found."，清空各显示字段。

3.1.2 Set Regenerate处理流程

  1. 开始：用户点击Set Regenerate按钮。
  2. 前置校验：Chassis number必填检查。
  3. 调用UD15SelecthdocsenddatavinplateApi的UD15SetRegenerate方法，operation为"setRegenerate"。
  4. 将HDOC_SEND_DATA_VIN_PLATE表中对应底盘号的Status字段更新为"0"。
  5. 结果处理：
    • 成功：显示"Status updated successfully."。
    • 失败：显示"Chassis number XXX not found."。

3.1.3 Set OK处理流程

  1. 开始：用户点击Set OK按钮。
  2. 前置校验：Chassis number必填检查。
  3. 调用UD15SelecthdocsenddatavinplateApi的UD15SetOK方法，operation为"setOK"。
  4. 将Status字段更新为"1"。
  5. 结果处理：同Set Regenerate。

3.1.4 Change to Basic Info处理流程

  1. 开始：用户点击Change to Basic Info按钮。
  2. 前置校验：Chassis number必填检查。
  3. 调用UD15SelecthdocsenddatavinplateApi的UD15ChangetoBasicInfo方法，operation为"changeToBasicInfo"。
  4. 将Status更新为"0"，Type更新为"1"。
  5. 结果处理：
    • 成功：显示"Status and Type updated successfully."。
    • 失败：显示"Chassis number XXX not found."。

3.1.5 Change to Advanced Info处理流程

  1. 开始：用户点击Change to Advanced Info按钮。
  2. 前置校验：Chassis number必填检查。
  3. 调用UD15SelecthdocsenddatavinplateApi的UD15ChangetoAdvancedInfo方法，operation为"changeToAdvancedInfo"。
  4. 将Status更新为"0"，Type更新为"2"。
  5. 结果处理：同Change to Basic Info。

4. 接口定义 (API Specification)

6. 实现注意事项 (Implementation Notes)

  1. 状态管理：
    • 使用React State管理Chassis number输入值和错误消息。
    • 所有按钮在API调用期间应设为disabled，防止重复提交。
  2. 操作类型：所有按钮操作都调用同一个API端点，通过operation参数区分不同功能。
  3. 底盘号格式：输入格式为系列号-编号（使用中划线-分隔），例：JPCT-1234567890。后端通过-拆分得到SERIE和CHNR分别查询数据库。
  4. 底盘号验证：所有按钮操作都需要先验证底盘号是否存在，不存在时显示Warning级别的错误消息。
  5. UI细节：
    • 页面标题显示为"EDB Engineering Database - Vin Plate"。
    • 五个功能按钮清晰排列，每个按钮对应一种状态操作。
    • 操作成功后应显示相应的成功消息。
