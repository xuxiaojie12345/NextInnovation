1. 背景 (Background)

本模块提供用户搜索功能，支持通过Userid、User、Market等条件搜索用户，并可按权限类型（Not set、Rule Admin、Template Admin）过滤搜索结果。从HDOC_USER_INFOR表获取用户信息，从HDOC_MARKET_AUTH表获取用户市场权限。

  • 目标：提供多条件组合的用户搜索功能。
  • 面向用户：系统管理员、需要查询和管理用户信息的业务人员。
  • 用户体验：提供多种搜索条件组合、清晰的搜索结果展示、显示搜索结果数量。
  • 安全性：需要用户登录认证。

3. 业务逻辑与校验规则 (Business Logic & Checks)

3.1 处理流程

3.1.1 页面初始化流程

  1. 开始：页面加载。
  2. 调用UD19SearchResultListApi的UD19SelectMarketMaster方法（operation=GET_MARKET_LIST），从MARKET_MASTER表获取所有Market数据。
  3. 填充到Market下拉列表中，清空其他输入字段，单选按钮组默认不选中任何选项。

3.1.2 通过Userid搜索流程（动态条件）

  1. 开始：用户点击Search按钮。
  2. API调用：调用UD19SearchResultListApi的UD19SearchHdoc方法（operation=SEARCH_USER），传递参数serid。
  3. 后台处理：后台接收前台参数serid，以serid对应的值作为关联查询的条件（INNER JOIN），从HDOC_USER_INFOR（取得项目 userid、username）、HDOC_MARKET_AUTH（market）使用动态SQL，将参数serid对应的值作为WHERE条件（userid = serid）进行检索。
  4. 返回前台显示：将取得的数据返回到前台，在DataTable中显示搜索结果（Userid、User、Market），在COUNT字段显示搜索结果数量。

3.1.3 通过User搜索流程（动态条件）

  1. 开始：用户点击Search按钮。
  2. API调用：调用UD19SearchResultListApi的UD19SearchHdoc方法（operation=SEARCH_USER），传递参数user。
  3. 后台处理：后台接收前台参数user，通过user检索取得HDOC_USER_INFOR表中对应的userid，将取得的userid作为关联查询的条件（INNER JOIN），从HDOC_USER_INFOR（取得项目 userid、username）、HDOC_MARKET_AUTH（market）使用动态SQL，将取得的userid作为WHERE条件进行检索。
  4. 返回前台显示：将取得的数据返回到前台，在DataTable中显示搜索结果（Userid、User、Market），在COUNT字段显示搜索结果数量。

3.1.4 通过权限类型搜索流程

  1. 开始：用户选择单选按钮（Not set/Rule/Template）并点击Search。

Not set选择时：
2. API调用：调用UD19SearchResultListApi的UD19SearchHdoc方法（operation=SEARCH_USER）。
3. 后台处理：查询HDOC_MARKET_AUTH内连接HDOC_USER_INFOR（INNER JOIN），userid作为关联条件，从HDOC_USER_INFOR获取userid、username，从HDOC_MARKET_AUTH获取market。
4. 返回前台显示：将取得的数据返回到前台显示。

Rule选择时（动态条件）：
2. API调用：调用UD19SearchResultListApi的UD19SearchHdoc方法（operation=SEARCH_USER）。
3. 后台处理：从HDOC_USER_INFOR（取得项目 userid、username）、HDOC_MARKET_AUTH（market）使用动态SQL，将参数Rule和选择的market作为WHERE条件进行检索。
4. 返回前台显示：将取得的数据返回到前台显示。

Template选择时（动态条件）：
2. API调用：调用UD19SearchResultListApi的UD19SearchHdoc方法（operation=SEARCH_USER）。
3. 后台处理：从HDOC_USER_INFOR（取得项目 userid、username）、HDOC_MARKET_AUTH（market）使用动态SQL，将参数Template和选择的market作为WHERE条件进行检索。
4. 返回前台显示：将取得的数据返回到前台显示。

4. 接口定义 (API Specification)

UD19SearchResultListApi

统一API名称空间，包含以下方法：UD19SelectMarketMaster（市场列表查询）、UD19SearchHdoc（用户搜索）。

4.1 UD19SelectMarketMaster - 市场列表查询

功能：获取所有可用市场列表，用于填充Market下拉列表

  • Method：POST
  • Endpoint：/api/ud19/UD19SearchResultListApi

Request 

{
  "operation": "GET_MARKET_LIST"
}

Response Success (200) 

{
  "code": 200,
  "message": "success",
  "data": [
    { "market": "AUS", "description": "Australia" },
    { "market": "USA", "description": "United States" }
  ]
}

Response Error (500) 

{
  "code": 500,
  "message": "Internal server error",
  "data": null
}

4.2 UD19SearchHdoc - 用户搜索

功能：根据条件搜索用户，支持Userid、User、权限类型（Rule/Template）及Market组合查询

  • Method：POST
  • Endpoint：/api/ud19/UD19SearchResultListApi

Request 

{
  "operation": "SEARCH_USER",
  "serid": "string (可选，最大10字符，半角英数字)",
  "user": "string (可选，最大32字符，半角英数字)",
  "market": "string (可选)",
  "type": "string (可选，RULE_ADMIN/TEMPLATE_ADMIN)"
}

Response Success (200) 

{
  "code": 200,
  "message": "success",
  "data": {
    "count": 5,
    "users": [
      { "userid": "USER001", "user": "John Smith", "market": "AUS" },
      { "userid": "USER002", "user": "Jane Doe", "market": "USA" }
    ]
  }
}

Response Error (500) 

{
  "code": 500,
  "message": "Internal server error",
  "data": null
}

6. 实现注意事项 (Implementation Notes)

  1. 搜索条件组合：支持同时输入Userid/User、选择Market、选择权限类型进行组合搜索。
  2. 单选按钮互斥：Not set、Rule、Template三个RadioBox为互斥选择。
  3. 数据来源：
    • HDOC_USER_INFOR表：通过userid关联，获取Userid和User信息。
    • HDOC_MARKET_AUTH表（ユーザmarket権限テーブル）：通过userid进行关联，获取Market（用户市场权限）信息。
    • MARKET_MASTER表：仅用于填充Market下拉列表的选项数据。
  4. 搜索结果：DataTable显示Userid、User、Market三列，COUNT显示记录总数。
  5. Market数据源区分：画面上的Market下拉列表（搜索条件）从MARKET_MASTER表取得选项；而检索结果中的Market列則通过userid关联，从ユーザmarket権限テーブル（HDOC_MARKET_AUTH）取得用户的实际市场权限数据。
