## 1. 背景 (Background)

本模块用于根据用户输入的底盘系列、底盘编号和文档类型，查询并生成相应的认证文档。

- **目标**：使用户能够快速查询并生成所需的认证文档。
- **安全性**：所有敏感数据传输需加密，前端不存储任何明文数据。
- **用户体验**：采用页面内Label显示错误信息，避免频繁弹窗打断操作流；支持前次输入条件的默认显示，提升操作效率。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击 [Submit] 按钮时同步或异步执行。

### 3.1 处理流程

#### 页面初始化

1.  **开始**：页面初始化。
2.  **前置处理**：调用 UD03SelectHdocdocumentlistApi 获取文档类型列表
3.  **结果处理**：
    - 成功且列表非空：
      更新 Document type 下拉框选项。
      若本地存储中有上次的 Document type 且存在于新列表中，则选中该值；否则选中默认值（如第一项）。
      清空 error message area。
    - 成功但列表为空 (Count == 0)：
      设置 error message area = "Chassis no is not exists"。
      禁用或清空 Document type 下拉框。
    - 失败 (Exception)：
      设置 error message area = "System error. Please contact support." 或 "Network error. Please try again."。

#### 点击 [Submit] 按钮

1.  **开始**：用户点击 [Submit] 按钮。
2.  **前置处理**：输入 Chassis series、Chassis no、选择 Document type。
3.  **空值校验 (Frontend Check)**：
    - 若 `Chassis series` 为空：
      - 设置 `Error message area` = `底盘系列是必填项。`
      - **终止**流程，不调用 API。
    - 若 `Chassis no` 为空：
      - 设置 `Error message area` = `底盘编号是必填项。`
      - **终止**流程，不调用 API。
    - 若 `Document type` 未选择：
      - 设置 `Error message area` = `文档类型是必填项。`
      - **终止**流程，不调用 API。
4.  **结果处理**：
    - 成功迁移至"Generate document"画面
    - 迁移失败，报error message

#### 点击 [Reset] 按钮

1.  **开始**：用户点击 [Reset] 按钮。
2.  **前置处理**：无。
3.  **动作**：- 清空 Chassis series、Chassis no 输入框。- 将 Document type 下拉列表重置为默认值（Please select）。- 清除 Error message area 内容。
4.  **结果处理**：画面回到初期化状态。

#### 点击 [Help] 按钮

1.  **开始**：用户点击 [Help] 按钮。
2.  **前置处理**：无。
3.  **动作**：
    - 跳转至 Help 画面。
4.  **结果处理**：
    - **成功**："查询成功"
    - **失败**："查询失败"

## 4. 接口定义 (API Specification)

### 4.1 UD03SelectHdocdocumentlistApi

- **功能**：获取可用的文档类型列表。
- **Method**: `POST`
- **Endpoint**: `/api/UD03/selectHdocdocumentlist`

#### Request

```json
无参数
```

#### Response Success (200)

```json
{
  "code": 200,
  "msg": "查询成功",
  "data": {
    "doctypeList": ["VIN Plate", "VP_XML2(With weights)"]
  }
}
```

#### Response Error (状态码)

```json
{
  "code": 500,
  "msg": "系统错误。请稍后再试。",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景                 | 处理方式           | Message 显示内容             |
| :----------------------- | :----------------- | :--------------------------- |
| **网络断开/超时**        | 捕获 Network Error | `网络错误。请检查您的连接。` |
| **服务器内部错误 (500)** | 捕获 Server Error  | `系统错误。请联系管理员。`   |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 chassisSeries, chassisNo, documentType, errorMessage, `isLoading`。
    - `Error message area` Label 默认隐藏（内容为空时不占位或高度为0）。
2.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 不在前端存储任何敏感信息。
3.  **UI 细节**：
    - [Submit] 按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
    - `Error message area` 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
    - 页面初始化时自动加载上次的搜索条件。
