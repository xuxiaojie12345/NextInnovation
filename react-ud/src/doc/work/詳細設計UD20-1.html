1. 背景 (Background)

本模块用于实现市场文档设置功能，用户可以通过检索功能跳转到Market Document Settings List画面，选择一条记录并返回。还可以清空输入的信息、返回上级画面，以及更新现有的市场文档信息。

  • 目标：提供市场文档的检索、更新和维护功能。
  • 面向用户：HDoc系统用户、需要管理市场文档配置的业务人员、系统管理员。
  • 用户体验：提供简洁直观的搜索界面，支持从前画面跳转到后画面并能携带查询条件，同时提供清空和返回功能，确保用户操作便捷。
  • 安全性：用户需要具备相应的文档管理权限才能进行更新操作。

3. 业务逻辑与校验规则 (Business Logic & Checks)

3.1 处理流程

3.1.1 初期表示流程

  1. 开始：画面加载，显示页面标题"HDoc - Market Document Settings"。
  2. 前置处理：判断初期化场合和后画面返回的场合：
    • 初期化场合：显示初始画面，所有输入字段为空。
    • 后画面（Market Document Settings List）返回的场合：需要判断是后画面的Select按钮按下返回还是Back按钮按下返回。
      • Select返回：接收后画面传回的数据（Document type、Bussines unit、User、Date），填充到对应输入框中。
      • Back返回：画面保持原有状态，不更新任何字段。
  3. API调用：无。
  4. 结果处理：渲染画面。

3.1.2 Search处理流程

  1. 开始：用户点击Search按钮。
  2. 前置处理：获取画面中的检索条件（Document type、User、Date），可以为空。
  3. 空值校验：无。
  4. API调用：无。
  5. 结果处理：携带检索条件参数跳转到Market Document Settings List画面。

3.1.3 Back处理流程

  1. 开始：用户点击Back按钮。
  2. 前置处理：无。
  3. 空值校验：无。
  4. API调用：无。
  5. 结果处理：返回前页面，不携带任何数据。

3.1.4 Clear处理流程

  1. 开始：用户点击Clear按钮。
  2. 前置处理：无。
  3. 空值校验：无。
  4. API调用：无。
  5. 结果处理：清空所有输入字段（Document type、Bussines unit、User、Date）。

3.1.5 Update Mode处理流程

  1. 开始：用户点击Update Mode按钮。
  2. 前置处理：获取输入的内容数据（Document type、User、Date）。
  3. 空值校验 (Frontend Check)：
    • 若Document type为空：
      • 设置错误消息 = Document type不能为空
      • 终止流程，不调用API。
    • 若Document type在表中不存在（API校验）：
      • 设置错误消息 = Document type does not exists. Please enter the correct content.
      • 终止流程。
  4. API调用 (Backend Check)：
    • 调用UD20MarketDocumentSettingsApi的UD20-1UpdateHdocDocumentList方法，传递参数doctype、user、date、market、setting，更新HDOC_DOCUMENT_LIST表数据。
  5. 结果处理：
    • 成功：显示成功提示更新成功。
    • 失败：显示错误消息更新失败。

3.2 校验详细规格表

No. 检查时机 检查对象 检查条件 错误消息 (Message Content) 动作
1 Update Mode按钮点击 Document type Document type未选择 Document type不能为空 显示错误消息，终止流程
2 Update Mode按钮点击 Document type Document type在表中不存在 Document type does not exists. Please enter the correct content. 显示错误消息，终止流程

4. 接口定义 (API Specification)

4.1 UD20MarketDocumentSettingsApi - UD20-1UpdateHdocDocumentList

功能：更新HDOC_DOCUMENT_LIST表中的市场文档信息

  • Method：POST
  • Endpoint：/api/ud20-1/updatehdocdocumentlist

Request

{
  "operation": "UPDATE_HDOC_DOCUMENT_LIST",
  "doctype": "string (文档类型，Update Mode时必须)",
  "user": "string (注册用户)",
  "date": "string (注册日期)",
  "market": "string (市场)",
  "setting": "string (设置)"
}

Response Success (200)

{
  "code": 200,
  "message": "更新成功"
}

Response Error (404)

{
  "code": 404,
  "message": "Document type does not exists. Please enter the correct content."
}

Response Error (500)

{
  "code": 500,
  "message": "更新失败"
}

6. 实现注意事项 (Implementation Notes)

  1. 画面状态判断：页面加载时需要区分初期化场合和从Market Document Settings List返回的场合。
  2. 后画面返回处理：
    • Select按钮返回：接收数据并填充到表单。
    • Back按钮返回：保持原有状态。
  3. Search跳转：携带检索条件（可为空）跳转到Market Document Settings List画面。
  4. Update Mode校验：Document type为必须输入项，且需要在表中存在。
  5. Bussines unit固定值：该字段固定显示为'BU'。
  6. Loading状态：Update Mode API调用期间建议显示加载提示，防止重复提交。
