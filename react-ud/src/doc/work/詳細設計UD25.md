## 1. 背景 (Background)

本模块用于展示当前登录用户的详细信息，从Saviynt系统获取用户数据并以只读形式呈现。

- **目标**：向所有已登录系统的用户提供用户信息查看功能。
- **安全性**：仅展示当前登录用户的信息，不涉及敏感数据修改，所有数据均为只读。
- **用户体验**：界面简洁清晰、信息一目了然、操作便捷。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在页面加载时或用户执行操作时执行。

### 3.1 处理流程

#### 3.1.1 页面初始化流程

1.  **开始**：页面加载触发。
2.  **前置处理**：

- 页面加载时自动调用AuthenticationApi获取当前登录用户信息。
- 将获取到的信息填充到对应字段。

3.  **结果处理**：

- **成功**：正常显示用户信息。
- **失败**：若Saviynt系统调用失败，对应字段显示为空。

#### 3.1.2 清空处理流程（Clear）

1.  **开始**：用户点击Clear按钮。
2.  **处理步骤**：

- 系统清空所有字段的显示内容。
- 不进行任何数据保存操作。

3.  **结果处理**：

- **成功**：所有字段清空，保持只读状态。

#### 3.1.3 返回处理流程（Back）

1.  **开始**：用户点击Back按钮。
2.  **处理步骤**：

- 系统执行页面跳转，返回到前一个画面。

3.  **结果处理**：

- **成功**：页面跳转到前一个画面。

## 4. 接口定义 (API Specification)

### 4.1 [AuthenticationApi]

- **功能**：验证用户凭证并返回认证结果。
- **Method**: `POST`
- **Endpoint**: `/api/auth/login` (示例路径)

#### Request Body

```json
{
  "userID": "string (Max 10, Alphanumeric)",
  "password": "string (Max 32, Alphanumeric + Symbols)"
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "token": "xxxx",
    "userId": 1,
    "username": "xxx",
    "responsible": "xxx",
    "userPosition": "xxx",
    "eMail": "xxx"
  }
}
```

#### Response Error (401 Unauthorized)

```json
{
  "code": 401,
  "data": null,
  "message": "Invalid credentials"
}

## 5. 异常处理 (Exception Handling)

| 异常场景                 | 处理方式     | Message 显示内容                     |
| :----------------------- | :----------- | :----------------------------------- |
| **Saviynt系统调用失败**  | 字段显示为空 | -                                    |
| **用户未登录或会话过期** | 显示错误提示 | `用户未登录或会话已过期，请重新登录` |
| **网络异常**             | 字段显示为空 | -                                    |
| **返回前一个画面失败**   | 显示通用错误 | `页面跳转失败，请刷新页面重试`       |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 userId, responsible, userPosition, email, errorMessage, `isLoading`。
    - 确保所有用户信息字段为只读状态。
2.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 需要用户登录认证后才能访问。
3.  **UI 细节**：
    - Clear 和 Back 按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
    - Message 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
```
