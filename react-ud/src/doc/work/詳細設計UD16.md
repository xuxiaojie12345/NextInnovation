## 1. 背景 (Background)

本模块用于管理ADCA（Advanced Data Change Authorization）变更信息的维护。用户可以添加、删除和检查AD Change记录，包括Serie-Chnr（系列编号）和Desc（描述信息）。该功能主要用于系统配置和数据变更管理，确保AD Change信息的准确性和完整性。

- **目标**：向具有系统配置权限的管理员、负责数据变更管理的业务人员及需要维护AD Change记录的授权用户提供AD Change记录管理功能。
- **安全性**：需要对HDOC_ADCA_CHANGE表进行CRUD操作；ADD操作前需检查是否存在未激活的记录；DELETE操作需谨慎处理，避免误删重要数据；CHECK操作用于验证记录状态。
- **用户体验**：界面简洁直观，提供清晰的输入框和操作按钮；支持快速添加、删除和检查操作；提供明确的错误提示和警告消息；所有操作均有即时反馈。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在页面加载时或用户执行操作时执行。

### 3.1 处理流程

#### 3.1.1 ADD操作流程

1.  **开始**：用户点击ADD按钮。
2.  **前置处理**：

- 获取Serie-Chnr和Desc字段的输入值。
- 去除首尾空格。

3.  **空值校验 (Frontend Check)**：

- 若Serie-Chnr为空或仅包含空格：
  - 设置Message = "Serie-Chnr不能为空"。
  - **终止**流程。

4.  **API 调用 (Backend Check)**：

- 调用[UD16ADChangeApi]
- 请求参数：
  ```json
  {
    "serieChnr": "JPCT-G28321",
    "desc": "这是AD Change的描述信息"
  }
  ```

5.  **结果处理**：

- **成功**：显示成功消息"AD Change记录添加成功"；清空输入框（可选）。
- **失败**：若记录已存在且未激活：显示警告"AFTER DEF CHANGE IS NOT ACTIVATED"；若其他错误：显示具体错误消息。

#### 3.1.2 DELETE操作流程

1.  **开始**：用户点击DELETE按钮。
2.  **前置处理**：

- 获取Serie-Chnr字段的输入值。
- 去除首尾空格。

3.  **空值校验 (Frontend Check)**：

- 若Serie-Chnr为空或仅包含空格：
  - 设置Message = "Serie-Chnr不能为空"。
  - **终止**流程。

4.  **确认对话框**：

- 弹出确认对话框："Do you really want to delete this AD Change record?"。
- 若用户点击"取消"：终止流程。
- 若用户点击"确定"：继续执行。

5.  **API 调用 (Backend Check)**：

- 调用[UD16ADChangeApi]
- 请求参数：
  ```json
  {
    "serieChnr": "JPCT-G28321"
  }
  ```

6.  **结果处理**：

- **成功**：显示成功消息"AD Change记录删除成功"；清空Serie-Chnr输入框。
- **失败**：若记录不存在：显示错误"记录不存在，无法删除"；若其他错误：显示具体错误消息。

#### 3.1.3 CHECK操作流程

1.  **开始**：用户点击CHECK按钮。
2.  **前置处理**：

- 获取Serie-Chnr字段的输入值。
- 去除首尾空格。

3.  **空值校验 (Frontend Check)**：

- 若Serie-Chnr为空或仅包含空格：
  - 设置Message = "Serie-Chnr不能为空"。
  - **终止**流程。

4.  **API 调用 (Backend Check)**：

- 调用[UD16ADChangeApi]
- 请求参数：
  ```json
  {
    "serieChnr": "JPCT-G28321"
  }
  ```

5.  **结果处理**：

- 记录存在且已激活：显示"记录存在且已激活"。
- 记录存在但未激活：显示警告"AFTER DEF CHANGE IS NOT ACTIVATED"。
- 记录不存在：显示"记录不存在"。

## 4. 接口定义 (API Specification)

### 4.1 UD16ADChangeApi

- **功能**：添加新的AD Change记录。
- **Method**: `POST`
- **Endpoint**: `/api/ud16/add`

#### Request Body

```json
{
  "serieChnr": "JPCT-G28321",
  "desc": "这是AD Change的描述信息"
}
```

##### 参数说明

| 参数名    | 类型   | 必填 | 说明                          |
| :-------- | :----- | :--- | :---------------------------- |
| serieChnr | String | Y    | AD Change系列编号，最大15字符 |
| desc      | String | Y    | 描述信息，最大4000字符        |

#### Response Success (200)

```json
{
  "code": 200,
  "msg": "添加AD Change成功",
  "data": {
    "serie": "xxx",
    "chnr": "xxx"
  }
}
```

#### Response Error (400/500)

```json
{
  "code": 400,
  "message": "Serie-Chnr已存在且未激活",
  "data": null
}
```

### 4.2 UD16ADChangeApi

- **功能**：删除指定的AD Change记录。
- **Method**: `DELETE`
- **Endpoint**: `/api/ud16/delete`

#### Request Body

```json
{
  "serieChnr": "JPCT-G28321"
}
```

##### 参数说明

| 参数名    | 类型   | 必填 | 说明                      |
| :-------- | :----- | :--- | :------------------------ |
| serieChnr | String | Y    | 要删除的AD Change系列编号 |

#### Response Success (200)

```json
{
  "code": 200,
  "msg": "删除AD Change成功",
  "data": {
    "serie": "xxx",
    "chnr": "xxx"
  }
}
```

#### Response Error (400/500)

```json
{
  "code": 400,
  "message": "记录不存在，无法删除",
  "data": null
}
```

### 4.3 UD16ADChangeApi

- **功能**：检查AD Change记录是否存在及其状态。
- **Method**: `GET`
- **Endpoint**: `/api/ud16/check`

#### Request Parameters

| 参数名    | 类型   | 必填 | 说明                      |
| :-------- | :----- | :--- | :------------------------ |
| serieChnr | String | Y    | 要检查的AD Change系列编号 |

#### Response Success

```json
{
  "code": 200,
  "msg": "检查AD Change成功",
  "data": {
    "serie": "xxx",
    "chnr": "xxx",
    "act": "xxx",
    "bu": "xxx",
    "reason": "xxx"
  }
}
```

#### Response Error - 不存在 (404)

```json
{
  "code": 404,
  "message": "记录不存在",
  "data": null
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景                               | 处理方式                             | Message 显示内容                    |
| :------------------------------------- | :----------------------------------- | :---------------------------------- |
| **Serie-Chnr为空（ADD/DELETE/CHECK）** | 前端校验拦截，不发起API请求          | `Serie-Chnr不能为空`                |
| **Serie-Chnr长度超过15字符（ADD）**    | 前端校验拦截，不发起API请求          | `Serie-Chnr长度不能超过15字符`      |
| **Desc长度超过4000字符（ADD）**        | 前端校验拦截，不发起API请求          | `Desc长度不能超过4000字符`          |
| **记录已存在且未激活（ADD）**          | API返回警告，前端显示警告消息        | `AFTER DEF CHANGE IS NOT ACTIVATED` |
| **记录不存在（DELETE）**               | API返回400错误，前端显示错误消息     | `记录不存在，无法删除`              |
| **记录不存在（CHECK）**                | API返回404错误，前端显示提示信息     | `记录不存在`                        |
| **记录存在但未激活（CHECK）**          | API返回警告，前端显示警告消息        | `AFTER DEF CHANGE IS NOT ACTIVATED` |
| **数据库连接异常**                     | API返回500错误，前端显示通用错误消息 | `系统错误，请稍后重试`              |
| **API超时**                            | 前端捕获超时异常，显示超时提示       | `请求超时，请检查网络连接后重试`    |
| **网络异常**                           | 前端捕获网络异常，显示网络错误提示   | `网络连接失败，请检查网络设置`      |
| **用户取消删除操作**                   | 前端拦截，不发起API请求              | 无（不显示任何消息）                |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 serieChnr, desc, errorMessage, successMessage, `isLoading`。
    - 确保输入框的值与状态同步。
2.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 需要用户登录认证后才能执行增删改操作。
3.  **UI 细节**：
    - 操作按钮（ADD、DELETE、CHECK）在 `isLoading` 期间应设为 `disabled`，防止重复提交。
    - Message 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
    - 成功消息使用绿色 (`#52c41a`) 显示。
    - DELETE 操作前需要弹出确认对话框。
