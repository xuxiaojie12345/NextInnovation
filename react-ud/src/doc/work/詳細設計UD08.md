## 1. 背景 (Background)

本模块用于管理车辆认证变量（Homologation Variables）的配置信息，支持对变量数据的查询、新增、修改和删除操作。

- **目标**：向系统管理员、配置工程师及合规审核人员提供车辆认证变量的管理功能。
- **安全性**：仅允许授权用户执行增删改操作，所有变更需记录操作人与时间。
- **用户体验**：保证输入字段清晰、操作按钮明确、错误提示及时。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在页面加载时或用户执行操作时执行。

### 3.1 处理流程

#### 3.1.1 画面初期表示流程

1.  **开始**：页面加载触发。
2.  **前置处理**：

- 初始化所有字段为空。
- 加载Product class下拉列表（PRODUCT_CLASS_MASTER）。
- 加载Market下拉列表（MARKET_MASTER）。

3.  **结果处理**：

- **成功**：所有文本框默认为空，按钮处于可用状态。
- **失败**：显示错误消息："系统内部错误，请联系管理员"。

#### 3.1.2 搜索处理流程

1.  **开始**：用户点击「Search」按钮。
2.  **前置处理**：用户在对应字段中输入或选择条件。
3.  **API 调用 (Backend Check)**：

- 调用 UD08HomologationVariablesApi 搜索接口。

4.  **结果处理**：

- **成功**：跳转至"Homologation Variables"搜索结果页面。
- **失败**：显示错误消息："系统内部错误，请联系管理员"。

#### 3.1.3 新增处理流程

1.  **开始**：用户点击「Add」按钮。
2.  **前置处理**：用户填写Product class、Number、Market等必填字段，填写Variable、Value、Variant string等其他字段。
3.  **空值校验 (Frontend Check)**：

- 若Product class、Number、Market任一为空：
  - 设置Message = "Product class、Number、Market为必填项"。
  - **终止**流程。

4.  **变量校验 (Frontend Check)**：

- 若Variable字段以TEMPLATE-开头：
  - 去除前缀后检查是否存在于HDOC_VARIABLES表中。
  - 若不存在：
    - 设置Message = "变体不存在，请输入正确内容"。
    - **终止**流程。

5.  **主键冲突校验 (Backend Check)**：

- 调用 UD08HomologationVariablesApi 检查Product class、Number、Market组合是否已存在。
- 若已存在：
  - 设置Message = "主键冲突，请输入正确内容"。
  - **终止**流程。

6.  **API 调用 (Backend Check)**：

- 调用 UD08HomologationVariablesApi 新增接口执行插入操作。

7.  **结果处理**：

- **成功**：显示提示："记录添加成功"。
- **失败**：显示对应错误消息。

#### 3.1.4 更新处理流程

1.  **开始**：用户点击「Update」按钮。
2.  **前置处理**：用户选择要修改的记录（可通过搜索获取），修改相关字段内容。
3.  **存在性校验 (Backend Check)**：

- 调用 UD08HomologationVariablesApi 检查Product class、Number、Market组合是否存在。
- 若不存在：
  - 设置Message = "数据不存在，请检查输入内容"。
  - **终止**流程。

4.  **变量校验 (Frontend Check)**：

- 若Variable字段以TEMPLATE-开头：
  - 去除前缀后检查是否存在于HDOC_VARIABLES表中。
  - 若不存在：
    - 设置Message = "变体不存在，请输入正确内容"。
    - **终止**流程。

5.  **主键冲突校验 (Backend Check)**：

- 检查是否与其他记录重复（主键冲突）。
- 若存在冲突：
  - 设置Message = "主键冲突，请输入正确内容"。
  - **终止**流程。

6.  **API 调用 (Backend Check)**：

- 调用 UD08HomologationVariablesApi 更新接口执行更新操作。

7.  **结果处理**：

- **成功**：显示提示："记录更新成功"。
- **失败**：显示对应错误消息。

#### 3.1.5 删除处理流程

1.  **开始**：用户点击「Delete」按钮。
2.  **前置处理**：用户选择要删除的记录。
3.  **存在性校验 (Backend Check)**：

- 调用 UD08HomologationVariablesApi 检查该记录是否存在。
- 若不存在：
  - 设置Message = "数据不存在，请检查输入内容"。
  - **终止**流程。

4.  **API 调用 (Backend Check)**：

- 调用 UD08HomologationVariablesApi 删除接口执行删除操作。

5.  **结果处理**：

- **成功**：显示提示："记录删除成功"。
- **失败**：显示错误消息："数据不存在，请检查输入内容"。

#### 3.1.6 清除处理流程

1.  **开始**：用户点击「Clear」按钮。
2.  **处理逻辑**：

- 所有输入框内容被清空。
- 下拉菜单恢复初始状态。

3.  **结果处理**：

- **成功**：所有字段清空，页面恢复初始状态。

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 productClass, number, market, variable, value, variantString1, variantString2, comments, addDate, deleteDate, createdUser, date, errorMessage, `isLoading`。
    - 所有字段均支持输入/输出操作。
2.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 需要用户登录认证后才能执行增删改操作。
    - 所有变更需记录操作人与时间。
3.  **UI 细节**：
    - 操作按钮（Search、Clear、Add、Update、Delete）在 `isLoading` 期间应设为 `disabled`，防止重复提交。
    - Message 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
    - Variable字段以'TEMPLATE-'开头时，自动去除前缀并验证剩余部分。
