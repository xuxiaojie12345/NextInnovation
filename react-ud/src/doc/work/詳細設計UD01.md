## 1. 背景 (Background)

本模块是系统的入口，负责验证用户身份。用户通过输入 UserID 和 Password，经由前端校验后调用后端 AuthenticationApi 进行认证。

- **目标**：确保只有授权用户能进入系统，并提供清晰的错误反馈。
- **安全性**：密码字段需掩码显示，所有敏感数据传输需加密。
- **用户体验**：采用 Label 形式在页面内显示错误信息，避免频繁弹窗打断操作流。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在用户点击[Login]按钮时同步或异步执行。

### 3.1 处理流程

1.  **开始**：点击Login按钮。
2.  **前置处理**：输入UserID和Password。
3.  **空值校验 (Frontend Check)**：
    - 若 `UserID` 是空白的场合：
      - 设置 `Message` = `用户名和密码是必填项。`
      - **终止**流程。
4.  **开始**：点击Login按钮。
5.  **前置处理**：输入UserID和Password。
6.  **空值校验 (Frontend Check)**：
    - 若 `Password` 是空白的场合：
      - 设置 `Message` = `用户名和密码是必填项。`
      - **终止**流程。
7.  **开始**：点击Login按钮。
8.  **前置处理**：输入UserID和Password。
9.  **空值校验 (Frontend Check)**：
    - 若输入的 `UserID` 或 `Password` 不正确的场合：
      - 设置 `Message` = `我们无法识别您输入的用户名或密码。请重试。`
      - **终止**流程。
10. **API 调用 (Backend Check)**：
    - 调用 [AuthenticationApi]
11. **结果处理**：
    - **成功**："登录成功"
    - **失败**："登录失败"

### 3.2 校验详细规格表

| No. |    检查对象    |           校验内容            |          错误消息 (Message Content)          | 错误等级 |
| :-: | :------------: | :---------------------------: | :------------------------------------------: | :------: |
|  1  |     UserID     | 用户ID为空，且点击Login按钮时 |           `用户名和密码是必填项。`           | Warning  |
|  2  |    Password    |  密码为空，且点击Login按钮时  |           `用户名和密码是必填项。`           | Warning  |
|  3  | 用户存在性检查 |     用户ID或密码不正确时      | `我们无法识别您输入的用户名或密码。请重试。` |  Error   |

## 4. 接口定义 (API Specification)

### 4.1 [AuthenticationApi]

- **功能**：验证用户凭证并返回认证结果。
- **Method**: `POST`
- **Endpoint**: `/api/auth/login` (示例路径)

#### Request Body

```json
{
  "userID": "string (Max 10, Alphanumeric)",
  "password": "string (Max 32, Alphanumeric + Symbols)"
}
```

#### Response Success (200 OK)

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "token": "xxxx",
    "userId": 1,
    "username": "xxx",
    "responsible": "xxx",
    "userPosition": "xxx",
    "eMail": "xxx"
  }
}
```

#### Response Error (401 Unauthorized)

```json
{
  "code": 401,
  "data": null,
  "message": "Invalid credentials"
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景                 | 处理方式           | Message 显示内容             |
| :----------------------- | :----------------- | :--------------------------- |
| **网络断开/超时**        | 捕获 Network Error | `网络错误。请检查您的连接。` |
| **服务器内部错误 (500)** | 捕获 Server Error  | `系统错误。请联系管理员。`   |
| **输入非法字符**         | 前端实时拦截       | 不允许输入非定义范围内的字符 |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 `userID`, `password`, [message], `isLoading`。
    - `Message` Label 默认隐藏（内容为空时不占位或高度为0）。
2.  **安全性**：
    - 严禁在前端日志中打印明文密码。
    - API 请求必须通过 HTTPS 发送。
3.  **UI 细节**：
    - [Login]按钮在 `isLoading` 期间应设为 `disabled`，防止重复提交。
    - `Message` 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
