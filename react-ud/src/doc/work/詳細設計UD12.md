## 1. 背景 (Background)

本模块用于管理HDoc模板文件的上传和删除操作，主要功能包括：支持选择并上传模板文件到指定市场文件夹、支持从指定市场文件夹删除模板文件、提供模板检查链接跳转到HDoc Template Check页面、市场下拉列表动态加载可用市场选项、模板下拉列表根据所选市场动态加载该市场下的模板文件。

- **目标**：向需要管理认证系统模板文件的授权用户提供模板文件管理功能。
- **安全性**：需要用户登录认证后才能访问；文件上传需要进行类型和大小验证；支持HTTPS安全传输协议。
- **用户体验**：清晰的文件上传界面；明确的操作反馈消息；删除操作前的确认提示；便捷的模板检查跳转功能。

## 3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在页面加载时或用户执行操作时执行。

### 3.1 处理流程

#### 3.1.1 页面初始化流程

1.  **开始**：页面加载。
2.  **处理步骤**：

- 调用 UD12UploadDeletetemplatApi（GET /api/ud12UploadDeletetemplat/getmarketlist）获取可用市场列表。
- 将市场列表填充到两个Market下拉列表中。
- Templates下拉列表初始化为空或禁用状态。
- 清空错误消息和成功消息区域。

3.  **结果处理**：

- **成功**：市场下拉列表填充完成，模板下拉列表为空。
- **失败**：显示错误消息："系统错误。请联系管理员。"。

#### 3.1.2 文件上传流程

1.  **开始**：用户点击Upload file按钮。
2.  **前置处理**：

- 校验是否选择了文件。
- 若未选择，显示错误消息"NO FILE UPLOADED"并终止流程。

3.  **处理步骤**：

- 获取选中的文件和市场代码。
- 构建FormData对象。
- 调用文件上传API。
- 等待API响应。

4.  **后端处理**：

- 验证文件类型和大小。
- 将文件保存到指定市场文件夹。
- 返回成功响应。

5.  **结果处理**：

- **成功**：显示成功消息"TEMPLATE XXX WAS SUCESSFULLY UPLOADED TO MARKET JPN"。
- **失败**：显示错误消息。

#### 3.1.3 模板删除流程

1.  **开始**：用户点击Delete按钮。
2.  **前置处理**：

- 校验是否选择了市场和模板。
- 若未选择，显示错误消息并终止流程。

3.  **处理步骤**：

- 显示确认对话框"Do you really want to delete template?"。
- 若用户取消，终止流程。
- 若用户确认，获取选中的市场代码和模板文件名。
- 构建请求参数。
- 调用文件删除API。
- 等待API响应。

4.  **后端处理**：

- 验证文件和路径存在性。
- 从指定市场文件夹删除文件。
- 返回成功响应。

5.  **结果处理**：

- **成功**：显示成功消息"TEMPLATE XXX WAS SUCESSFULLY DELETE FROM MARKET JPN"；刷新Templates下拉列表。
- **失败**：显示错误消息。

#### 3.1.4 市场选择联动流程

1.  **开始**：用户在Delete区域的Market下拉列表中选择市场。
2.  **处理步骤**：

- 获取选中的市场代码。
- 调用API获取该市场文件夹下的模板文件列表。
- 将文件列表填充到Templates下拉列表中。
- 若无文件，显示"No templates available"。

3.  **结果处理**：

- **成功**：Templates下拉列表更新为所选市场下的模板文件。
- **失败**：Templates下拉列表保持不变，显示错误消息。

#### 3.1.5 模板检查链接跳转流程

1.  **开始**：用户点击"Check Template (Only for rtf files)"链接。
2.  **处理步骤**：

- 使用React Router navigate函数跳转到/HDocTemplateCheck路由。

3.  **结果处理**：

- **成功**：跳转到HDoc Template Check页面。

## 4. 接口定义 (API Specification)

### 4.1 UD12UploadDeletetemplatApi

### 4.1.1 获取市场列表API

- **功能**：获取可用的市场列表。
- **Method**: `GET`
- **Endpoint**: `/api/ud12UploadDeletetemplat/getmarketlist`

#### Request

无请求参数

#### Response Success (200)

```json
{
  "code": 200,
  "msg": "获取市场列表成功",
  "data": [
    {
      "market": "xx"
    }
  ]
}
```

#### Response Error (500)

```json
{
  "message": "Internal server error"
}
```

### 4.2 获取模板文件列表API

- **功能**：根据市场代码获取该市场文件夹下的模板文件列表。
- **Method**: `GET`
- **Endpoint**: `/api/template/files/{marketCode}`（具体路径需根据实际API定义）

#### Request

```json
{
  "marketCode": "String (市场代码, Required)"
}
```

#### Response Success (200)

```json
[
  {
    "fileName": "template1.rtf",
    "filePath": "/templates/JPN/template1.rtf"
  },
  {
    "fileName": "template2.docx",
    "filePath": "/templates/JPN/template2.docx"
  }
]
```

##### 成功响应参数说明

- fileName：文件名，字符串类型
- filePath：文件路径，字符串类型

#### Response Error (500)

```json
{
  "message": "Internal server error"
}
```

### 4.3 文件上传API

- **功能**：上传模板文件到指定市场文件夹。
- **Method**: `POST`
- **Endpoint**: `/api/template/upload`（具体路径需根据实际API定义）

#### Request

```json
{
  "file": "File (模板文件对象, Required)",
  "market": "String (市场代码, Required)"
}
```

#### Response Success (200)

```json
{
  "success": true,
  "message": "TEMPLATE template1.rtf WAS SUCESSFULLY UPLOADED TO MARKET JPN",
  "fileName": "template1.rtf",
  "market": "JPN"
}
```

#### Response Error (400)

```json
{
  "success": false,
  "message": "Invalid file type or size"
}
```

#### Response Error (500)

```json
{
  "success": false,
  "message": "Internal server error"
}
```

### 4.4 文件删除API

- **功能**：从指定市场文件夹删除模板文件。
- **Method**: `POST`
- **Endpoint**: `/api/template/delete`（具体路径需根据实际API定义）

#### Request

```json
{
  "market": "JPN",
  "fileName": "template1.rtf"
}
```

##### 请求参数说明

- market：市场代码，字符串类型，必填
- fileName：文件名，字符串类型，必填

#### Response Success (200)

```json
{
  "success": true,
  "message": "TEMPLATE template1.rtf WAS SUCESSFULLY DELETE FROM MARKET JPN",
  "fileName": "template1.rtf",
  "market": "JPN"
}
```

#### Response Error (404)

```json
{
  "success": false,
  "message": "File not found"
}
```

#### Response Error (500)

```json
{
  "success": false,
  "message": "Internal server error"
}
```

## 5. 异常处理 (Exception Handling)

| 异常场景                       | 处理方式                                 | Message 显示内容                              |
| :----------------------------- | :--------------------------------------- | :-------------------------------------------- |
| **网络连接失败**               | 捕获网络异常，显示通用错误消息           | `System error. Please contact administrator.` |
| **API超时**                    | 设置超时时间（建议10秒），超时后显示错误 | `System error. Please contact administrator.` |
| **文件上传API返回400**         | 显示文件验证错误消息                     | `Invalid file type or size`                   |
| **文件上传API返回500**         | 显示系统错误消息                         | `System error. Please contact administrator.` |
| **文件删除API返回404**         | 显示文件不存在错误消息                   | `File not found`                              |
| **文件删除API返回500**         | 显示系统错误消息                         | `System error. Please contact administrator.` |
| **JSON解析失败**               | 捕获解析异常，显示系统错误               | `System error. Please contact administrator.` |
| **未预期的JavaScript错误**     | 使用try-catch包裹关键代码，记录错误日志  | `System error. Please contact administrator.` |
| **用户未登录**                 | 检查会话状态，跳转到登录页面             | `Please login first`                          |
| **未选择文件点击Upload**       | 显示文件选择提示消息                     | `NO FILE UPLOADED`                            |
| **未选择市场或模板点击Delete** | 显示选择提示消息                         | `Please select market and template.`          |
| **删除确认对话框用户点击取消** | 终止流程，不执行删除                     | -                                             |

## 6. 实现注意事项 (Implementation Notes)

1.  **状态管理**：
    - 使用 React State 管理 templateFile, market, templates, errorMessage, successMessage, `isLoading`。
    - 市场下拉列表初始化时从API获取可用市场列表。
    - 模板下拉列表根据所选市场动态更新。
2.  **安全性**：
    - API 请求必须通过 HTTPS 发送。
    - 需要用户登录认证后才能访问。
    - 文件上传需要进行类型和大小验证。
3.  **UI 细节**：
    - 操作按钮（Upload file、Delete）在 `isLoading` 期间应设为 `disabled`，防止重复提交。
    - Message 文字颜色建议使用红色 (`#ff4d4f`) 以起到警示作用。
    - 成功消息使用绿色 (`#52c41a`) 显示。
    - 删除操作前显示确认对话框。
