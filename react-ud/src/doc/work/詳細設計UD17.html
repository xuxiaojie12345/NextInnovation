1. 背景 (Background)

本模块用于管理HDoc系统的用户权限配置，支持查询用户信息、分配角色权限及Market访问权限。

  • 目标：向系统管理员、权限管理人员提供用户权限管理功能。
  • 安全性：仅允许授权管理员执行权限配置操作，所有变更需记录日志。
  • 用户体验：界面布局清晰、权限分类明确、操作反馈及时。

3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在页面加载时或用户执行操作时执行。

3.1 处理流程

3.1.1 页面初始化流程

  1. 开始：页面加载触发。
  2. 前置处理：
  • 初始化所有输入框和复选框为空/未勾选状态。
  • 加载MARKET_MASTER表数据到所有Market下拉列表。
  1. 结果处理：
  • 成功：UserID输入框为空，User标签为空，所有角色复选框未勾选，所有Market下拉列表默认显示'-EU'或为空，功能权限复选框未勾选，所有操作按钮处于可用状态。

3.1.2 用户信息查询处理流程（User Info）

  1. 开始：用户点击User Info按钮。
  2. 前置处理：
  • 校验UserID是否为空。
  • 若为空：设置Message = "请输入UserID"；终止流程。
  1. 处理步骤：
  • 调用API从Saviynt系统查询用户信息。
  • 若未找到用户：报错"We didn't recognize the userid you entered. Please try again."。
  • 若找到用户：在"User"标签中显示从Saviynt获取的用户名；同时从DOC_MARKET_AUTH和HDOC_FUNCTION_AUTH表加载该用户已有的权限配置；自动勾选已配置的角色复选框；自动填充已配置的Market下拉列表；自动勾选已配置的功能权限复选框。
  1. 结果处理：
  • 成功：显示查询到的用户名，加载并展示已有权限配置。
  • 失败：显示错误消息："We didn't recognize the userid you entered. Please try again."。

3.1.3 权限更新处理流程（Update Role）

  1. 开始：用户点击Update Role按钮。
  2. 前置处理：
  • 检查是否已查询到用户。
  • 若未先执行查询：设置Message = "请先查询用户信息"；终止流程。
  1. 处理步骤：
  • 系统校验UserID是否存在。
  • 若不存在：设置Message = "We didn't recognize the userid you entered. Please try again."。
  • 若存在：调用API保存权限配置到DOC_MARKET_AUTH和HDOC_FUNCTION_AUTH表；根据角色自动应用对应的画面功能权限（参考权限矩阵表）。
  1. 结果处理：
  • 成功：显示提示："权限更新成功"。
  • 失败：显示错误消息："更新失败，请联系管理员"。

3.1.4 权限删除处理流程（Delete Role）

  1. 开始：用户点击Delete Role按钮。
  2. 前置处理：
  • 检查是否已查询到用户。
  • 若未先执行查询：设置Message = "请先查询用户信息"；终止流程。
  1. 处理步骤：
  • 系统弹出确认对话框："确定要删除该用户的所有权限吗？"。
  • 用户确认后，系统校验UserID是否存在。
  • 若不存在：设置Message = "We didn't recognize the userid you entered. Please try again."。
  • 若存在：调用API从DOC_MARKET_AUTH和HDOC_FUNCTION_AUTH表删除该用户的所有权限记录。
  1. 结果处理：
  • 成功：显示提示："权限删除成功"；清空所有角色复选框；清空所有Market下拉列表；清空所有功能权限复选框。
  • 失败：显示错误消息："删除失败，请联系管理员"。

6. 实现注意事项 (Implementation Notes)

  1. 状态管理：
    • 使用 React State 管理 userId, userName, roles, functions, marketSuperUser, errorMessage, successMessage, isLoading。
    • 所有角色权限、功能权限和市场权限的状态都需要正确绑定到相应的UI组件。
  2. 安全性：
    • API 请求必须通过 HTTPS 发送。
    • 需要用户登录认证后才能执行权限配置操作。
    • 所有变更需记录日志。
  3. UI 细节：
    • 操作按钮（User Info、Update Role、Delete Role）在 isLoading 期间应设为 disabled，防止重复提交。
    • Message 文字颜色建议使用红色 (#ff4d4f) 以起到警示作用。
    • 成功消息使用绿色 (#52c41a) 显示。
    • Delete Role 操作前需要弹出确认对话框。
