1. 背景 (Background)

本模块用于展示和修改VIN Plate模板中的变量值，支持用户查看当前值并输入修改后的值。

  • 目标：使系统管理员、生产准备人员及质量审核人员能够便捷地修改VIN Plate模板中的变量值。
  • 安全性：仅允许授权用户执行修改操作，所有变更需记录日志；必须至少有一个Modified value字段有值才能保存。
  • 用户体验：界面清晰易读、变量列表完整、修改操作便捷、错误提示明确。

3. 业务逻辑与校验规则 (Business Logic & Checks)

所有校验逻辑均在页面加载时或用户点击Save按钮时执行。

3.1 处理流程

3.1.1 页面初始化流程

  1. 开始：页面加载。
  2. 前置处理：获取前画面传递的Chassis no和Market参数。
  3. API 调用 (Backend Check)：
    • 调用 UD05ModifyDocumentApi。
  4. 结果处理：
    • 成功：
      • 展示从前画面传递的Chassis no和Market信息。
      • 展示Template文件链接（如aus/UD_TEST.odt）。
      • 从Template文件解析所有变量列表。
      • 对每个变量：
        • 从HDOC_VARIABLES表获取Description。
        • 检查HDOC_ADCA_MODIFICATION表中是否存在该变量的修改记录。
        • 若存在：Current value显示NEWVAL。
        • 若不存在：显示为空白。
      • 以表格形式展示所有变量及其信息。
    • 失败：
      • 显示错误消息："系统错误。请联系管理员。"。

3.1.2 保存处理流程

  1. 开始：用户点击Save按钮。
  2. 前置处理：检查Modified value字段是否有输入值。
  3. 空值校验 (Frontend Check)：
    • 若所有Modified value字段均为空：
      • 设置Message = "NO UNRELEASED VERSION EXISTS!"。
      • 终止流程。
  4. API 调用 (Backend Check)：
    • 调用 UD05ModifyDocumentApi 执行保存操作。
  5. 结果处理：
    • 成功："修改保存成功"。
    • 失败："保存失败，请联系管理员"。

3.1.3 查看底盘详细信息

  1. 开始：用户点击chassis no链接。
  2. 前置处理：跳转到Vehicle Specification页面（UD07），携带参数chassisNo（SERIE + CHNO拼接）。
  3. 结果处理：Vehicle Specification页面加载并显示底盘详细信息。

4. 接口定义 (API Specification)

4.1 UD05ModifyDocumentApi

4.1.1 查询接口

  • 功能：提供Modify Document页面的数据查询和保存接口。
  • Method: POST
  • Endpoint: /api/UD05/modifydocumentunit
Request 
{
  "chassisNo": "JPCT 028321",
  "market": "AUS"
}
Response Success (200) 
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "DESCRIPTION": "xxx",
    "NEWVAL": "xxx"
  }
}

4.1.2 保存接口

  • 功能：提供Modify Document页面的数据查询和保存接口。
  • Method: POST
  • Endpoint: /api/UD05/modifydocumentsave
Request 
{
  "action": "save",
  "chassisNo": "JPCT 028321",
  "market": "AUS",
  "modifications": [
    {
      "variable": "VIN_TEXT3",
      "newValue": "MODIFIED_VALUE_1"
    },
    {
      "variable": "UD_GCM",
      "newValue": "35000"
    }
  ]
}
Response Success (200) 
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "DESCRIPTION": "xxx",
    "NEWVAL": "xxx"
  }
}
Response Error (400) 
{
  "error": "Validation failed",
  "message": "NO UNRELEASED VERSION EXISTS!"
}
Response Error (500) 
{
  "error": "Internal Server Error",
  "message": "Failed to save modifications"
}

5. 异常处理 (Exception Handling)

异常场景 处理方式 Message 显示内容
所有Modified value为空 显示错误消息 NO UNRELEASED VERSION EXISTS!
Modified value长度超过500 截断或提示错误 输入值长度不能超过500字符
Template文件不存在 显示通用错误 模板文件不存在，请联系管理员
API调用失败 显示通用错误 保存失败，请联系管理员
数据库操作异常 显示通用错误 系统内部错误，请联系管理员

6. 实现注意事项 (Implementation Notes)

  1. 状态管理：
    • 使用 React State 管理 chassisNo, market, templateFile, variables, modifications, errorMessage, isLoading。
    • Message Label 默认隐藏（内容为空时不占位或高度为0）。
  2. 安全性：
    • API 请求必须通过 HTTPS 发送。
    • 需要用户登录认证后才能访问。
    • 敏感数据需要进行权限控制。
  3. UI 细节：
    • Save 按钮在 isLoading 期间应设为 disabled，防止重复提交。
    • Modified value 输入框应限制最大长度为500字符。
    • Message 文字颜色建议使用红色 (#ff4d4f) 以起到警示作用。
